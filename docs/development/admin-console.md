# 管理后台控制台（2026-11-02）

`/admin` 由原来的单页页签改为带侧边栏的控制台。原有的用户、举报、商品管理表格、私密证据读取和人工处理原样保留，只是分别移到了 `/admin/users`、`/admin/reports`、`/admin/products`。详情面板应用户要求从右侧抽屉改成了居中对话框，焦点循环、Esc 关闭和关闭后焦点回到原按钮这些行为都保留。

## 路由

| 路由 | 内容 |
|---|---|
| `/admin` | 仪表盘：顶部是商品增长、待处理事项、今日订单、平台用户；「数据洞察」区有在售分类（颜色与图标和前台一致）、订单状态、举报原因、发布时段热力图；「待办与处理」区有待办任务、平台健康度、最新订单、被举报较多的用户、最近处理记录 |
| `/admin/reports` | 原举报处理面板 |
| `/admin/products` | 原商品治理面板 |
| `/admin/orders` | 订单管理（新）：按订单号或商品标题搜索、状态筛选、详情抽屉、导出 CSV |
| `/admin/users` | 原用户管理面板 |
| `/admin/profile` | 个人中心（新）：账号资料、累计与近 7 天处理数、处理类型、我的处理记录；资料和头像在前台 `/profile` 编辑 |
| `/admin/audit` | 操作日志（新）：只看处理决定，或者连同查看记录一起显示 |

所有页面都要管理员权限：游客会跳到登录页，普通账号会看到 403。按 Ctrl+K 可以打开搜索面板，用来跳转页面或搜索订单。

## 新接口

- `GET /admin/dashboard?days=7|30`（`adminGetDashboard`）
- `GET /admin/orders`（`adminListOrders`）
- `GET /admin/audit-logs?scope=decisions|all&mine=true|false`（`adminListAuditLogs`，`mine=true` 只返回当前管理员自己的记录）

每次读取都会经 `read_audit` 记录一条管理员访问审计。

## 数字与前台保持一致

- 「在售」和各分类的数量，与前台市场使用同一个筛选条件：`deleted_at IS NULL`、`status = ON_SALE`，并且卖家账号为 `ACTIVE`。`tests/test_admin_console.py` 会断言它们分别等于 `GET /products` 和 `GET /products?category=X` 返回的 `total`。
- 「今日」「近 N 天」按校园时间（Asia/Shanghai）的自然日计算，前端显示时也固定使用这个时区。
- 增长率与上一个等长区间比较。上一个区间为 0 时不算百分比，直接显示增加了多少（如 `+3`）。
- 订单状态的文案与交易页面一致。

## 如实呈现、没有编造的部分

- 商品没有「待审核」状态。待处理事项只统计未处理的举报和争议中的订单。
- 目前没有任何接口会把订单置为 `DISPUTED`，所以争议数据如实显示为 0；订单详情里也注明了暂时没有仲裁接口。
- 某项健康度的分母为 0 时显示「暂无数据」，不显示 0% 或 100%。

## 本次没有做（后端尚无对应能力）

分类管理、公告、敏感词、争议仲裁。等后端有了接口再接入，不在前端放假入口。
