# T2 三项复测问题修复（2026-11-15）

本记录是维护者修复与验证说明，不替代 T2 的独立复测、原始失败记录或签收。

## 修复范围

| 问题 | 原因 | 修改后的行为 |
| --- | --- | --- |
| 驳回后不能再次举报 | 接口查询和数据库唯一约束都永久去重 | 仅 PENDING/PROCESSING 阻止同一人对同一目标、同一原因重复举报；RESOLVED/REJECTED 后可新建举报，旧记录和处理说明保留 |
| 评价提交后无法查看 | 只有写入接口和提交页面 | 完成订单新增“查看评价”，双方可查看评分、文字和时间；评价页面提交成功后展示双方评价，刷新仍可见，不能重复评价 |
| 后台订单搜索不支持组合关键词 | 将整个输入当作一段连续文字 | 空格分词，各词都必须命中，允许跨商品名称、订单号、买卖双方昵称或邮箱匹配；不区分英文字母大小写；`#订单号`仍为精确查询 |

评价读取接口 `GET /orders/{orderId}/reviews` 仅允许该订单的买卖双方访问，游客和陌生用户不能读取。历史缺失的分项显示“未评分”，文字评价保留原文、换行与长文本换行。中文和英文界面文案同步补齐；不改动用户昵称、邮箱和评价原文。

后台列表和导出使用相同搜索条件；修改关键词或状态回到第一页，过滤在服务器分页之前完成。`%`、`_` 按普通字符处理，搜索最长 200 字符。

## 数据迁移和环境更新

新增迁移 `0013` 将举报永久唯一约束改为仅针对未处理状态的唯一索引。验证过空库升级/回滚/重升、带旧举报升级、保留处理说明、已处理后重提和数据库直接拒绝两条未处理举报。

旧版本无法容纳多条同键举报历史：如果已有此类历史，降级会明确失败并保留数据与迁移版本，不删除记录来强行降级；无此类历史时可正常降级。

日常、T1、T2 共用本次代码，但数据相互独立。升级时保留原数据库、媒体卷和账号凭据：

```powershell
powershell -File scripts/start-local.ps1 -Rebuild -NoBrowser
python scripts/audit_env.py upgrade --namespace permission --run-id run2
python scripts/audit_env.py upgrade --namespace business --run-id run2
```

审计环境升级脚本会先备份数据库与旧映射。升级后应检查 API/worker 源码一致、迁移为 `0013`、三个网页连接各自 API，并比较升级前后的核心表计数及内容摘要。日常只做只读/拒绝访问检查，写入验收继续使用独立审计库。

## T2 独立复测建议

1. 新建举报，处理中再次提交应提示重复；后台驳回后，用新提交再次举报应成功；“我的举报”和后台同时保留两次记录。已处理完成后也做一次相同检查。
2. 用买卖双方各完成一次评价，在订单“查看评价”回看内容；刷新、切换中英文和手机宽度检查显示；陌生账号不能访问该订单评价。
3. 后台搜索例如 `电脑 16GB`、`电脑 买家昵称`，应同时满足输入的关键词；切换订单状态、翻页、清空关键词与导出应保持同一过滤口径。

复测请记录实际提交 SHA、网页/API 地址和结果；保留原失败记录，追加本次复测结果。
