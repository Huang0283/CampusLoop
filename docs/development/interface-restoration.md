# 原版界面恢复与复盘

## 原因与责任

2026-10-09 的 `74d8c0c`（第三阶段真实接口集成）把正式路由从原来的 `src/pages` 切换到新写的 `src/live` 页面。集成时重新写了通用列表和表单，没有保留已有的页面布局，造成商品详情、聊天及其他界面的视觉退步。这是集成过程中未经用户要求的设计变更，不是后续组员提交造成的，也不是接真实接口必须付出的代价。

2026-10-23 按用户要求恢复。原版页面作为布局依据，正式页面继续使用 `src/sdk`、真实会话和后端业务状态；不把路由切回 Mock 原型。

## 本次恢复范围

- 全站：原有蓝白配色、CampusLoop 标识、固定顶栏搜索、统一侧栏、通知和用户菜单。搜索接入真实市场查询；保留游客与账号权限。
- 市场 `/market`、我的发布 `/my-products`、收藏 `/favorites`：分类/筛选区域、商品图片卡片、价格/成色/状态、卖家头像；发布管理和取消收藏仍调用后端。
- 商品 `/product/:id`：左右分栏、单张大图、上一张/下一张、可点击缩略图和计数、描述、参数、卖家/操作卡片及交易地点。成色与分类显示中文；没有学校照片或型号参数时不编造。
- 发布 `/publish`、编辑 `/product/:id/edit`：居中的分段表单、图片上传、价格/成色/地点和描述；保留上传状态及原价校验。
- 求购 `/wanted`：双列需求卡片、预算/最低成色、发布者/地点/发布时间。
- 求购详情 `/wanted/:id`：需求说明/条件与右侧发布者卡片；联系、本人编辑/关闭和本人匹配入口接真实 API。
- 求购发布/编辑 `/wanted/publish`、`/wanted/:id/edit`：分段表单与预算区间布局，保留真实提交。
- 匹配 `/wanted/:wantedId/matches`：带图片的横向结果卡片、相关度、原因、约束、有效期和版本；保留降级/过期/无权限说明。
- 价格建议 `/publish/price-advice`：商品信息与建议区间分栏；影响因素、样本量及规则/模型标识来自实际响应，不恢复原型的固定区间和假因素评分。
- 聊天 `/chat`、`/chat/:id`：按用户提供的原图调整约三成宽的会话栏、头像/未读数、关联商品、左右消息气泡和紧凑报价卡片；底部恢复附件/表情图标和发送按钮，另保留真实报价入口。报价按时间进入消息区域；保留发送失败重试、WebSocket 与 HTTP 补拉、历史消息、报价接受/拒绝/还价/撤回和订单跳转。正常连接改为标题栏状态，断线仍明确提示。搜索范围为会话联系人、商品/求购标题与最后消息，不假称可以搜索全部历史。没有头像时显示昵称首字，消息与商品来自实际会话，不能为复刻截图写死人物或聊天内容。
- 交易 `/transactions`：购买/出售页签、带商品图的订单卡片、状态和金额。
- 订单 `/transactions/:id`：进度、商品、买卖双方、订单信息、见面操作和时间线。保留约定版本、双方确认、取消、争议和评价的业务限制。
- 见面 `/transactions/:id/meetup`：当前约定、新约定表单与商品侧栏，保留未来时间校验。
- 评价 `/transactions/:id/review`：商品摘要、分项星级及内容表单，仍只允许已完成交易评价。
- 通知 `/notifications`：分类页签、通知类型图标、未读底色/标记和已读操作；举报历史入口保留。
- 举报记录 `/report`：真实个人举报列表与处理状态，提交仍通过原来的真实举报弹窗。
- 个人中心 `/profile`：左侧头像/资料/真实交易次数与评分，右侧编辑资料表单。不恢复原型写死的认证标识、交易次数和评分。
- 登录 `/login`、注册 `/register`：独立居中品牌卡片与输入图标；继续验证真实密码，不恢复演示身份选择器。
- 管理 `/admin`：用户/举报/商品页签与管理表格，保留详情抽屉、私密证据、人工处理与访问审计。

## 验证边界

`frontend/tests/live/interface-restoration.spec.ts` 用明确的网络夹具验证正式路由及真实 React 组件：23 个学生/认证页面各检查桌面 1440px 和手机 390px，并额外检查管理页、图库切换、消息发送、游客操作保护和错误响应不回退假商品。夹具截图只用于布局验收，不作为真实后端成功的证据。

真实业务另用现有 `journey.spec.ts`、`m2-phase4.spec.ts` 和 `product-governance.spec.ts`，连接独立 audit API、专用数据库与 Redis DB15。覆盖注册、真实图片上传、两个账号聊天、断网补拉/失败重试、报价生成订单、见面版本和时间校验、双方完成、评价、角色不同的举报、刷新持久化、退出登录、跨页签账号隔离，以及管理员禁用/恢复和商品人工下架/恢复。不会清空或回滚日常账号库。

这次还修正了退出登录的跳转竞争：先同步离开受保护页面，再清除身份，防止权限守卫覆盖“返回市场”的目标。

代码复核追加修正：刷新会话列表保留当前聊天组件和未发送草稿（仅同一资源/账号，切换账号仍清除）；商品收藏按钮先查询当前账号真实收藏列表，并检查后续分页，收藏/取消后刷新仍保持后端状态；390×667 与 390×568 的手机视口下，聊天内容内部滚动，发送按钮不被底部导航遮挡。每一项均先复现失败，再加入修复后回归。

2026-10-23 最终回归：前端 lint、TypeScript/Vite build 通过；SDK 一致性检查通过；Playwright 完整 31 项通过（包含网络夹具布局检查与独立 audit 后端真实业务测试，两者不混用作证据）。新增聊天专项检查使用 1720×960 视口，验证会话栏比例、报价卡片高度、接受/拒绝报价可见、表情实际进入草稿以及报价输入开合，并人工查看对照截图；其测试内容只存在测试夹具中，不写入日常数据库。管理员处理按钮增加明确的可访问名称，避免加载图标混入操作名称。构建仍有现存的大包体积提示，不影响运行。

日常启动也通过 `scripts/start-local.ps1 -NoBrowser` 复核：网站 `http://127.0.0.1:5174`，API `http://127.0.0.1:8001`，固定数据库卷 `campusloop-local-db`，数据库 `campusloop`。无网络拦截的浏览器检查确认真实商品列表返回 200、商品详情显示恢复后的图库与卖家区域、游客进入聊天会转到登录，页面没有运行异常。本次没有改密码、重建账号库或删除旧商品；先前已存在的测试商品图片仍按实际存储显示。

## 以后必须遵守

1. 接口集成只替换数据来源和业务调用；布局、信息层级、组件和交互已有依据时直接保留。
2. “流程跑通”和“界面保持原样”分开验收。必须查看实际页面和截图，不能只凭构建通过就宣布完成。
3. 路由整体替换影响全站，必须逐页列出受影响入口并做回归；不能只检查首页或当前截图。
4. 界面恢复与业务回退分开处理。真实权限、会话、幂等、持久化和错误状态不得被旧 Mock 覆盖；没有真实数据时展示缺省状态。
5. 同时核对目录、分支、API 地址和数据库卷；向用户明确展示的版本，避免“代码更新、实际运行旧服务”。
6. 不在浏览器验收进行时重新生成 SDK 或更改应用模块，避免开发服务器热更新干扰真实登录与跳转测试。
7. 任何主动简化或重新设计界面的建议，先给用户看具体差异并获得明确要求，再实施。
