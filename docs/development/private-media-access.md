# 私有媒体访问与 T1 复测

对应 Issue #149、#145。修复分支为 `fix/private-media-access`，目标为 `main`；本地验证网址 `http://127.0.0.1:5196`，API 为 `http://127.0.0.1:18036`。该预览使用独立审计数据库、Redis DB14 和独立媒体桶，不代表日常 5174 网站已更新。

## 当前访问规则

| 图片 | 存储与读取 | 游客 |
| --- | --- | --- |
| 商品图片 | 公开桶，沿用原展示方式 | 可见 |
| 用户及管理员头像 | 私有桶，`GET /avatars/image?reference=...` 携带登录凭证 | 拒绝；页面显示昵称首字 |
| 聊天图片 | 私有桶，按消息接口检查会话双方及上传归属 | 拒绝，无关登录账号也拒绝 |
| 举报证据 | 私有桶，沿用管理员鉴权与审计读取 | 拒绝 |

头像上传后本人可预览；其他登录用户只能读取当前已保存的头像。更换或清空后，其他用户不能继续读取旧头像；普通账号不能读取被禁用用户的头像，管理员仍可审核其当前头像。系统不抓取任意外站头像地址，无法识别的历史外站引用显示首字，需重新上传。

前台与后台头像共用 `UserAvatar`，通过现有 SDK 带凭证读取 Blob。头像、聊天及举报/申诉证据在图片解码显示后立即撤销临时 `blob:` 地址；复制地址到同一浏览器新标签页或独立无痕窗口都无法再次读取。放大预览由 `PrivateMediaImage` 复用现有 AntD 界面，每次打开单独生成临时地址并在显示后撤销，支持重复打开、缩放与关闭；卸载时也释放剩余资源。媒体接口返回图片字节及 `Cache-Control: no-store`，不向浏览器签发可转发的存储下载地址。头像大小、上传校验与现有排版保持不变。

## 旧公开副本迁移

标准入口 `backend/scripts/serve.py` 在提供 API 前调用 `scripts/privatize_media.py`。只扫描本系统 `UploadedObject` 登记的非商品对象：先复制到私有桶，核对 ETag 与长度后才删除公共桶副本；目标内容冲突或存储异常时停止启动并保留原图，排查后重试。相同内容可重复执行，不改数据库内头像、聊天或证据引用，不删除商品图片。

自定义部署若绕过 `serve.py` 直接启动 ASGI，须在开始提供服务前，在同一后端环境执行 `python scripts/privatize_media.py`。这不是数据库结构迁移，无需新增 Alembic 版本。公共和私有桶必须分开；私有桶及反向代理不可配置匿名读取，部署方需确认这一存储前提。

程序只能撤销受本系统控制的已登记对象原始链接。外站副本、此前已下载的文件或代理/CDN 已留存的缓存需要分别处理；有权限的查看者仍可主动保存或截图，不能承诺阻止所有转发。

## T1 怎么复测

保留 #149 原来的失败证据，在 PR 对应修复提交上另记复测结果，无需重建整套数据。

1. 登录普通账号，上传并保存头像，刷新确认个人中心和顶部都正常；管理员个人中心也检查上传、保存和刷新。
2. 将页面中头像、聊天缩略图和放大预览图的图片地址复制到同一浏览器新标签页及独立无痕窗口，都应无法打开。反复关闭和重新放大，图片仍正常。直接请求头像 API 且不带凭证应为 401；已保存头像可被合法登录者读取。
3. 两个普通账号发送聊天图片，双方可看并在刷新后保留；游客请求为 401，无关第三个账号为 404。
4. 保留升级前的本系统头像/聊天原始公开链接，迁移后匿名访问应为 403 或 404；原资料和聊天仍能显示。不要只检查新上传图片。
5. 更换或清空头像后，其他账号不可再读取旧头像。退出登录后旧令牌不可继续读取。
6. 确认商品公开图片、桌面与手机卡片正常，上传失败可重试，资料草稿不丢失。

自动化入口：`backend/tests/test_avatar_upload.py`、`backend/tests/test_realtime_media.py`、`backend/tests/test_demo_dataset.py`；前端 `profile-avatar.spec.ts`、`admin-profile.spec.ts`、`media-privacy.spec.ts`。真实浏览器用例只在指定审计环境执行，设置 `CAMPUSLOOP_UI_URL` 与 `CAMPUSLOOP_TEST_API_CONTAINER`；不要指向日常账号库。管理员合成夹具另校验审计数据库与 Redis DB14/15。
