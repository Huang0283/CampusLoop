## 启动与登录

先安装 Docker Desktop、Python、Node，启动 Docker Desktop。在仓库根目录执行：

```powershell
git fetch origin
git switch fix/price-advice-guidance
cd frontend
npm ci
cd ..
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1
```

如果本地已有同名分支，再执行 `git pull --ff-only`。有未提交修改时先保留自己的工作，不要强制切换或覆盖。首次运行需要下载依赖和构建镜像。

“历史禁用后恢复”用于展示申诉撤销结果，两个普通账号当前都是正常状态。所有交易、标价、违规与证据都明确用于合成演示，不代表真人行为。通知初始为未读；打开聊天、处理申诉或新增评价后，数量和状态会正常变化。

## 建议按这个顺序体验

1. 买家登录，打开个人资料和交易页：确认成交次数 15，查看同一件商品的订单、校内见面信息与评价。第 15 笔完成订单可实际填写评价。
2. 买家打开聊天：与同一卖家的不同商品会话由现有界面集中展示，每件商品保留自己的报价和订单关系。
3. 买家打开通知、本人举报和账号处理记录：查看举报结果、警告原因、证据和申诉结果。
4. 卖家登录，查看“我的发布”和交易页：核对相同订单；查看待复核的警告申诉与已经撤销的历史禁用。
5. 管理员登录后台：依次查看用户管理、商品治理、订单、举报、申诉、通知和审计。可以处理待办记录；操作后切回对应用户，刷新查看通知与状态。
6. 需要实际测试封禁时，使用管理员处理演示普通账号，核对禁用提示与申诉入口，完成后恢复账号。管理员不作为普通交易身份。

初始化记录用于快速到达业务场景，不能替代 T2 对新增下单、双方确认、举报提交、权限拒绝及失败重试等操作的手动验收。

## 价格建议怎么试

使用**买家账号**，进入发布商品的价格建议页，分类选“运动户外”、成色选“八成新”，关键词输入“羽毛球拍”。初始可匹配 6 件在售商品，展示标价区间和参考商品链接。卖家查询会排除自己的商品，不能用卖家账号复现这 6 件样本。

预置的 15 笔订单是合成交易，**不会自动写入成交价格模型的训练集**，所以成交样本显示 0 与个人成交次数 15 可以同时成立。在售标价参考独立计算，不冒充真实成交。真实外部行情采价、同款型号识别及成交模型训练不包含在这套数据里；规则详见[商品标价参考](listing-price-reference.md)。

## 素材处理与隔离方式

- 素材来自用户提供的 `桌面/新建文件夹`。按外观与多角度关系整理成 25 件独立商品，重新导出 81 张 JPEG，约 1.85 MB；不依赖原目录继续存在。
- 28 张商品说明截图不作为商品图；另有 31 张重复、额外人物、带店铺水印或促销内容等照片未采用。完整选择清单和图片校验值见 `backend/demo_assets/catalog.json`。
- 标题和简介重新写，去除“小学生”“儿童”等字眼，不添加未经核对的型号配置，地点统一为校内。这 25 件固定演示商品提供对应的英文标题和简介，品牌保留。演示标价是功能测试用价格，不是对原商品的真实性或行情鉴定。
- 举报和申诉证据为专门生成、明确标有 `SYNTHETIC DEMO EVIDENCE` 的说明图；放在演示私有桶，由现有权限接口读取。
- Compose 项目为 `campusloop-demo`，独立数据库 `campusloop_demo`、Redis DB15 与独立媒体卷。初始化同时检查显式演示开关、数据库名和 Redis 分区，拒绝写入日常库或生产环境。
- 初始化采用事务与锁，非空库不重复灌入，不强制恢复密码或覆盖手工修改。页面角标随中英文偏好切换，提醒当前处于演示环境。
