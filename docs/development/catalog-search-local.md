## 搜索为什么一直提示不可用

旧公共接口把 semantic/hybrid 都交给冻结的 M7 基线；基线对语义请求明确返回 `MODEL_DISABLED`，公开结果模式也一直写成 keyword。这不是用户输入错误，也不是前端隐藏提示就能恢复。

本轮增加独立的实时目录检索集成，复用项目已经下载并有来源哈希的 `BAAI/bge-small-zh-v1.5` 中文编码器。原阶段评测、冻结数据与正式门禁记录不修改，本地接通不代表那些历史正式验收已经通过。

- 关键词模式继续按当前商品名称、简介和既有别名规则检索。
- 语义模式使用真实模型相似度；混合模式融合关键词和模型的排名。公开接口返回实际执行模式。
- 分类、精确成色、价格、商品状态、账号状态、可见性先约束候选，输出前再核对商品最新版本。
- 每次从当前数据库生成快照，把最新名称和简介送入检索。内容变化自动重新编码，不需要针对每件新商品维护静态名单。
- 模型在本机独立进程运行，CPU 推理；缓存最多5000条文本向量，不存账号、密码或私聊。公开商品名称和简介供模型使用。
- 短商品名检索使用已有明确匹配的分类约束扩展范围，低相似度不强行补结果。当前相似度阈值属于本地启发式，不能解释成准确率或成交概率。
- 模型服务失败时明确回退关键词；不会把回退结果标成模型成功。空结果可清除分类、成色筛选。

截图里“电脑 + 数码电子 + 七成新”确实没有符合条件的在售电脑；清除成色筛选可看到电脑，不能偷偷忽略用户选择的筛选。

## 启动与依赖

继续使用 `scripts/start-local.ps1`，保留既有数据库、Redis与媒体卷。它现在也调用 `scripts/start-catalog-search.ps1` 启动模型；Stop 同步停止本脚本拥有的模型进程。

模型文件位于 `%USERPROFILE%/.cache/campusloop/bge-small-zh-v1.5-7999e1d`。该目录已有约96MB权重，服务只离线加载并校验来源哈希，不在启动时下载。

当前机器使用 Python 3.14 和已有的 PyTorch CPU 运行时；语义库独立安装在 `%USERPROFILE%/.cache/campusloop/catalog-runtime` 虚拟环境，继承本机已安装的CPU版PyTorch。本机已验证的依赖记录见该虚拟环境中的 `environment.json`，不把它当作其他机器的通用完整环境锁。

新机器应先按照 `services/m7_semantic/README.md` 准备相应平台验证过的Python/PyTorch与模型；当前本地启动器默认使用上述独立目录。准备好PyTorch后，可执行：

```powershell
python -m venv --system-site-packages "$env:USERPROFILE/.cache/campusloop/catalog-runtime"
& "$env:USERPROFILE/.cache/campusloop/catalog-runtime/Scripts/python.exe" -m pip install transformers==4.57.6 huggingface-hub==0.36.2 tokenizers==0.22.2 safetensors==0.8.0
.\scripts\start-local.ps1
```

模型服务宿主端口18789，Compose API通过 `host.docker.internal` 访问；评分请求必须通过已有RPC令牌鉴权。令牌从本机 `.env` 读取，不出现在命令参数、日志或交付文档中。API只发送公开商品字段。
