# 商品语言往返与默认排序修复（2026-11-24）

## 原因与改动

- 原商品数据没有损坏。中文模式把含 Cosplay 的中文标题整体送入英译中模型，已有中文被重译，出现“剧本”等错误。现在英译中只处理英文片段，已有中文和中文标点始终保留；Cosplay / PVC 作为商品术语保留。品牌、型号、审计前缀及真实英文说明仍使用既有保护和翻译机制。
- 新增公开商品列表 `sort=recommended`：在数据库分页之前，将 `other` 分类排在常见分类之后，同组按发布时间、ID 倒序。商城无关键词浏览默认选择“推荐”。保留原“最新发布”、价格排序及搜索相关性语义，不删除、不隐藏任何商品，不按商品 ID 特判。
- 同步 OpenAPI、SDK 类型及 T1 响应契约源文件哈希；响应结构没有变化。

## 验证

- 翻译/缓存单测 8 项通过，含四个真实 Cosplay 标题双向校对、现有中文和品牌重叠保护、新英文说明不会把中文送进模型。
- 实际本机翻译模型：日常商城四个 Cosplay 商品的标题与简介共 8 段，通过中文 → 英文 → 中文原文显示检查；没有改数据库内容。
- 独立审计数据库、Redis DB14：商品排序、关键词搜索及校园目录集成回归 45 项通过，含跨页无遗漏、`other`/`OTHER` 后排、明确排序与分类筛选不受影响。没有向日常账号库创建测试商品。
- Playwright 双语及商品展示 15 项通过，涵盖桌面/移动端、语言持久化、旧请求竞态、权限、失败恢复、完整图片显示。前端构建、相关 ESLint 与后端 Ruff 检查通过。
- 复核上轮 CI 失败：后台移动端夹具遗漏公开翻译端点，已补精确模拟；真实交易重连后的去重断言误数了联系人摘要，改为仅统计 `.chat-message-stream`，未改消息业务逻辑。后台移动端专项通过；真实交易/求购估价/访客与登录恢复等 6 条旅程在独立审计库通过。临时容器的 Cookie 名称与规则估价开关曾不符合 CI 前提，已对齐后完整重跑；未因此修改业务行为或降低断言。

原始运行材料保存在项目 `.codex-tmp/catalog-roundtrip-20261124/`，不改写旧测试组验收证据；本轮只证明以上受影响范围，不代表所有测试组交付已完成。部署后的三环境只读核查记录另见最终环境交接文档。

## 当日后续：新上架商品的语义翻译

用户追问新商品时，额外检查发现旧翻译器将一句话拆成很多词翻译，导致阅读支架变成 kickstand、耳机收纳盒变成“案件”，甚至把“不含充电器”里的“含充电器”单独翻译。仅保护中文原名不能解决这些语义问题。

这轮改为固定提交版本的本机 HY-MT1.5-1.8B 完整语句翻译，少量商品术语作为上下文提示，不再替换句中的词条片段。品牌、型号、数量、重量和原语言段落使用占位符保护，检查缺失、重复和新增后再恢复。完整原文校订仍精确匹配，新增/编辑的内容走真实模型。前端按每段独立请求，原界面与权限保持不变。

验证范围：

- 18 条不加载权重的规则/缓存单测通过，已接 CI；模型替换未要求 CI 下载约 4.1 GB 权重。
- 16 条未收录于完整标题词典的实际模型语义用例通过，含首轮 12 类与追加的办公椅、平板裂纹、教材缺页、台灯开关/灯泡 4 类。以含义、否定、配件、数量和原文恢复验收，不要求译文逐字等同某个模板。每次运行使用未变更的源文本，缓存不写回账号库。
- 独立审计库、Redis DB14 通过真实注册/图片上传/发布流程创建中文阅读支架、英文耳机两件商品。两件各中英切换两轮，再刷新，原始名称/简介完全未被覆盖；1440px/390px 布局无横向溢出。没有将蓝色测试图片商品写入日常商城、T1 或 T2 数据库。
- 双语/商品展示 Playwright 16 条回归，前端构建、相关 ESLint 和 Python Ruff 检查通过。原实际服务检查脚本继续覆盖品牌/型号/金额/成色正反含义及现有商品。

机器准备、模型版本、内存与首载限制见 [本地翻译说明](frontend-bilingual-20261103.md)。本机使用 FP32；曾试验的通用 INT8 量化产生错误输出，未进入交付实现。新句子检查代表上述样例的实际结果，不能宣称任意输入都百分之百准确。语义结果与真实上架记录见 [本轮证据](../evidence/phase-5/management-quality/catalog-i18n-20261124/README.md)。
