# 缺陷等级与任务状态说明

> 文档编号：QUALITY-WORKFLOW-001
> 负责人：M10
> 版本：0.1 候选版
> 最后更新：2026-09-19

## 1. 缺陷等级

| 等级 | 判定标准 | 示例 | 处理要求 |
|---|---|---|---|
| P0 阻断 | 数据泄露/破坏、核心流程完全不可用、无法启动或无可行降级 | 越权读取私聊；重复订单破坏交易事实；仓库密钥泄露 | 立即停止相关合并和发布，M1/M10/模块负责人当天介入；关闭前不得发布 |
| P1 严重 | MVP 主路径失败、权限或状态规则错误、结果不可恢复，但有临时绕行 | 单方确认即可完成；第二买方也能接受；非参与者可评价 | 下一工作日完成归属和修复计划；里程碑前必须关闭 |
| P2 一般 | 次要功能错误、异常提示缺失、兼容或性能问题，不破坏核心事实 | 筛选条件丢失；重连提示不清；管理列表分页错误 | 纳入当前或下一迭代，记录影响与目标周次 |
| P3 轻微 | 文案、样式、低频易用性或非阻断文档问题 | 术语不统一；对齐问题；辅助说明缺失 | 排期修复，可在已知问题中带入候选版本 |

等级按影响而非修复工作量判断。任何安全、隐私或交易事实问题至少按 P1 分诊；实际可利用或造成泄露时升为 P0。

## 2. 缺陷必填字段

`标题、发现版本、环境、关联需求/场景、严重度、复现步骤、实际结果、预期结果、证据、负责人、目标日期、修复提交、复测结果、关闭人`。

无法复现时不得直接关闭，应记录已尝试的环境、数据和次数，并转为 `blocked` 或“需更多信息”。

## 3. 任务状态

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| `todo` | 目标、负责人、优先级和验收条件已明确，尚未开始 | 作者开始处理并记录分支/PR |
| `in-progress` | 已有负责人和工作分支，正在实现或编写 | 提交自测证据后进入 `review`；受阻进入 `blocked` |
| `blocked` | 外部依赖、决策、环境或权限使工作无法继续 | 写明阻塞项、影响、需要谁处理和下一检查时间；解除后回原状态 |
| `review` | 交付物、验收入口和自测证据齐全 | 通过后进入 `done`；有问题回 `in-progress` |
| `done` | 代码/文档已合并，验收条件满足，证据可复核，无未说明 P0/P1 | 后续回归失败时重新打开 |

## 4. 完成定义

任务进入 `done` 前必须同时满足：

- 交付物位于约定路径且已合并，不只存在于个人电脑或截图。
- 需求、实现、测试和证据能通过编号或链接追踪。
- 作者自测、同组评审和受影响小组评审已记录。
- 新增或修改的接口、状态、权限、数据和配置已有说明。
- 没有真实密钥、敏感数据、未说明的 P0/P1 或伪造指标。
- 候选功能没有被描述为已经正式交付。

## 5. 工作流

```mermaid
stateDiagram-v2
    [*] --> todo
    todo --> in-progress
    in-progress --> blocked
    blocked --> in-progress
    in-progress --> review
    review --> in-progress: 需修改
    review --> done: 验收通过
    done --> in-progress: 回归失败/重新打开
```
