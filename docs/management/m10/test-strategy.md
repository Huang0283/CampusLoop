# CampusLoop AI 测试策略候选版

> 文档编号：QUALITY-TEST-001  
> 负责人：M10  
> 版本：0.1 候选版  
> 最后更新：2026-09-19  
> 说明：本文件定义未来测试入口和证据要求，不代表测试已经执行。

## 1. 质量目标

1. 证明 MVP 能在统一环境完成发布、搜索、聊天、议价、订单、见面约定、双方完成确认和评价的闭环。
2. 证明权限、状态机、事务、幂等和隐私边界在异常路径下仍然成立。
3. 证明 AI、Redis、对象存储或 WebSocket 降级时，基础交易不会被错误阻断。
4. 让所有测试结果可复现、可定位到需求和版本，不用截图替代运行证据。

## 2. 测试层级与主责

| 层级 | 重点 | 主责 | M10 复核 |
|---|---|---|---|
| 单元测试 | 状态转换、权限判断、时间区间、匹配与价格规则、异常分支 | 模块作者 | 抽查关键边界与失败分支 |
| 接口测试 | 输入校验、认证、资源所有权、错误码、幂等、分页 | M5/M6/M7/M8 | 独立执行核心接口集合 |
| 集成测试 | PostgreSQL 事务与锁、Redis、MinIO、Worker、通知、重连 | M6/M9 及相关作者 | 核对依赖故障与回滚证据 |
| 端到端测试 | 两个学生账号和一个管理员账号的浏览器主流程 | M2-M6 | 维护核心旅程并复测 |
| 权限与安全测试 | 越权、敏感字段、上传、限流、审计 | M5/M6/M9 | 验证高风险用例 |
| 并发测试 | 报价接受、商品占用、重复完成、重复通知 | M6/M9 | 复核数据库事实与失败结果 |
| 性能测试 | API、搜索、WebSocket、任务队列和数据库查询 | M9 与模块作者 | 统一环境、负载和统计口径 |
| 恢复测试 | 服务重启、断线补拉、迁移回滚、备份恢复、智能降级 | M9 与模块作者 | 从干净环境独立演练 |
| AI 评估 | 关键词/规则基线、语义检索、匹配、价格区间 | M7/M8 | 检查数据泄漏、指标与证据 |

## 3. 测试优先级

- **P0 旅程**：登录、商品发布、关键词搜索、聊天、报价接受、订单、见面约定、双方完成确认、评价。
- **P0 约束**：不能购买自己的商品；第二买方并发接受失败；单方确认不能完成；非参与者不能评价；无权用户不能读取私密内容。
- **P1 能力**：收藏、举报、通知、管理审核、断线补拉和重复请求。
- **P2 能力**：求购、语义搜索、供需匹配、价格建议和规则化信誉。
- **P3 能力**：风险智能、高级推荐、高级分析及其他 Stretch 项。

## 4. 环境与测试数据

| 项目 | 候选要求 |
|---|---|
| 本地开发 | 模块作者快速运行单元和接口测试，不作为最终验收环境 |
| 统一集成环境 | 固定代码提交、依赖版本、迁移版本和环境配置模板 |
| 干净验收环境 | 非作者按文档全新安装，用于第 9-10 周部署与恢复验证 |
| 学生账号 A | 卖家场景，使用虚构资料 |
| 学生账号 B | 买家场景，使用虚构资料 |
| 学生账号 C | 并发买家和越权场景，使用虚构资料 |
| 管理员账号 | 举报与审计场景，仅使用测试权限 |
| 商品与求购数据 | 覆盖正常、边界、过期、已售、下架和无匹配情况 |

测试账号、密码和令牌不得写入仓库；只提交生成脚本、字段说明或 `.env.example` 占位项。

## 6. 性能与 AI 指标规则

- PDF 中的“100 个模拟并发用户”是未来测试负载候选，不是已达到的容量结论。
- 第 4 周前由 M9、后端负责人和 M10 固定硬件、数据量、预热、并发模型、重复次数和统计分位数。
- 语义搜索候选指标为 Precision@K、Recall@K、MRR；匹配候选指标为 Precision@5 和后续真实反馈指标。
- 价格候选指标为 MAE、有效价格样本上的 MAPE 和预测区间覆盖率。
- 没有数据许可、版本化评估集、规则基线和复核记录时，不发布任何效果数字。

## 7. 缺陷与回归

- 缺陷等级和状态遵循 [缺陷等级与任务状态](./defect-and-workflow.md)。
- 修复必须附失败用例、修复提交、复测结果和影响范围。
- 状态机、权限、迁移、公共类型和接口契约变更必须触发相关回归集合。
- 自动化未覆盖的关键场景必须保留可重复的人工步骤和证据位置。

## 8. 测试证据最小集合

每次里程碑至少保存：代码提交哈希、环境与依赖版本、数据准备方式、执行命令、开始和结束时间、通过/失败/跳过数量、失败详情、缺陷链接和复测结论。
