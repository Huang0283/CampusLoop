## P0 双账号主流程

**前置条件**：学生 A、学生 B 可登录；无真实个人信息；数据库处于已知版本。

1. A 发布一件在售商品。
2. B 通过关键词和筛选找到商品并查看详情。
3. B 发起聊天并提交结构化报价。
4. A 接受报价，系统创建唯一订单并占用商品。
5. A、B 在私聊后记录见面时间和地点，并分别确认同一版本。
6. 线下步骤由测试模拟，A、B 分别确认完成。
7. 订单进入已完成，商品进入已售。
8. A、B 各提交一次评价；再次评价被拒绝。

**必须保存的证据**：代码提交、环境版本、测试数据脚本、浏览器或接口执行记录、订单事件、数据库约束结果、失败步骤和关联缺陷。

## 异常与安全补充

- 无令牌、过期令牌、禁用账号和普通用户访问管理员接口。
- 跨用户编辑商品、读取私聊、读取见面约定或读取举报证据。
- 重复提交报价、重复接受、重复完成和重复评价。
- WebSocket 消息乱序、断线、重连、重复投递和鉴权失败。
- 图片伪装扩展名、超限文件、不可解码内容和元数据处理。
- 智能任务超时、索引未就绪、结果版本过期和重复通知。

## Given/When/Then 执行格式

| 场景 | Given（前置条件） | When（动作） | Then（预期结果） |
|---|---|---|---|
| AC-01 | 学生账号未登录，邮箱未注册 | 提交合法注册，再使用错误密码和正确密码登录、退出 | 合法注册建立会话；错误密码返回明确失败；正确登录成功；退出后令牌失效 |
| AC-02 | 学生已登录，资料含私有字段 | 查看公开主页并编辑允许字段 | 公开响应不含邮箱/令牌/私聊/举报证据；本人允许字段可更新 |
| AC-03 | 卖家已登录，商品字段合法 | 发布商品，买家按关键词和筛选查询并打开详情 | 商品进入在售列表；买家能找到并查看允许公开的详情 |
| AC-04 | 商品属于卖家，买家为另一账号 | 买家尝试编辑，卖家尝试购买自己的商品 | 两次操作均被拒绝，商品数据和状态不变化 |
| AC-05 | 买家已登录，商品在售 | 收藏、取消收藏，再查看收藏列表 | 收藏状态幂等切换；已售/下架商品按规则展示 |
| AC-06 | 两个账号属于同一会话，消息服务可用后断开 | 发送消息，断线，重复发送同一客户端消息，再补拉历史 | 消息先持久化；断线后补齐；重复 clientMsgId 不产生重复消息 |
| AC-07 | 报价处于 PENDING 且参与者身份合法 | 买卖双方执行接受、拒绝、还价、撤回和过期操作 | 仅允许的状态转换成功；越权、过期和重复操作返回确定错误 |
| AC-08 | 同一商品存在两个有效买方报价 | 两个买方并发请求接受报价 | 只有一个订单成功占用商品；另一个请求失败且不生成重复订单 |
| AC-09 | 订单可约定，当前见面约定为版本 N | 一方修改时间/地点，双方分别确认版本 N 与 N+1 | 修改生成 N+1 并使旧确认失效；只有双方确认同一有效版本才生效 |
| AC-10 | 订单已安排见面，双方均未完成确认 | 仅一方确认，再由双方分别确认完成 | 单方确认不完成；双方确认后订单完成、商品已售 |
| AC-11 | 订单已完成，参与者尚未评价 | 参与者评价，第三方或同一方再次评价 | 每个参与者最多一条评价；取消、争议和非参与者被拒绝 |
| AC-12 | 学生提交带证据举报，管理员登录 | 学生查看他人证据，管理员处理举报并填写决定 | 非授权用户不可见证据；管理员决定带原因并留下审计记录 |
| AC-13 | AI、Redis 或 WebSocket 依赖不可用 | 用户发布、浏览、关键词搜索并执行可替代交易动作 | 基础流程继续；页面显示明确降级；不把降级结果标为智能成功 |
