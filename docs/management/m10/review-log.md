当前材料已经给出项目定位、团队分工和三层范围。根 README 与 PDF 1.2 的范围及状态差异已在 M1 文档批次修复，M1/M10 的第一阶段管理交付物也已形成候选版。跨组确认和全员范围评审尚未完成，因此仍不应声明需求已经冻结。

## 2. README 与 PDF 1.2 对照

| 对照项 | PDF 1.2 | 更新后 README | 结论 |
|---|---|---|---|
| 项目定位 | 校园场景 + AI 智能匹配 + 可信交易 | 相同，并强调课程项目和协作记录边界 | 一致 |
| 当前状态 | 2026-09-15 时“尚未进入开发阶段” | 区分历史说明、当前 Mock 前端原型和未落地服务 | 已消除时间状态冲突 |
| MVP 闭环 | 账号、商品、搜索、聊天、议价、订单、约定、双方确认、评价、举报/通知和后台 | 按同一闭环列为 MVP | 一致 |
| 见面功能 | 只记录双方协商结果，不开发智能推荐 | 明确不做智能时间/地点推荐 | 已修复原 README 冲突 |
| 智能范围 | 语义搜索、求购匹配、价格为核心；风险智能等为扩展 | Core/Stretch 分列并说明基线、评估和降级 | 一致 |
| 技术栈 | React/FastAPI/PostgreSQL/Redis/MinIO/Worker 等候选 | 同时标明“已有前端”与“其余未落地” | 语义更准确 |

结论：更新后的 README 与 PDF 1.2 的产品范围和业务边界匹配；README 额外承担“当前仓库状态”入口，因此以实际代码和 2026-09-19 验证结果修正了 PDF 的历史阶段描述。
