# CampusLoop 八人自选分组与个人交付任务书

版本：1.0；日期：2026-10-09；配套文件：`closeout-task-packages.md`。

## 一、八人怎么选组

八位成员自行组成四组，每组两人，各占一个岗位。岗位编号是新的材料分工编号，不替代原 M1–M10 身份。报名时填写真实姓名、原成员编号、学号、组别、岗位、个人分支和组内复核人；由技术负责人确认没有重复岗位或遗漏成员。

本文件先列岗位，不预先给八个人指定组别。候选成员名单由团队确认；M1=黄麒玮，M10=陈梓弘，其余姓名/成员编号按原项目记录核对。每人独立完成一份任务清单和自己的产物，不能以“一起做了”代替个人交付。

报名格式：姓名：____；学号：____；原成员编号：____；选择组别/岗位：____；个人分支：____；组内复核人：____。登记位置：`docs/collaboration/registration.md`。

四组岗位为 A1/A2 文档报告、B1/B2 测试验收、C1/C2 手册与页面证据、D1/D2 汇报演示。技术负责人统一实现功能、维护源码/契约/迁移、修复缺陷和组织阶段合并；八人承担本文的材料、独立执行和复核。

## 二、所有岗位共同提交要求

每份产物注明任务 ID、作者、阶段、适用 SHA、输入文件、内容、检查结果和接收人。测试类还记录实际执行人、日期、环境、命令/步骤、结果和原始证据。每个阶段按 D1–D7 周计划交付，截止登记为实际日期时间。

每人维护 `docs/collaboration/phase-<n>/<岗位>/task-log.md`，列出本周任务、文件链接、PR、接收结果与阻塞。未完成项写具体缺少什么、依赖谁、影响、下一动作和日期。

文件命名使用小写 ASCII 与连字符；DOCX/PDF/PPTX 统一使用 `CampusLoop_<主题>.<扩展名>`。Markdown 作为可审查源稿，最终办公文件导出后检查目录、页码、字体、图片、链接和文件可打开性。

涉及未合入的功能时只交准备稿，待技术负责人提供版本后实际执行。Phase 2 的 Mock、Phase 3 的真实实现、Phase 4 的高级模型/规则和 Phase 5 的最终材料分别标识。

## 三、A1：需求、项目介绍与技术报告统稿

### 个人任务

- A1-01：整理项目问题、目标用户、解决思路、目标与项目边界；写英文 Introduction 与 Conclusions 源稿。每个结论对应目标和实际完成状态。
- A1-02：写 Requirements，逐项列需求 ID、角色、场景、正常/失败结果、阶段和验收链接；重点区分游客浏览、学生买卖身份、管理员、受保护动作与私密数据。
- A1-03：维护需求到实现/测试/章节的追踪清单。将未完成和实验功能写清原因、影响与后续计划。
- A1-04：合并 A2 章节、B 组测试总结和 C 组截图，统一英文术语、编号、引用与交叉链接；整理真实成员贡献。
- A1-05：导出总报告 DOCX/PDF，核对两种文件内容、页码、图注和目录一致。团队建议篇幅 40–60 页，教师要求优先。

### 个人交付物

- `docs/submission/technical-report/introduction.md`、`requirements.md`、`conclusions.md`。
- `report-evidence-index.md`、`references.md`、`member-contributions.md`、`technical-report.md`。
- `CampusLoop_Technical_Report.docx` 和 PDF；每周个人任务日志。

### 验收和交接

每项需求能跳转到对应代码/契约、测试或明确的限制；报告没有仓库角色、真实支付或未实现能力的完成声明。A2 复核章节事实，B1/B2 复核测试结论。向 D1 交报告摘要、可引用数字和图表来源；向技术负责人交总稿与待确认事实清单。

## 四、A2：系统设计、实现说明与智能方法

### 个人任务

- A2-01：根据实际源码写 Design：前后端结构、数据库、缓存、对象存储、任务/实时通信及模块职责；给出可编辑架构和 ER/状态图源文件。
- A2-02：说明注册/登录/会话、资源归属、游客访问、隐私白名单、报价接受、唯一订单、约定版本、双方确认及完成后评价的实现流程。
- A2-03：说明接口与生成 SDK、迁移/种子/CI、消息去重与重连等实际实现；未实现项标为设计输入或待实现。
- A2-04：说明关键词/规则基线、搜索/匹配/价格、结果解释、版本与降级。引用智能资产和评估原始结果；没有真实成交标签时不能写价格模型预测达标。
- A2-05：写技术选择、替代方案和限制；核查组件/数据/算法来源与许可，向 A1 提供引用。

### 个人交付物

- `docs/submission/technical-report/design.md`、`implementation.md`、`ai-methods-and-limitations.md`、`architecture-decisions.md`。
- `diagrams/` 中可编辑图源与导出图，`design-source-index.md` 中各图与代码/契约对应位置。
- 个人任务日志、图文检查记录。

### 验收和交接

系统图的每个模块均有源码/配置依据，状态和字段与当前 OpenAPI/模型一致；不把 source 文件整段复制进报告。A1 复核术语和需求映射，技术负责人核对实现事实。向 A1 交独立章节、图源和引用；向 C2 交部署结构与必要配置解释。

## 五、B1：核心功能、双账号交易与功能复测

### 个人任务

- B1-01：编写游客浏览、注册登录、商品/求购、收藏、聊天、议价、订单、约定、完成、评价、通知的功能用例。每条预期来自对应阶段 Issue 或冻结契约。
- B1-02：使用两套隔离会话分别作为买方和卖方执行主路径；记录商品/会话/报价/订单/约定 ID，核对另一账号可见结果和数据刷新。
- B1-03：Phase 2 记录 Mock 可点击状态；Phase 3 起核对真实请求、刷新持久化、双方状态和评价结果；阶段用例分开编号。
- B1-04：登记功能缺陷，给清楚的最短复现、预期/实际、SHA、角色、严重度与证据；按修复提交逐条复测并保留失败历史。
- B1-05：核对 D2 的演示操作脚本，确保演示数据 ID、步骤、预期和实际版本一致。

### 个人交付物

- `docs/collaboration/phase-<n>/testing/functional-test-cases.md`、`functional-execution-log.md`、`functional-defects.md`、`functional-retest-log.md`。
- `functional-evidence-index.md`、`functional-test-summary.md` 与必要截图/请求证据。
- 个人任务日志；Phase 5 提交最终功能回归结论供总报告引用。

### 验收和交接

每条用例均有可重复步骤、具体预期和实际结果；真实双账号闭环需要双方操作和持久化证据。B2 复查代表性成功/失败用例。向技术负责人交缺陷，向 A1/A2 交实际测试结论，向 D2 交已验证主路径。

## 六、B2：权限、异常、智能降级与环境验收

### 个人任务

- B2-01：编写游客/学生/管理员、买方/卖方/非参与方、账号禁用/过期的权限与隐私用例；检查私密消息、举报证据和内部风险结果。
- B2-02：执行空/超长/非法字段、无效 ID、非法图片、重复请求、并发接受报价、旧约定版本、未完成/取消评价、断线重试、重复消息与通知去重。
- B2-03：按智能运行手册复现数据/契约检查与已交付指标，记录版本和原始输出；验证服务不可用/超时/样本不足的降级。NO_GO 的能力按限制记录。
- B2-04：按 C2 部署手册在隔离的新目录/机器启动，记录依赖版本、配置、迁移、种子、服务健康和常见失败；数据库回滚/恢复仅用专用测试库。
- B2-05：在 Phase 5 按冻结阈值执行性能、并发、安全和备份恢复，记录命令、数据量、硬件、原始结果及限制；阈值不能测试后临时降低。
- B2-06：复测边界缺陷，并与 B1 汇总测试报告；记录通过、失败、阻塞、不适用，分别计算。

### 个人交付物

- `docs/collaboration/phase-<n>/testing/boundary-test-cases.md`、`boundary-execution-log.md`、`boundary-defects.md`、`boundary-retest-log.md`。
- `environment-verification.md`、`ai-reproduction.md`、`non-functional-results.md`、`test-summary.md` 和原始日志/证据索引。
- 个人任务日志；B2 维护组测试总结，B1 仅交功能摘要，避免两人编辑同一份总结。

### 验收和交接

权限测试检查服务端响应及数据可见性，不能只看按钮隐藏。环境实机运行成功才记通过；高级模型条件不齐保持 NO_GO；数字可由原始结果重算。B1 复核代表性边界用例，技术负责人确认缺陷影响，A1/A2 接收实际结论，C2 接收部署问题。

## 七、C1：用户手册、页面截图与体验问题

### 个人任务

- C1-01：按实际页面编写游客浏览与学生用户操作手册，覆盖主要流程、角色变化、失败反馈、登录来源恢复和智能免责声明。
- C1-02：每个步骤写前置、页面/入口、填写内容、按钮、预期结果和遇错处理；交易流程写明双方分别做什么。
- C1-03：采集游客、学生和管理员页面截图，整理桌面/手机及加载、空、成功、失败、无权限证据；不适用状态写理由。
- C1-04：检查 1440×900、390×844 的页面布局、右上角账号/通知、侧栏、滚动、弹窗与表单反馈，登记页面问题给技术负责人。
- C1-05：用新版本复查手册/截图，每张图标明阶段、SHA、路由、角色、状态、数据 ID 和用途；最终导出用户手册 DOCX/PDF。

### 个人交付物

- `docs/submission/manuals/user-manual.md`、`CampusLoop_User_Manual.docx` 和 PDF。
- `docs/collaboration/phase-<n>/experience/screenshot-index.md`、`page-issues.md`、`screenshots/` 中必要图像。

### 验收和交接

B1 照手册完成主路径并记缺失步骤；截图没有个人隐私、密码或令牌，图中页面与文字步骤一致。向 A1/D1 交按用途筛选的图片与图注，向 D2 交最终用户操作步骤，向技术负责人交页面缺陷及复测结果。

## 八、C2：管理员/部署手册、演示数据与故障指南

### 个人任务

- C2-01：编写管理员手册，覆盖当前版本已支持的登录、列表筛选、举报审核、用户/商品操作、原因和审计；明确权限和限制。
- C2-02：编写部署手册，逐步给依赖、clone/检出 SHA、环境示例、迁移、种子、前后端启动、地址、健康检查、停止与升级。
- C2-03：编写常见问题：端口占用、依赖未启动、对象存储不可用、接口地址错误、账号/令牌失效、服务降级；引用实际日志和处理步骤。
- C2-04：规划虚构演示账号与商品/求购/订单数据，记录 ID、数量、所需状态、生成方式与每轮复位办法；由技术负责人维护种子脚本。
- C2-05：编写独立测试环境的备份恢复步骤并交 B2 执行；最终更新所有手册及数据版本，导出 DOCX/PDF。

### 个人交付物

- `docs/submission/manuals/admin-manual.md`、`deployment-manual.md`、`troubleshooting.md` 及对应 DOCX/PDF。
- `docs/collaboration/phase-<n>/experience/demo-data-plan.md`、`deployment-input-index.md`、`manual-verification.md`。
- 个人任务日志；不提交真实账号密码或私密数据库。

### 验收和交接

B2 按部署手册在独立环境实际运行；管理员步骤由另一账号复查。所有文件使用当前端口/角色/数据库，任何恢复命令写明专用目标和检查步骤。向 B1/D2 交稳定的演示数据清单，向 A2 交部署事实，向技术负责人交环境问题。

## 十一、分组后如何交接与验收

每组指定一人维护 `group-deliverables.md`，列两人的独立文件、任务 ID、SHA、复核人与接收结论。四组周内交接参照配套任务包的 D1–D7 安排，每周材料映射回该阶段 Issue。

- 技术负责人 → B1/B2：可运行版本、账号/数据、已实现/Mock/限制、原始自动检查。
- B1/B2 → C1/C2：测试通过路径、缺陷/复测、环境与数据问题。
- B1/B2/C1/C2/A2 → A1：真实测试结果、手册/截图、设计与实现章节。
- A1/C1/C2/B1/B2 → D1/D2：报告结论、演示数据、图片、指标与可执行路径。
- 四组 → 技术负责人：各自候选包、复核记录、统一版本与遗留项。

组间疑问先写明相关需求/Issue、字段/步骤、当前证据与建议；技术负责人处理实现，材料 Owner 同步记录，原测试执行人复测。每项最终得到具体文件、执行结果、接收人和链接，才能进入阶段收尾。

## 十二、第一轮开始就要提交的内容

本轮 D1：八人填报名表；各人建任务日志；技术负责人发布基线和账号/运行包。D2：A1 交报告目录和需求清单，A2 交架构/实现事实索引，B1/B2 各交用例草稿，C1/C2 各交手册结构，D1 交 PPT 结构，D2 交演示流程。

D3–D4 用实际版本补证据并提缺陷；D5 跟进修复与首轮彩排；D6 完整候选包互审；D7 交付可核对的本周组包。输入未就绪时登记可做工作、不能执行的项目及责任人，不能以等待接口为由遗漏独立任务。
