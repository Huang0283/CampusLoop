## 3. 替补与互审

| 主责 | 替补/互审 | 触发条件 | 边界 |
|---|---|---|---|
| M1 | M10 | 项目资料、汇报或集成状态需要接管 | M10 可维护记录，不单方面改变业务范围 |
| M10 | M1 | 质量资料或发布清单需要接管 | M1 不能跳过独立复测结论 |
| M2 | M3 或 M4 | 公共前端阻塞或负责人不可用 | 业务页面仍由原主责说明 |
| M3 | M2 | 市场公共交互需要接管 | 智能字段需 M7/M8 复核 |
| M4 | M2 | 交易前端需要公共框架支持 | 交易状态必须由 M6 确认 |
| M5 | M6，数据库问题由 M9 支持 | 账号接口或数据故障 | 隐私与权限变更需专项评审 |
| M6 | M5，平台问题由 M9 支持 | 交易接口或事务故障 | 不能绕过状态机和数据迁移 |
| M7 | M8 | 数据、评估或智能任务阻塞 | 搜索/匹配口径仍由 M7 主责 |
| M8 | M7 | 数据、评估或智能任务阻塞 | 价格/风险口径仍由 M8 主责 |
| M9 | M5/M6 按模块支持 | 环境或迁移负责人不可用 | 共享数据库变更仍必须走迁移 |

## 4. 进度升级机制

1. 阻塞超过半天：成员在任务中记录影响、所需协助和下一检查时间。
2. 阻塞超过一个工作日：组内负责人组织结对、拆小任务或调整接口。
3. 连续两次未完成周目标：M1 与组内负责人调整范围或重新分配。
4. 影响他人的接口、状态、字段或目录变更：当天通知受影响负责人。
5. 任何重新分配都必须更新需求追踪、风险登记和变更记录。
