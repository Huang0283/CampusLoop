# Frontend-03 第一次汇报页面流程

## 使用方式

本讲解稿控制在 3-5 分钟，由 M2 说明范围、导航和阶段边界，M3、M4 分别说明市场/求购与交易原型。演示使用 Mock 数据，不宣称已经完成真实接口联调。

## M2：范围、导航与身份（约 60 秒）

1. 从 `/login` 展示学生和管理员两种演示身份，说明未登录、学生、管理员三类页面权限。
2. 学生进入 `/market`，说明 `/` 以市场页承担首页和分类入口，不重复建设独立首页。
3. 展示共享侧栏、顶部栏和 `/profile`；说明页面清单、角色矩阵和五类状态设计位于 `docs/frontend/m2/`。
4. 管理员进入 `/admin`，学生访问该地址进入 `/403`，说明第一阶段只验证身份与页面边界。

## M3：市场、商品与求购（约 60-90 秒）

1. 按 `/market` → `/product/101` 展示商品列表、筛选、详情、卖家信息和举报入口。
2. 按 `/publish` → `/publish/price-advice` 展示发布字段、校验、建议区间、影响因素和“仅供参考”提示。
3. 打开 `/my-products` 和 `/favorites`，说明商品编辑、上下架、删除确认、收藏及异常状态设计。
4. 按 `/wanted` → `/wanted/1` → `/wanted/matches` 展示求购字段、匹配原因，并明确匹配分是相关程度而非成交概率。

## M4：聊天、交易与治理（约 90 秒）

1. 按 `/chat` → `/chat/5001` 展示会话、上下文、历史消息、结构化报价及失败重试。
2. 从报价进入 `/transactions/:id`，展示买家/卖家身份、订单时间线和状态对应按钮。
3. 打开 `/transactions/8001/meetup`，展示约定版本、修改后确认失效和双方确认。
4. 打开 `/transactions/8004` 展示争议状态；打开评价与举报弹窗，说明只有完成订单参与者能够评价，私聊和举报证据遵守最小可见原则。
5. 打开 `/notifications`，展示未读状态和目标页面跳转。

## 收尾说明（约 30 秒）

- 第一阶段交付页面范围、信息架构、低保真或静态 Mock、流程、状态和权限规则。
- 第二阶段把设计冻结为可点击 Mock 和接口契约；第三阶段才验收真实认证、HTTP/WebSocket、上传和持久化。
- 跨组字段、状态和测试确认仍由对应负责人完成，前端不自行代签。
