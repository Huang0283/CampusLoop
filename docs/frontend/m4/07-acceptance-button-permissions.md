# M4-07 按钮级权限验收方案（第一阶段）

> 状态：可执行。前置：dev server 运行于 `http://localhost:5174`，默认身份为 id=1（买家「我」），右上角可切换视角（写 localStorage，刷新保持）。

## A. 身份基座（stores/auth.ts）

| # | 操作 | 预期 |
|---|---|---|
| A1 | 打开 `/login`，以买家身份进入原型 | localStorage 出现 `token / role / userId / nickname` 四个键；跳首页 |
| A2 | A1 后刷新页面（F5） | 身份不丢——订单页按钮、列表过滤与刷新前一致（store 从 localStorage 恢复） |
| A3 | DevTools → Application → 删掉 `userId` 后刷新 | 回到未登录态，路由守卫踢回 `/login` |

## B. 订单操作按钮（OrderDetailPage + Can）

| # | 操作 | 预期 |
|---|---|---|
| B1 | `/transactions/8001`（我是买家，PENDING_CONFIRM） | 显示 4 个按钮：查看/填写约定、确认约定、取消（红）、举报 |
| B2 | 点右上「切换为卖家视角」 | 身份变为 id=2 李同学；按钮仍是 4 个但按卖家视角求值 |
| B3 | 保持卖家身份，访问 `/transactions/8003`（买卖双方是 1 和 3） | 出现橙色告警条「你不是该订单的买卖双方」，操作区零按钮，页面不崩 |
| B4 | `/transactions/8002`（COMPLETED，我是卖家） | 显示 查看评价 / 评价对方 / 举报；点「评价对方」弹 ReviewModal，对象是买家王学姐 |
| B5 | B4 中找「取消订单」 | 无此按钮——COMPLETED 状态矩阵里没有 cancel，验证的是矩阵而非硬编码 |

## C. 见面约定（MeetupPage）

| # | 操作 | 预期 |
|---|---|---|
| C1 | `/transactions/8001/meetup`，买家身份（meetup: buyerConfirmed=true） | 无确认按钮，显示「你已确认当前版本，等待对方确认」 |
| C2 | 切到卖家视角（id=2，sellerConfirmed=false）再进 | 确认按钮出现且可点；点击后确认进度真实变为 2/2，订单状态流转（mock 状态层） |
| C3 | B3 的非参与方身份进 `/transactions/8003/meetup` | 只读：上方展示卡正常，「填写/修改约定」表单整块不渲染 |

## D. 报价卡片（OfferCard）

| # | 操作 | 预期 |
|---|---|---|
| D1 | `/chat/5001`（我是 buyer，报价 9001/9002 是我发的） | 卡片显示「撤回报价」文本按钮，无接受/还价/拒绝 |
| D2 | `/chat/5002`（我是 seller，报价 9003 对方发的） | 显示 接受（主）/ 还价 / 拒绝；无撤回 |
| D3 | 切到卖家身份后回 `/chat/5001` | 两张卡片换成 接受/还价/拒绝——同一组件按身份重新求值 |
| D4 | `/chat/5001` 点「接受报价」（9002） | 报价卡片状态变为 ACCEPTED，生成新订单并跳转订单详情（mock 状态层全流程） |

## E. DISPUTED 争议态（2026-09-18 新增，订单 #8004）

| # | 操作 | 预期 |
|---|---|---|
| E1 | `/transactions/8004`，买家身份 | 状态标签红色「有争议」；步骤条停在「已预约」且 error；出现争议告警条 |
| E2 | 观察「取消订单」按钮 | 存在但灰色禁用，hover 出 tooltip「争议处理中，等待管理员裁决」 |
| E3 | 「查看见面约定」「举报」 | 正常可点（disabled 只作用于 cancel） |
| E4 | 切卖家视角再进 8004 | 同样表现（矩阵买卖双方对称） |
| E5 | 对比 `/transactions/8003` 的「取消订单」 | 红色可点——证明禁用是矩阵求值，不是写死 |

## F. 一致性回归（身份是全局的）

| # | 操作 | 预期 |
|---|---|---|
| F1 | 切到卖家（id=2）后访问 `/transactions` | 「购买」页签为空（user 2 无买单），「出售」出现订单 8001（列表过滤读的是同一份 localStorage 身份） |
| F1b | 同一身份下观察“全部”列表 | 每条订单的视角标签按身份推导：参与的单显示「我出售的 · 对方：我」，非参与单显示「非参与方 · 对方：—」 |
| F1c | 访问旧地址 `/profile/transactions` | 自动重定向到 `/transactions`，不出现 404 |
| F2 | `/chat/5001` 发一条消息 | 消息靠右的判定跟随新身份——证明不是页面局部动画 |

## G. 静态验收

- `npm run build` 通过
- 全局搜索：`OrderDetailPage` / `MeetupPage` 内不存在对 `CURRENT_USER_ID` 的引用（身份判断全部收敛到 access 层）
- 契约文档 `06-button-permissions.md` 存在且含与 M6 的边界三条

## 不在本方案范围

1. 管理员权限 `can.has('dispute:handle')`：无 UI 入口，属纯函数层，留给单测。
2. 接口安全：前端隐藏只是体验，服务端 403 校验是 M6 的验收项。
