# M4-02 交易异常交互规范（第一阶段 v0.1）

> 覆盖 PDF 任务要求：断线、消息补拉、重复消息、发送失败、重复提交、报价过期、一方确认、约定修改。
> 每个页面必须覆盖：加载 / 空数据 / 成功 / 失败 / 无权限 五种状态。

## 1. WebSocket 断线与重连

| 场景 | 前端表现 | 技术方案 |
|---|---|---|
| 连接建立中 | 聊天页顶部黄色提示条「连接中…」 | `status === 'connecting'` |
| 已连接 | 无提示条 | `connected` |
| 断线重连中 | 顶部黄色提示条「网络不稳定，正在重连…」+ 旋转图标 | `reconnecting`，指数退避 1s→2s→4s…上限 15s |
| 完全断开 | 顶部红色提示条「连接已断开，消息将以补拉方式同步」+ 手动重连按钮 | `disconnected` |
| 断线期间收到消息 | 恢复后不丢：进入/恢复聊天页时以 `lastMessageId` 调 HTTP 接口增量补拉 | 补拉结果按 `clientMsgId` 去重 |

## 2. 消息可靠性

- **去重**：每条消息携带客户端 `clientMsgId`（UUID），补拉与推送重复时按 id 覆盖，不重复渲染。
- **发送失败**：消息气泡右下角红色感叹号 + 「点击重试」；重试复用同一 `clientMsgId`（保证幂等）。连续失败 3 次提示检查网络。
- **发送中**：气泡半透明 + loading 图标。
- **乱序**：渲染前按 `createdAt` 排序；时间跨度 > 5 分钟插入时间分割线。

## 3. 重复提交防护（议价 / 确认完成 / 取消 / 评价 / 举报）

1. 所有写操作按钮提交期间置 loading，禁止二次点击。
2. axios 请求头携带 `Idempotency-Key`（UUID），同一动作生成一次，失败重试复用。
3. 后端若返回"订单状态已变化"（409），前端**刷新本地订单数据**后重新渲染操作矩阵，并 toast 提示「订单状态已更新」。

## 4. 报价过期

- `OFFER` 卡片实时检查 `expireAt`：剩余 <1h 显示红色倒计时；到期前端本地置灰并显示「已过期」。
- 过期卡片上「接受 / 拒绝 / 还价」按钮全部隐藏，仅卖家的 `PENDING` 报价展示操作按钮。
- 接受已过期报价时后端必然拒绝：前端捕获后刷新报价列表并提示「该报价已过期」。

## 5. 一方确认（完成 / 见面约定）

- 我方已确认、对方未确认：确认按钮变为 🔒 禁用 + 文案「等待对方确认」；详情页显示双方确认进度（1/2 → 2/2）。
- 对方确认后通过 `ORDER_UPDATE` 推送刷新；若断线，则在补拉订单详情时更新。

## 6. 约定修改提示（重点，PDF 明确要求）

- 任一方修改见面约定 → `meetup.version` +1 → **双方旧确认全部失效**，订单回到「待确认」。
- 前端在订单详情/约定页顶部显示醒目橙色 Alert：
  「对方已修改见面约定（第 N 版），之前的确认已失效，请查看新约定并重新确认。」
- 旧版本约定保留在"历史约定"折叠区，只读展示，防止扯皮。
