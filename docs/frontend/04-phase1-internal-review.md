# Frontend-04 第一阶段前端内部复核

## 复核范围

本文件记录 M2 对 M3、M4 交付物的结构、命名、入口和阶段边界复核结果。它是可供三名成员交叉评审的核对稿，不代替成员本人在 GitHub PR 中提交 Review。

## 统一术语

- 列表和导航统一使用“交易”，入口为 `/transactions`；“订单”用于具体订单及订单状态。
- 线下时间和地点统一使用“见面约定”，不再使用独立“预约”页面名称。
- `/my-products` 的页面名称统一为“我的发布”，`/favorites` 统一为“我的收藏”。
- `/` 以市场页承担首页和分类入口；侧栏只保留“首页”，不重复显示“市场”。
- 举报不设脱离上下文的 `/report` 页面，统一从商品、用户、订单或聊天消息上下文打开 `ReportModal`。

## M3 复核

- 页面范围覆盖市场、商品详情、发布、我的发布、我的收藏、求购、匹配和价格建议。
- 商品管理流程补充编辑、上下架和删除确认；求购流程补充发布者编辑入口。
- 筛选条件保留、草稿和离开提醒已冻结为第一阶段交互规则，不误写为真实持久化。
- 匹配分统一解释为相关程度；价格建议统一标注为参考信息。
- M6/M7/M8 的字段确认保持待办，前端当前值仅作原型假设。

## M4 复核

- 核心路径统一为 `/chat` → `/chat/:id` → 报价/订单 → `/transactions/:id` → `/transactions/:id/meetup`。
- 订单列表和个人交易中心统一使用 `/transactions`；旧地址只保留兼容重定向。
- 评价规则统一为仅 `COMPLETED` 订单参与者可评价；取消、未完成、争议订单不能进入正常评价流程。
- 举报证据和私聊采用最小可见原则，通知只展示必要摘要。
- M6 状态确认和 M10 双账号场景确认保持待办，不把 Mock 状态写成正式契约。

## 复核结论

- 页面名称、路径名称和核心术语已经统一。
- M3、M4 的第一阶段内部设计缺口已经补入文档。
- 第二阶段可点击原型和第三阶段真实接口任务未混入第一阶段关闭条件。
- 尚需三名前端成员在收尾 PR 中完成交叉 Review；尚需对应人员完成跨组确认、范围验收和可测试性确认。
