## 检查范围

使用生产预览、全新浏览器上下文及模拟会话检查六个页面：
校园市场、登录、发布商品、交易中心、通知、管理后台。
前五个页面使用 USER 会话，管理后台使用 ADMIN 会话。
本轮未访问真实业务数据，未执行真实业务写入。

普通页面在标题就绪后观察 2 秒，通知页观察 6.5 秒。
记录接口请求时间、控制台警告及错误、页面运行异常和非预期接口。

## 发现与修复

通知页与外壳原先各自维护一份通知查询和 5 秒轮询。
修复前，通知列表在首次加载和第一个轮询周期各请求两次，共 4 次。

修复后，外壳通过 React Context 向通知页提供同一份资源和刷新入口。
通知页不再独立轮询；已读操作统一通过通知变更事件触发刷新。

修复后相同观察窗口内，通知列表共请求 2 次，间隔约 5 秒。
举报列表仍保持自身每 5 秒一次的正常轮询。
六个页面的采样均未捕获控制台警告、错误、页面运行异常或非预期接口。

## 针对性回归

m2-notification-sync.spec.ts 在 Edge 和 Chrome 各通过 1 项，
共 2 项通过，耗时 14.0 秒。

覆盖首次加载、单一轮询、单条已读、全部已读，
以及通知页状态与右上角未读计数同步。
模拟写入仅有预期的两次已读请求，未捕获非预期接口或运行错误。
lint、TypeScript 和生产构建通过；主入口体积警告仍存在。
