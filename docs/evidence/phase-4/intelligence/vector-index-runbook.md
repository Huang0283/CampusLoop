# AI4-02 向量索引运行手册

更新：2026-10-11。实现位于 `services/m7_semantic/index.py`，入口 `VectorIndex.rebuild/upsert/delete/query/logical_digest/close`。可运行命令见 [服务说明](../../../../services/m7_semantic/README.md)。

构建输入为经 schema 校验的商品快照与同模型向量，输出为 M7 实验 SQLite 索引。CLI 按数值商品 ID 固定顺序编码；模型及配置 identity 绑定 revision、逐文件哈希、维度、预处理、完整字典、schema、索引及排序版本。数据库同时保存商品 entityVersion 和完整事实哈希。重建先验证整个批次，再以事务替换数据和 READY 元数据。比较逻辑内容哈希，不承诺 SQLite 物理文件字节相同。

增量更新在同一事务检查 entityVersion：同版本同事实幂等，保留既存向量以容忍批次浮点舍入；同版本不同事实冲突；旧版本忽略。下架/删除保留墓碑；`delete(productId, version)` 接收带版本删除事件，墓碑阻止旧事件复活商品。任何批次冲突都会回滚此前写入。重建用于全量权威快照替换，调用方必须保证快照新鲜，不能以旧快照覆盖最新业务事实。

查询必须匹配模型/配置 identity，检查每个合格商品的版本及事实哈希。未就绪、版本不兼容、商品缺失/墓碑/事实过时均明确失败，交由混合入口回退基线。余弦只在授权与硬条件过滤后的集合计算，再截取 topK，避免先全库取 topK 导致合格商品被截掉。向量余弦相同按数值 ID 排序。

测试覆盖事务原子性、幂等、乱序事件、墓碑、版本冲突、事实过时、缺模型、持久化重开、归一化和重建确定性。实际固定模型的增量更新、重复事件、旧事件及删除测试见 `evidence/m7-v1/run-record.json`。模型、SQLite 和环境缓存不进入 Git 或交付 ZIP。

M6 真实事件、数据库/outbox 原子写入及生产向量库尚未接入；不能将此私有索引作为联调通过证据。
