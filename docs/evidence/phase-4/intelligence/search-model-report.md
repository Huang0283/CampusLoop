## 延迟、重复性及失败审计

真实模型每次按固定顺序、batch=16 编码，同机同配置重复向量及逻辑索引哈希一致；两个独立进程的逐样本排序与指标文件也需在 verify 中字节一致。运行提交、全量输入哈希、环境和完整依赖见 `evidence/m7-v1/run-record.json` 与 `evaluation/evaluation-status.json`。

测量为同机 CPU、模型预热后的单进程逐请求一次，包含校验、过滤、查询编码和排序；模型首次加载及两次全量编码另外记录，不算进预热延迟。P95/P99、逐请求耗时、峰值进程 Working Set、模型文件及 SQLite 占用见 `evaluation/timings.json`，不冒充并发 SLA 或生产 RSS 验收。跨硬件浮点误差容忍须由 M10 事先约定。

失败分类逐请求记录于 `evaluation/failure-analysis.json`，区分未知条件排除、求购已失效、正例无结果/未排首位、无答案误推荐、硬约束违规和候选降级。无结果/未知/失效请求不通过改变标签或删请求美化。无答案场景即使本次未误推荐，仍需更丰富查询；向量候选未设经验证的相似度阈值，不能声称具备可靠置信度拒答。
