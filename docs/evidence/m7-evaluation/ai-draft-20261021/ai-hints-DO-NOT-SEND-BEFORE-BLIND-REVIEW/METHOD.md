# AI 初审建议的生成方法

这些记录属于 `AI_RULE_DERIVED_DRAFT_NOT_HUMAN_REVIEW`，不是独立人工复核，也不是两名 AI 分别评审。
查询由 Codex 按原商品快照编写，建议标签由公开说明的确定性规则辅助生成，可能出错。
没有运行关键词搜索或 BGE 候选来挑选容易得分的查询或生成标签。

1. 对请求与商品调用原项目 `scripts/m7_phase2/pipeline.py` 的 hard_constraints。
   搜索先移除查看者/校区上下文，只评公共可见性；求购按构造的求购人和场景时点检查。
2. 已知硬约束失败时建议 0；约束所需事实缺失时建议 U。
3. 对其余商品，根据明确保存的 draftIntent 判断。类别与意图不符建议 0。
4. 查询要求保修期限和购买凭证、快照未提供这些字段时建议 U。
5. 型号场景将 NFKC 规范化、忽略空格/大小写/连字符后的目标型号与商品型号及标题比对。
   相符建议 2，同类别的其他型号建议 1。指定型号的结构化筛选仍受前面的硬约束约束。
6. 用途场景按已披露的用途类别给初步建议。标题明确是吸顶灯、查询要求书桌阅读灯时建议 0；
   某些特定用途的其他型号仅建议弱相关 1，其余同类商品暂建议 2。
   这一步不证明功能、尺寸、适配性或全部语义条件成立，需要成员逐条核对，不得直接当真值。

每行保留方法类别、建议理由、AI 作者、实际机器生成时间和原始请求/商品 ID。
保留不同意见，不依据模型效果修改建议。人工复核另用盲审表，先不展示这些建议。
原始商品信息不足时，应由数据负责人补事实或保留 U，不能为了满足最低数量强行填写相关标签。
