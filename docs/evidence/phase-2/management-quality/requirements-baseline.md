## 冻结术语

- 商品：学生发布的可交易物品；生命周期与可见性由服务端状态决定。
- 求购：买家表达的需求记录；匹配结果不自动关闭求购。
- 匹配：先执行资格/预算/成色/地点/有效期硬约束，再计算软相关度。
- 聊天会话：围绕商品或求购建立的双人私有会话。
- 报价：会话内结构化交易提议，不等于订单。
- 订单：报价被有效接受后创建的唯一交易事实。
- 见面约定：双方协商结果的版本化记录，不提供智能时间或地点推荐。
- 完成确认：买卖双方分别确认；单方确认不得完成订单。
- 评价：仅已完成订单参与者各提交一次。
- 举报：用户提交的治理记录；证据默认私有。
- 智能分数：相关度或规则评分，不是成交概率、信誉事实或欺诈概率。

## 角色和权限

- 游客：读取公开市场、商品详情、求购列表和求购详情；不能执行私有动作。
- 普通用户：在游客权限上，可维护本人资源、参与本人交易、收藏、举报和查看本人通知。
- 资源参与者：除角色外还必须满足资源所有权或交易参与关系。
- 管理员：只在显式管理接口执行审核；管理权限不能自动读取无关私聊、约定和举报证据。
- 服务/Worker：使用内部身份处理任务；不能信任客户端传入的 `ownerId`、角色或授权布尔值。

## 核心状态候选

- 用户：`ACTIVE`、`DISABLED`。
- 商品：`ON_SALE`、`RESERVED`、`SOLD`、`HIDDEN`；逻辑删除由持久化字段表达，不增加客户端可写状态。
- 求购：`OPEN`、`MATCHED`、`CLOSED`、`EXPIRED`；`MATCHED` 的业务含义需在 `MQC-003` 关闭后冻结。
- 报价：`PENDING`、`ACCEPTED`、`REJECTED`、`COUNTERED`、`EXPIRED`、`CANCELLED`。
- 订单：`PENDING_CONFIRM`、`BOOKED`、`MEETUP_ARRANGED`、`COMPLETED`、`CANCELLED`、`DISPUTED`。
- 见面：`PROPOSED`、`CONFIRMED`、`COMPLETED`、`CANCELLED`。
- 举报：`PENDING`、`PROCESSING`、`RESOLVED`、`REJECTED`。

状态只能由契约定义的业务动作转换；Phase 3 必须为重复、越权、过期和非法前置状态提供确定结果。

## 契约和数据规则

- API 服务地址候选为 `http://localhost:8000`；前端开发地址为 `http://localhost:5173`。
- 金额在存储层使用精确十进制，智能数据使用整数分或明确的十进制文本；不得用二进制浮点猜回金额。
- 所有写入按风险使用幂等键、唯一约束或版本号；客户端重试不得创造重复事实。
- PostgreSQL 是交易事实来源；Redis 只作缓存、撤销、未读和临时协调；对象存储分公共商品图与私有举报证据。
- 公共响应只返回最小公开用户字段；错误、日志、通知和智能解释不得包含邮箱、Token、私聊、约定或举报证据。
- AI、Redis、对象存储或 WebSocket 故障时，基础浏览、关键词搜索和可替代交易不得被误标为智能成功。
