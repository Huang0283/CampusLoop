## 认证与资料

### P3-AUTH-001 注册成功

- 层级：接口 + 页面。
- Given：未注册的虚构邮箱、合法 nickname 和密码。
- When：从 `/register` 提交一次。
- Then：HTTP `201`，建立会话；数据库只保存密码哈希；页面进入登录后目标页。
- 证据：接口响应、用户行的非敏感字段、浏览器跳转。

### P3-AUTH-002 重复注册和输入错误

- Given：已存在邮箱以及缺失/非法字段。
- When：重复或非法提交。
- Then：重复为 `409`，输入错误为 `422`；不新增用户或会话。

### P3-AUTH-003 登录、错误凭据和禁用账号

- Given：ACTIVE 与 DISABLED 测试账号。
- When：正确密码、错误密码和禁用账号分别登录。
- Then：成功为 `200`；错误凭据 `401`；禁用账号 `423`；页面反馈可区分。

### P3-AUTH-004 刷新轮换与退出撤销

- Given：有效 refresh token。
- When：刷新、重放旧 token、退出后再次刷新。
- Then：新 token 生效；旧/撤销 token 返回 `401`；服务端撤销事实可查。

### P3-AUTH-005 来源路由恢复

- Given：游客从含 query/hash 的私有动作进入登录。
- When：成功登录。
- Then：返回原 pathname、query、hash；外部 URL 不被接受为回跳目标。

### P3-AUTH-006 资料公开白名单

- Given：本人资料含邮箱、认证和私有数据。
- When：本人读取/修改与他人读取公开资料。
- Then：本人按契约读写；公开响应不含邮箱、Token、私聊、约定和举报证据。

## 商品与求购

### P3-MARKET-001 匿名列表与详情

- Given：在售、已售、隐藏和删除商品。
- When：无 Token 请求列表、筛选、排序、分页和详情。
- Then：允许的公开结果返回 `200`；非法参数 `422`；不存在 `404`；隐藏/删除不泄漏。

### P3-MARKET-002 发布商品幂等

- Given：卖家登录、合法图片和同一 `Idempotency-Key`。
- When：连续提交两次。
- Then：只创建一件商品和一组图片；第二次返回同一事实或确定冲突。

### P3-MARKET-003 编辑和状态转换

- Given：本人商品处于不同状态。
- When：编辑、上下架、删除和非法转换。
- Then：允许转换成功；非本人 `403/404`；非法状态 `409`；失败不产生部分更新。

### P3-MARKET-004 收藏幂等与状态同步

- Given：买家和在售商品。
- When：重复收藏、取消和查看已售/下架商品。
- Then：唯一收藏；重复请求不报伪成功；列表显示当前商品状态。

### P3-WANTED-001 求购生命周期

- Given：买家登录。
- When：创建、编辑、关闭和到期处理。
- Then：预算和有效期校验明确；非本人拒绝；关闭/到期后不可非法恢复。

### P3-WANTED-002 匹配不自动关闭求购

- Given：OPEN 求购产生匹配结果。
- When：读取匹配并刷新结果。
- Then：求购仍按冻结语义保持可接收候选；只有显式关闭动作改变生命周期。

## 聊天、报价和订单

### P3-CHAT-001 会话创建与参与者权限

- Given：商品卖家、买家、第三方。
- When：买家重复联系卖家，第三方读取会话。
- Then：相同上下文复用或幂等创建会话；第三方 `403/404`。

### P3-CHAT-002 消息持久化、重复和补拉

- Given：双方会话与固定 `clientMsgId`。
- When：发送、断线、重复发送、重连补拉。
- Then：先持久化后推送；重复不新增；按游标补齐缺失消息。

### P3-OFFER-001 报价状态机

- Given：PENDING 报价。
- When：接受、拒绝、还价、取消、过期及重复动作。
- Then：只有角色和前置状态合法的动作成功；非法/过期/重复为确定 `409/403`。

### P3-ORDER-001 并发接受唯一订单

- Given：同一商品两个有效报价。
- When：两个请求并发接受。
- Then：只有一个订单和一个商品占用成功；另一个请求失败；事务无部分事实。

### P3-ORDER-002 订单事件与可见性

- Given：有效订单和非参与者。
- When：参与者/第三方读取详情和事件。
- Then：参与者看到允许字段；第三方拒绝；事件顺序和分页稳定。

### P3-MEETUP-001 约定版本确认

- Given：版本 N 的时间地点。
- When：一方修改为 N+1，双方分别确认旧/新版本。
- Then：旧确认失效；只有双方确认同一有效版本才进入确认状态。

### P3-COMPLETE-001 双方完成确认

- Given：有效约定和未完成订单。
- When：单方确认、双方确认、重复确认。
- Then：单方不完成；双方后订单 COMPLETED、商品 SOLD；重复不产生新事件。

### P3-REVIEW-001 完成后评价

- Given：完成/取消/争议订单及第三方。
- When：参与者评价、重复评价、第三方评价。
- Then：完成订单参与者各一次；其余拒绝；汇总值来自已落库评价。

### E2E-P3-001 双账号主闭环

- 路径：A 发布 → B 匿名搜索 → B 登录联系 → 聊天/报价 → A 接受 → 约定版本确认 → 双方完成 → 双方评价。
- 通过：页面、HTTP、数据库和事件结果一致；重试不产生重复事实；所有证据绑定同一提交。

## 举报、通知和降级

### P3-REPORT-001 举报隐私和审核

- Given：用户举报带私有证据，管理员登录。
- When：普通用户读取他人证据、管理员处理。
- Then：普通用户拒绝；管理员决定含原因和审计；公共响应不泄漏证据对象键。

### P3-NOTIFY-001 通知去重和已读

- Given：同一业务事件重复投递。
- When：生成通知、单条已读、全部已读。
- Then：同一接收人/事件只生成一次；已读操作幂等；他人通知不可访问。

### P3-DEGRADE-001 Redis/WebSocket 故障

- Given：数据库正常，Redis 或 WebSocket 不可用。
- When：浏览、发布、关键词搜索和可替代交易动作。
- Then：基础事实仍由 PostgreSQL 保持；页面提示降级；需要实时能力的动作明确失败或补拉。

### P3-DEGRADE-002 AI 服务故障

- Given：智能超时、索引未就绪或结果过期。
- When：搜索/匹配。
- Then：回退关键词/硬约束结果；`degraded=true` 和原因可见；不把回退称为模型成功。
