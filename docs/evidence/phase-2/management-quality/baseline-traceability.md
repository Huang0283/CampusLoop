# MQ2-03 Phase 2 基线追踪矩阵

> 版本：`MQ-P2-TRACE-0.1`
> 日期：2026-09-29
> 规则：每项需求必须说明页面、接口/服务、数据、测试和当前结论；不适用必须明确写出原因。

## 认证与资料

### AUTH-001 注册、登录、退出和会话失效

- 页面：`/login`、`/register`；前端证据 `auth-profile-prototype.md`。
- 接口：`POST /auth/register`、`/auth/login`、`/auth/refresh`、`/auth/logout`。
- 数据：`users`、`refresh_sessions`；M5 仍需冻结 Token 生命周期。
- 测试：`P3-AUTH-001—006`；错误凭据、禁用、过期和撤销。
- 结论：原型/契约候选存在，真实认证实现属于 Phase 3。

### AUTH-002 用户资料与模拟校园认证

- 页面：`/profile`、公开用户资料。
- 接口：`GET/PATCH /users/me`、`GET /users/{userId}`。
- 数据：`users` 的公开/私有字段；真实学校 SSO 不适用，原因是已排除。
- 测试：`P3-AUTH-007—010`；公开字段白名单与本人修改。
- 结论：前端原型存在；M5 字段契约待提交。

### AUTH-003 角色与资源所有权

- 页面：路由角色图和所有私有动作守卫。
- 接口：所有受保护写接口与管理接口。
- 数据：`users.role/status`、资源 `owner_id`、订单参与者。
- 测试：`SEC-AUTH-001—008`。
- 结论：角色枚举已对齐；服务端授权实现待 Phase 3。

## 市场与求购

### MARKET-001 商品发布、编辑、上下架和删除

- 页面：`/products/new`、`/products/:id`、我的发布。
- 接口：`POST /products`、`PATCH/DELETE /products/{id}`、`PATCH /products/{id}/status`。
- 数据：`products`、`product_images`、状态检查和所有权外键。
- 测试：`P3-MARKET-001—008`、`SEC-MARKET-001—004`。
- 结论：页面原型、OpenAPI 和迁移存在；业务接口未实现。

### MARKET-002 市场、详情、分页和排序

- 页面：`/market`、`/products/:id`。
- 接口：匿名 `GET /products`、`GET /products/{id}`。
- 数据：公开商品字段与公开卖家最小白名单。
- 测试：`P3-MARKET-009—014`，含空、非法参数和 `404`。
- 结论：Phase 2 可点击原型通过构建；真实 HTTP 待 Phase 3。

### MARKET-003 关键词搜索和筛选

- 页面：市场搜索、筛选、排序和返回列表状态。
- 接口：`GET /products` 的 `query/category/status/sort`；智能扩展 `GET /search`。
- 数据：商品标题、描述、类别、品牌、金额、成色、地点。
- 测试：`P3-SEARCH-001—008`、`AI-SEARCH-001—004`。
- 结论：关键词契约候选可用；M7 高级字段尚未合入唯一 OpenAPI。

### MARKET-004 所有权与禁止自购

- 页面：编辑、收藏、联系和购买动作状态。
- 接口：商品写接口、会话/报价创建接口。
- 数据：`products.owner_id` 与当前用户、订单买卖方。
- 测试：`SEC-MARKET-005—009`、`AC-04`。
- 结论：设计规则已冻结，服务端校验待 Phase 3。

### MARKET-005 收藏和状态同步

- 页面：商品详情和收藏列表。
- 接口：`GET /favorites`、`PUT/DELETE /favorites/{productId}`。
- 数据：`favorites` 唯一键、商品当前状态。
- 测试：`P3-FAVORITE-001—006`。
- 结论：契约候选存在；列表状态策略需 M6 确认。

### MARKET-006 求购生命周期

- 页面：`/wanted`、`/wanted/new`、`/wanted/:id`、匹配结果。
- 接口：匿名 GET；受保护 POST/PATCH/close；`GET /wanted/{id}/matches`。
- 数据：`wanted_posts`、预算、类别、需求、状态、有效期。
- 测试：`P3-WANTED-001—010`、`AI-MATCH-001—006`。
- 结论：前端和数据契约存在；`MATCHED` 语义待 `MQC-003`。

## 聊天与交易

### TRADE-001 双人会话、消息持久化和补拉

- 页面：`/chat`、会话详情。
- 接口：会话列表、消息列表、发送、已读；WebSocket 在 Phase 3 定义。
- 数据：`chat_sessions`、`chat_messages`、参与者和 `clientMsgId`。
- 测试：`P3-CHAT-001—010`、`SEC-CHAT-001—004`。
- 结论：OpenAPI/迁移候选存在；M4 页面证据和真实补拉未完成。

### TRADE-002 报价、拒绝、还价和过期

- 页面：聊天内结构化报价卡片。
- 接口：创建报价及 accept/reject/counter/cancel。
- 数据：`offers`、父报价、金额、过期时间、状态。
- 测试：`P3-OFFER-001—012`。
- 结论：状态枚举存在；写操作前置、错误样例待 M6。

### TRADE-003 接受报价并创建唯一订单

- 页面：报价接受反馈和订单入口。
- 接口：`POST /offers/{id}/accept`。
- 数据：订单唯一性、商品占用和数据库事务。
- 测试：`P3-ORDER-001—006`、并发 `SEC-ORDER-001`。
- 结论：迁移有候选约束；并发实现与证据待 Phase 3。

### TRADE-004 订单状态与事件

- 页面：订单列表、详情和事件时间线。
- 接口：`GET /orders`、详情和 events。
- 数据：`orders`、`order_events`；客户端不得直接写状态。
- 测试：`P3-ORDER-007—012`。
- 结论：契约候选存在；事件分页和可见性待 M6。

### TRADE-005 见面约定版本确认

- 页面：订单详情约定编辑/确认。
- 接口：保存约定、确认约定。
- 数据：版本号、时间、地点、双方确认版本。
- 测试：`P3-MEETUP-001—008`、`AC-09`。
- 结论：智能推荐不适用；原因是项目明确排除。

### TRADE-006 双方完成确认

- 页面：订单详情双方确认状态。
- 接口：`POST /orders/{id}/confirm-complete`。
- 数据：买卖方独立确认、订单和商品原子变化。
- 测试：`P3-COMPLETE-001—006`、`AC-10`。
- 结论：契约候选存在；事务实现待 Phase 3。

### TRADE-007 完成后评价

- 页面：订单完成后的评价入口。
- 接口：`POST /reviews`。
- 数据：参与关系、完成状态、每人每单唯一约束。
- 测试：`P3-REVIEW-001—007`、`AC-11`。
- 结论：迁移候选存在；M4 页面证据待提交。

### TRADE-008 取消和争议

- 页面：订单详情取消/争议状态。
- 接口：`POST /orders/{id}/cancel`；争议操作待 M6 明确。
- 数据：取消原因、争议状态、商品释放策略。
- 测试：`P3-ORDER-013—018`。
- 结论：取消契约存在；争议入口和回滚语义未冻结。

### TRADE-009 幂等

- 页面：重复点击显示同一结果，不制造重复卡片。
- 接口：写操作使用 `Idempotency-Key`、业务唯一键或版本。
- 数据：消息、报价、订单、通知和评价唯一约束。
- 测试：`SEC-IDEM-001—010`。
- 结论：M7 契约有完整样例；M6 业务写接口文档待提交。

### TRADE-010 双账号完整旅程

- 页面：发布→搜索→聊天→报价→订单→约定→完成→评价。
- 接口：AUTH/MARKET/TRADE 全链路。
- 数据：学生 A/B/C 和管理员虚构数据。
- 测试：`E2E-P3-001`。
- 结论：Phase 2 不适用真实执行，原因是业务接口尚未实现；Phase 3 必跑。

## 智能能力

- 页面：搜索结果、解释、降级和过期状态。
- 接口：`GET /search`；M7 候选契约包含版本、超时和降级。

- 测试：`AI-SEARCH-001—010`。

- 页面：`/wanted/:id/matches`。

### AI-004 信誉和风险人工线索

- 页面：用户信誉说明与管理员授权视图。
- 接口/服务：Phase 4 定义；Phase 2 无线上接口，不适用真实调用。

- 测试：`AI-RISK-001—008`。

## 质量能力

### QUALITY-001 依赖降级

- 页面：明确降级提示，不能冒充成功。
- 服务：健康/就绪、AI/Redis/对象存储/WebSocket 降级。
- 数据：保留交易事实，不用缓存替代数据库。
- 测试：`P3-DEGRADE-001—010`、`AC-13`。
- 结论：健康接口单测通过；真实 Compose 受镜像阻塞。

### QUALITY-002 自动化与 CI

- 页面/数据：不适用业务页面；原因是工程门禁。
- 服务：前端 SDK/Lint/build，后端 Ruff/迁移/种子/pytest，智能契约测试。
- 测试：`CI-FE`、`CI-BE`、`CI-AI`。
- 结论：候选命令已定义；后端 CI 尚未启用前端 `sdk:check`，需修复。

### QUALITY-003 统一环境

- 页面：`5173`；HTTP：`8000`；PostgreSQL：`5432`；Redis：`6379`；MinIO：`9000/9001`。
- 配置：`.env.example`，禁止真实密钥。
- 数据：迁移和虚构种子。
- 测试：`ENV-001—008`。
- 结论：Compose 语法通过，MinIO 镜像不可拉取，未通过完整启动。

### QUALITY-004 迁移和恢复

- 页面：不适用，原因是数据库运维能力。
- 服务/数据：Alembic upgrade/downgrade、种子幂等、备份恢复。
- 测试：`DB-001—008`。
- 结论：迁移脚本存在；空库实跑因 Compose 阻塞未完成。

### QUALITY-005 文档、缺陷和发布门禁

- 页面/接口/数据：覆盖全部交付，不是单一业务功能。
- 测试：文档自检、缺陷等级、PR 证据和演示脚本。
- 结论：本目录提供 Phase 2 门禁；同组 Review 和联合确认仍待真实成员。

### QUALITY-006 需求、风险和变更追踪

- 页面/接口/数据：所有变更必须写影响范围。
- 测试：基线追踪完整性与变更单检查。
- 结论：`phase1-decisions.md`、本文件和 `change-control.md` 已建立。
