# Phase 2 基线变更控制

> Owner：M1；测试影响复核：M10
> 适用版本：`MQ-P2-BASELINE-0.1-CANDIDATE` 及后续冻结版

## 变更单必填内容

1. 变更编号、提出人、日期和目标版本。
2. 原需求/字段/枚举/状态/接口/测试值。
3. 新值及不能沿用旧值的原因。
4. 影响的需求 ID、页面、API、数据库、智能契约和场景 ID。
5. 数据迁移、兼容、回滚和废弃计划。
6. 实现 Owner、测试 Owner、接收人和绝对截止时间。
7. 变更提交、生成 SDK 提交、测试结果和遗留风险。

## 决策流程

1. Owner 在任务 PR 提交变更单，不通过聊天口头修改基线。
2. M1 判断纳入、延期或拒绝，并记录范围/计划影响。
3. 受影响接口或字段 Owner 确认最终值；M10 更新测试场景和 CI 门禁。
4. 先合入唯一契约，再生成下游代码；禁止先手改消费者。
5. 自动检查和受影响场景通过后才能合并；豁免必须按 `ci-quality-gates.md` 登记并设到期时间。
6. 合并后更新 `requirements-baseline.md`、`baseline-traceability.md` 和 handoff。

## 紧急变更

只有 P0 安全、隐私或数据破坏问题可以先阻断功能再补变更单。紧急修复仍必须在 24 小时内补齐影响分析、测试和回滚记录；不得以“紧急”为由跳过授权、迁移或证据。
