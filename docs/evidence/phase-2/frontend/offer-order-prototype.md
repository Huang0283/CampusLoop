# FE2-09 报价与订单原型交付

## 报价规则与入口

- `/chat/5002` 的在售商品 102 用于新交易旅程，学生 1 为卖家、学生 3 为买家。
- 发起报价必须是对应商品会话的参与学生，金额必须是有限正数；游客、管理员、错误会话、已预约/已售出商品均不得创建报价。
- 买卖身份与本次报价发起人分开：卖家也能报价，还价后 `proposerId` 切换为还价人，buyerId/sellerId 不变。
- 当前发起人只能撤回；另一参与方才能接受、拒绝、还价。过期报价禁止这些动作；统一有效期为 48 小时。
- 发起报价不锁定商品；接受有效报价后才创建待确认订单并将商品设为 RESERVED。重复接受或已有未取消订单不得再次创建订单。
- 保存失败时保留金额弹窗并明确报错，不能提示已成功保存。

## 订单状态与角色动作

- PENDING_CONFIRM：参与双方可修改/确认见面约定、取消；不得确认完成或评价。
- BOOKED：保留契约/旧种子状态；参与方可查看、修改或确认约定，不凭此跳过双方约定确认。
- MEETUP_ARRANGED：约定双方确认后到达；参与方独立确认完成、查看/修改约定或取消；单方完成不得变为 COMPLETED。
- COMPLETED：只读交易、查看评价、各自评价一次、举报；不得取消或修改约定。
- CANCELLED：终止订单，释放商品；不得确认完成或评价，查看历史与举报入口保留。
- DISPUTED：展示争议提示、历史和治理入口；禁止普通用户取消、修改约定或完成；管理员裁决真实实现留给后续阶段。
- 非参与者不能查看订单详情或约定，不仅仅是隐藏按钮；状态层也拒绝写操作。

## 可复现验收

1. 登录学生 1，进入 `/chat/5002`，接受学生 3 的报价；出现新订单且商品变为已预约。
2. 查看订单详情及时间线，执行约定填写与双方确认，然后双方分别确认完成。
3. 重复接受同一报价、对已预约商品继续报价、非参与学生访问新订单，应被拒绝。
4. 重置演示数据后，学生 1 发起还价，学生 1 不能接受自己的还价，学生 3 可以接受。
5. 进入 `/transactions/8001`、`/transactions/8002`、`/transactions/8003`、`/transactions/8004` 分别检查待确认、完成、已安排与争议样例。取消态通过取消可操作订单演示。
