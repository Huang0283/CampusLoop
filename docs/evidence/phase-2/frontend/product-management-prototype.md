# FE2-06 商品发布与管理原型

## 范围

- 发布入口：`/publish`，由路由登录守卫保护。
- 编辑入口：`/product/:id/edit`，复用商品表单页面并保持受保护状态。
- 个人商品入口：`/my-products`，用于承接编辑、上下架和删除确认原型。

## 发布流程

1. 用户填写标题、分类、成色、原价、售价、描述和交易地点。
2. 图片选择后进入 Phase 2 Mock 上传队列；只接受 JPG/PNG，最多五张，单张原型限制 5 MB。
3. 上传中的图片会阻止提交；没有任何成功上传的图片也会阻止提交。
4. 上传成功生成确定性的原型图片 URL，并写入统一商品 Mock 数据层。
5. 提交期间按钮进入 loading 并拒绝重复提交；成功后清除草稿并进入 `/my-products`。
6. `/my-products` 从同一 Mock 数据层读取，新建、编辑、上下架和删除在刷新后保持一致。
7. Phase 3 按 `page-api-map.md` 将 Mock 边界替换为 `POST /uploads/images`、`POST/PATCH /products`。

## 异常与反馈

- 格式错误：选择阶段直接拒绝非 JPG/PNG 文件。
- 数量超限：上传组件限制为五张。
- 大小超限：Phase 2 以 5 MB 作为原型演示限制；M6 冻结真实契约后由生成 SDK 限制替换。
- 上传失败：单张图片标记失败，失败图片 URL 不进入商品请求。
- 字段校验失败：由表单定位到具体字段。
- 重复提交：按钮 loading 与幂等键共同处理。
- 未登录：路由守卫保存来源并跳转登录。
- 可复现失败：设置 `sessionStorage.productMockUploadError=true` 或 `productMockSubmitError=true` 后重试。

## 草稿、编辑和离开提醒

- 发布与编辑草稿分别保存在 `campusloop:phase2:product-draft:new` 和带商品 ID 的键中。
- 刷新或重新进入表单时恢复字段和已完成图片；用户可以显式放弃草稿。
- 表单存在未提交修改时，刷新/关闭标签页触发浏览器离开提醒；点击“返回我的发布”时显示确认框。
- `/product/:id/edit` 从统一 Mock 数据层读取原商品并回填表单，保存后保持原 ID、状态和创建时间。

## 管理动作边界

编辑、上下架和删除确认在 Phase 2 使用统一 Mock 数据层完成可点击状态和刷新后持久化；真实 `PATCH/DELETE`、并发版本冲突和服务端持久化结果在 Phase 3 接口联调中验收。
