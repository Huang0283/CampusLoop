# FE2-07 求购与匹配解释原型

## 路由和权限

- 公开读取：`/wanted`、`/wanted/:id`。
- 登录后页面：`/wanted/publish`、`/wanted/:id/edit`、`/wanted/:wantedId/matches`。
- 游客可以浏览、搜索、筛选、排序、分页和查看详情；收藏、联系、举报、发布和个性化匹配使用动作或路由守卫。

## 契约映射

- 求购列表：`GET /wanted`，使用 `query` 执行服务端关键词搜索。
- 求购详情：`GET /wanted/{wantedId}`。
- 发布求购：`POST /wanted`，每次提交携带 UUID `Idempotency-Key`。
- 个性化匹配：`GET /wanted/{wantedId}/matches`，要求登录。

## 列表交互

- 当前契约没有求购分类字段，因此页面不伪造分类筛选。
- 关键词通过接口 `query` 参数重新请求。
- 预算、最低成色和排序在已加载结果上执行可复现的客户端原型行为。
- 列表一次最多加载一百条，筛选后的结果按每页十条分页；该限制在 Phase 3 扩展服务端筛选契约时移除。
- 重置操作会同时清空关键词、预算、成色、排序并返回第一页。

## 详情和匹配解释

- 详情展示预算区间、最低成色、地点、状态、发布者和有效期。
- “查看全部匹配结果”进入带 `wantedId` 的受保护路由，避免缺失对象上下文。
- `relevanceScore` 仅显示为相关程度百分比，不称为成交概率。
- 匹配原因优先展示 `reasons`，没有原因时展示约束或明确空说明。
- 价格只展示商品价格和原价，不给出成交保证。

## 降级和失败状态

- 列表或详情失败时显示错误状态，不回退到伪造成功数据。
- 资源不存在时显示空状态。
- 匹配服务失败时显示错误或无结果状态，不阻塞公开求购详情浏览。
- 求购收藏尚未进入当前 OpenAPI；已登录用户点击时显示“契约尚未纳入”的明确提示，不伪造收藏成功。
