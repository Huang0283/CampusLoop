# FE2-10 约定、完成、评价、举报与通知原型

## 约定和完成

- `/transactions/:id/meetup` 仅交易参与者可查看。非参与者不得读取时间、地点或备注。
- 保存约定校验非空地点、日期、合法时间和结束时间晚于开始时间；保存失败不导航、不提示成功。
- 每次修改版本 +1，双方约定确认和双方完成确认全部失效，订单回到 PENDING_CONFIRM。
- 双方确认当前约定后进入 MEETUP_ARRANGED；只有该状态及当前版本双确认满足时，才允许分别确认完成。
- 单方完成保持已安排；双方完成后订单 COMPLETED、商品 SOLD。
- 已完成、已取消、争议订单不展示可编辑表单；历史区域只展示真实保存的 Mock 事件说明，不再虚构旧版本地点/时间。

## 评价

- `/transactions/:id/review` 和订单内评价弹窗使用同一状态层。
- 只有已完成订单的参与学生可评价本次交易的另一方；每位评价者每个订单只允许一次；四项评分须为整数 1–5。
- 待确认、未完成、取消订单及第三人不可评价；失败不能显示成功或关闭输入。
- 仅保存本次内存 Mock；刷新后不保证保留。双方评价互见时机仍以 Phase 3 服务端契约为准，当前不声明已实现双盲。

## 四类举报

- 用户：会话详情的对方用户入口。
- 商品：商品详情入口，游客先完成登录动作守卫。
- ORDER：交易详情入口。
- MESSAGE：聊天消息入口。
- 共用 `ReportModal`；reason 必填，description 按 canonical 最多 2000 字，证据可选、最多 5 张，JPG/PNG、每张不超过 5 MiB。被拒绝文件不进入有效列表。
- Phase 2 仅保存目标与证据文件名，不上传图片、不获取私密聊天证据、不承诺管理员已收到或 48 小时内实际处理。真实私有桶、审计和裁决留给 Phase 3/4。

## 通知与交易中心

- `/notifications` 仅展示当前学生的通知，单条/全部已读只修改该接收人的通知；根据上下文链接进入对应订单或会话。
- `/transactions` 只列出当前学生参与的交易，支持状态/身份筛选；订单详情读取与写入再次校验参与关系。
- 原型接受报价、约定修改/确认、完成、取消和举报产生对应内存通知；这是本地可点击旅程，不是已实现消息投递服务。
