# MQ1-05 五周单周阶段计划与关闭门禁

详细执行计划见 [`docs/management/m1/ten-week-plan.md`](../../../management/m1/ten-week-plan.md)。

> 兼容说明：文件名沿用早期的 `ten-week-plan.md`，避免破坏已有 Issue、PR 和证据链接；正式计划已改为五个连续的一周阶段。

## Phase 1：第 1 周

- 结果：范围、职责、需求追踪、页面/领域/智能可行性和质量框架形成候选闭环。
- 证据：四组个人产物、组内 Review、范围评审、第一次汇报彩排和阶段交接。
- 关闭门禁：所有能力有 Owner、阶段和验收；四组汇总进入阶段集成；M1/M10 完成收口。

## Phase 2：第 2 周

- 结果：需求和设计基线冻结，可点击原型、OpenAPI、SDK、数据库、统一环境、智能和测试契约一致。
- 证据：原型、契约校验、生成 SDK、迁移/种子、环境冒烟、契约测试和交接记录。
- 关闭门禁：非作者可启动环境；契约与 SDK 一致；原型和测试可按冻结输入执行。

## Phase 3：第 3 周

- 结果：两个账号通过真实 API 和持久化数据完成发布、浏览、聊天、报价、订单、见面、双方确认、评价、举报和通知。
- 证据：API/WebSocket/权限/状态测试、双账号 E2E、缺陷清单和 MVP 标签。
- 关闭门禁：关键流程不依赖未标记 Mock；非法状态、越权、重复和并发场景有明确结果。

## Phase 4：第 4 周

- 结果：至少两个智能功能真实接入，有基线对比、解释、治理和降级；周末冻结功能。
- 证据：数据/模型版本、运行命令、原始指标、集成和不可用演示、隐私检查和冻结清单。
- 关闭门禁：指标可复现；AI 不改变权威交易事实；服务失败不阻塞基础交易。

## Phase 5：第 5 周

- 结果：冻结版本完成缺陷收敛、干净部署、回归、恢复、性能、文档、演示和提交。
- 证据：最终 CI/回归/安全/负载/备份恢复结果、指南、报告、汇报材料、贡献记录和最终标签。
- 关闭门禁：非作者可以启动和演示；P0/P1 清零；提交包无缺项、密钥、真实隐私或虚假指标。

## 每周共同证据要求

每周退出必须记录提交号、运行环境、命令或操作步骤、实际结果、失败证据、缺陷结论和下一阶段接收人。未完成项必须记录 Owner、依赖人、影响、下一动作和明确截止时间；未达到门禁不得关闭阶段 Issue。
