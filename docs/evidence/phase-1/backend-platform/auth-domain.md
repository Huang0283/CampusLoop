## 2. 领域对象

| 对象 | 所表达的事实 | 责任与边界 |
|---|---|---|
| 账号 | 登录标识、凭据校验、账号状态 | M5；邮箱是私有登录标识，不是公开联系方式 |
| 用户资料 | 昵称、头像、简介、可选校园展示信息 | M5；本人编辑白名单，公开投影独立定义 |
| 角色 | 普通用户或管理员的能力集合 | M5；由服务端授权，注册请求和浏览器存储不能赋予管理员角色 |
| 会话 | 某次登录的有效性、期限、撤销及刷新关系 | M5；一次登录产生独立会话，退出默认撤销当前会话 |
| 校园模拟标识 | 未完成模拟流程或已完成教学模拟 | M5/M2；与账号是否有效、是否管理员分离 |
| 审核授权上下文 | 某管理员为某举报/纠纷读取哪些必要证据 | M5/M6；角色本身不等于全量私聊读取权 |
| 审计事件 | 敏感读取/变更的操作者、对象、原因和结果 | M5/M9；禁止保存密码、完整令牌或证据正文 |

买方、卖方是相对于某笔交易的关系，不是全局角色。管理员浏览市场或使用自己的交易资源时，也必须满足本人、参与者和状态条件。

## 3. 状态与不可变规则

### 3.1 三个独立维度

| 维度 | 概念状态 | 允许变化及约束 |
|---|---|---|
| 账号 | 正常、禁用 | 注册产生正常账号；有权限管理员可禁用/恢复并审计；恢复不复活旧会话 |
| 会话 | 有效、已轮换、已过期、已撤销 | 登录创建；刷新使旧刷新凭据失效；过期/撤销不能通过客户端重置；再次登录创建新会话 |
| 校园模拟 | 未模拟、教学模拟通过 | 由专用模拟流程控制；资料编辑不能自填“真实已认证”；具体触发和编码在 Phase 2 评审 |

“未登录”表示请求没有有效身份，不是数据库里的用户角色；访问令牌过期但刷新凭据仍有效时，可以尝试一次受控刷新。账号禁用、角色变化与会话撤销必须在服务端生效，不能仅依赖前端清除状态或令牌自然到期。

### 3.2 必须保持的规则

1. 注册只能获得普通用户身份；管理员初始化/授权通过受控运维流程，普通资料接口不支持升权。初始化方式由 M9 在 Phase 2 提交，M5/M10 复核。
2. 每次受保护访问校验：凭据有效、账号正常、会话未撤销、角色允许、对象归属/参与关系允许、业务状态允许。M6 负责最后两项的业务规则。
3. 禁用账号后不再允许登录、刷新和受保护操作；已有 WebSocket 不能继续收发私有数据。M6 需在连接及消息处理上接入身份失效语义。
4. 禁用不删除历史交易、不自动确认订单、不抹除证据。进行中的交易如何处理由 M6 提案、M1/M10 复核。
5. 刷新只允许一次有效消费；数据库中刷新凭据摘要唯一并不能证明“不可重放”，还需原子校验有效状态、消费旧凭据并产生新凭据。
6. PostgreSQL 保存可恢复的撤销事实；Redis 只能加速查询。无法验证身份时拒绝受保护操作，不得因缓存故障放行。
7. 资料、评价数、信誉和管理员处理记录来自各自事实 Owner；用户不能通过资料请求修改评分、交易次数、风险、角色或账号状态。

## 4. 账号与访问操作矩阵

下列“拒绝结果”为语义分类，不是已冻结 HTTP 状态码；Phase 2 由 M5 提交契约输入、M6 统一纳入 OpenAPI。

| 操作 | 允许者 | 拒绝者/边界 | 状态前置 | 成功与失败结果 |
|---|---|---|---|---|
| 注册 | 未登录访客 | 任何请求不得指定管理员角色或模拟认证结果 | 输入有效、登录标识可用、未触发限流 | 创建普通账号；非法字段/重复请求/冲突按统一语义拒绝，不写部分账号 |
| 登录 | 持有本人正确凭据者 | 错误或不存在账号的凭据、禁用账号 | 账号正常、凭据校验通过、限流允许 | 创建会话；不存在账号和错密码使用一致外部提示；禁用仅在凭据已验证后给出状态提示 |
| 刷新 | 持有本人有效刷新凭据的客户端 | 伪造、过期、撤销或已经消费的凭据；禁用账号 | 服务端会话有效且原子消费成功 | 返回新认证材料，旧刷新凭据失效；失败不签发令牌 |
| 退出 | 持有可定位当前会话的有效凭据者 | 不能指定其他用户/会话进行撤销 | 撤销事实可持久化 | 撤销当前会话；重复退出可返回中性已退出结果；服务不可用不得声称远端撤销成功 |
| 读取当前用户 | 当前正常账号本人 | 未认证、禁用或已撤销身份 | 身份检查通过 | 本人最小资料；不返回凭据摘要或其他人的隐私 |
| 修改资料 | 当前正常账号本人 | 他人、游客；管理员不能借普通资料接口改他人资料 | 本人对象且只包含可编辑字段 | 原子更新白名单字段；越权/保留字段/非法输入拒绝，不部分更新 |
| 完成校园模拟 | 正常账号本人，走专用教学流程 | 游客、他人、禁用账号；直接伪造资料字段 | 模拟步骤满足候选规则 | 只显示教学模拟标识；不声称学校核验；规则待 M1/M2/M5 评审 |
| 读取公开资料 | 游客、普通用户、管理员 | 私有字段均不开放 | 对象存在且允许公开 | 仅公开投影；对不可公开/不存在对象采用不泄露内部状态的响应 |
| 浏览市场/商品/求购 | 游客、正常用户、管理员 | 隐藏或私有资源仍按 M6 规则拒绝 | 资源处于公开可读状态 | 匿名浏览、搜索、筛选可用；公开读取不强制登录 |
| 收藏/发布/联系/举报 | 正常用户；管理员以普通用户身份操作本人资源 | 游客、禁用账号、非归属者或非参与者 | 身份、对象、状态均允许 | 交 M6 业务规则裁决；身份/对象/状态错误分别表达 |
| 禁用/恢复普通账号 | 授权管理员 | 普通用户、游客；默认不支持自禁用、操作其他管理员或角色提升 | 有原因、有目标、可记录审计 | 改变账号状态；禁用撤销全部会话；失败回滚，不留下无审计变更 |
| 查看审核证据 | 获得关联事项授权的管理员；本人按证据矩阵访问 | 无关联授权的管理员、被举报人、其他用户 | 授权范围有效、用途/原因明确、能记录访问审计 | 最小必要证据；越界拒绝，不返回公开链接 |

公开浏览采用当前 [Issue #21](https://github.com/Huang0283/CampusLoop/issues/21) 明确的“游客可读、登录后操作”边界。M2 Phase 1 原型中的“市场一律跳登录”记录为需对齐的历史差异，本 PR 不修改 M2 页面或声称对方已确认。

## 5. 管理员能力与治理限制

- 可管理普通账号状态、在授权事项内查看举报与必要证据、记录人工处理原因及审计；具体商品/订单处理由 M6 状态机限制。
- 不得读取密码或令牌、任意浏览全量私聊、代替交易双方完成确认、伪造评价、改写不可变交易事件。
- 审计包含操作者标识、事项标识、操作、目标、时间、原因、结果、请求关联标识；状态变更记录必要的脱敏前后值。
- 自己参与的交易或涉及自己的举报默认交其他管理员处理；无法分配时登记阻塞，不以自审绕过。
- 模型风险只提供线索，不能直接禁用账号或认定欺诈。敏感变更与审计需一致成功；审计失败则拒绝敏感操作。
