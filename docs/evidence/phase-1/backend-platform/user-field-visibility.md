# BP1-02 用户与关联隐私字段可见性

> Owner：M5（胡可铭）｜日期：2026-09-27｜状态：Phase 1 设计候选，待 M2/M6/M9/M10 评审
> 字段名称是概念标签，不冻结数据库列或 API schema。所有输出采用按用途定义的白名单，禁止直接返回 ORM 对象。

## 1. 四类可见性

- **公开**：游客和其他用户能够看到的最小资料。
- **本人/合法参与者**：经过身份和资源关系检查后的专用响应；“本人”不等于能看到别人上传的相关证据。
- **审核管理员**：有具体事项、有效授权、必要目的和审计记录的最小读取，不是所有管理员默认可读。
- **禁止返回**：任何资料、列表、审核、导出、日志、错误或通知都不得返回的凭据/内部数据；认证材料的专用签发例外单独列明。

## 2. 字段矩阵

| 概念字段/数据 | 公开 | 本人/合法参与者 | 审核管理员 | 编辑/来源与约束 |
|---|---|---|---|---|
| 用户标识、昵称 | 是 | 是 | 是 | 标识由系统生成；昵称由本人编辑，输出安全编码 |
| 头像、简介 | 是，用户明确选择公开的内容 | 是 | 是 | 本人编辑；头像不得携带私有桶链接或敏感元数据 |
| 学校/学院/专业 | 默认不公开；明确选择公开后才展示 | 本人可见 | 仅事项必要时 | 可选自填，不能用来推断真实认证；最小发布默认仅昵称和头像 |
| 校园模拟标识 | 是，附“教学模拟”说明 | 是 | 是 | 专用流程生成，资料写入不能改变 |
| 有效交易次数、有效评价汇总 | 是 | 是 | 是 | M6 的已完成交易/有效评价事实；新用户无评价不能伪造满分 |
| 公开信誉解释 | 经裁剪后的公开说明 | 本人说明 | 事项所需解释 | M8/M5 后续契约输入；不混入内部风险、举报人或私聊细节 |
| 邮箱/登录标识 | 否 | 本人专用资料可见 | 默认掩码，完整读取须有事项必要性及审计 | 不作为公开联系方式；修改登录标识不走普通资料白名单 |
| 角色、账号状态 | 不公开内部管理字段 | 本人可见必要状态 | 授权管理范围内可见 | 服务端生成；用户不得修改；公开“不存在/不可用”不暴露禁用原因 |
| 会话状态、到期提示 | 否 | 仅本人当前会话的必要提示 | 仅必要脱敏元数据 | 不提供可被用于接管会话的标识；Phase 1 不增加会话管理页面 |
| 密码明文、密码摘要 | 永不 | 永不 | 永不 | 密码仅进入专用凭据请求；服务端只存密码哈希；不得在错误、审计或日志回显 |
| 刷新凭据摘要、签名密钥 | 永不 | 永不 | 永不 | 仅内部验证/运维使用，不能出现在响应或导出中 |
| 访问/刷新令牌原文 | 否 | 仅专用登录/刷新成功通道按 Phase 2 方案签发 | 否 | 不进入用户资料、URL、通知、日志、统计或证据；存储/传输方式在 Phase 2 冻结 |
| 私人空闲时间表 | 否 | 如未来纳入则仅本人；当前不采集 | 默认无权 | M1 排除智能排期；不得因 ER/README 候选提前收集完整日程 |
| 已约定的面交时间地点 | 否 | 对应交易参与者 | 仅关联举报/纠纷所需范围 | 与完整私人日程不同；M6 管理订单和约定版本 |
| 私聊正文、私聊图片 | 否 | 对应会话参与者 | 仅关联事项所需消息范围，并审计 | 不能以“管理员”遍历全量聊天；参与者仍受账号/会话状态约束 |
| 举报正文、举报人身份 | 否 | 举报人可看本人提交及允许公开的处理进度 | 授权事项内可见 | 被举报人不能自动获知举报人身份、内部备注或全部证据 |
| 举报附件/举证材料 | 否 | 举报人本人上传的材料；不自动看到别人补充材料 | 授权事项内最小范围 | 私有桶；访问前检查权限并审计；不通过普通资源接口暴露 |
| 私有对象 key、访问地址 | 否 | 不暴露内部 key；授权后提供短时访问能力 | 同左 | 不生成永久公共 URL；预签名属于持有即可使用的短期能力 |
| 风险分值、规则命中、审核备注 | 否 | 默认不直接返回内部细节 | 仅关联事项、按必要性读取 | 对用户提供经裁剪的处理说明；不把风险信号当成欺诈结论 |
| 审计原始记录、IP/设备信号 | 否 | 默认不返回 | 专门授权且必要时 | 只采集最低必要信息，期限由 Phase 2 评审；禁止记录完整凭据或证据正文 |

## 3. 输出与输入控制

1. 公共、本人、审核响应分别定义白名单；包括嵌套卖家资料、搜索结果、聊天用户卡片、通知 payload、统计和导出。新增字段默认不可公开。
2. 个人资料只接受昵称、头像、简介及选定的可选展示字段；拒绝 role、status、模拟认证、评分、交易次数等保留字段，不能静默接受后忽略部分值。
3. 对象权限在查询和序列化前验证。仅过滤邮箱而允许枚举他人的私聊/订单，仍属于越权。
4. 头像/简介等用户内容要做格式校验和安全输出；错误响应不得回显完整原始请求、SQL、堆栈、对象 key 或令牌。
5. 用虚构账号演示：公开昵称“测试同学甲”；本人邮箱示例 `student-a@example.invalid`。不把队员个人邮箱、手机号或实际聊天放进样例。
6. 私有证据授权撤销后不得再签发链接；已经签发的预签名链接在过期前可能仍有效。Phase 2 由 M5/M9/M10 确定最短可用期限；若要求即时撤销，选择经 API 代理读取或具备撤销能力的方案并实测，不能声称预签名天然即时撤销。

## 4. 文档走查场景

| 场景 | 预期观察 | 接收/验收 |
|---|---|---|
| 游客看用户卡片、商品卖家、搜索结果 | 没有邮箱、令牌、私聊、证据、完整日程和内部风险 | M2/M3、M10 |
| 甲读取自己的资料，再尝试读取乙的私有资料 | 甲可见本人邮箱；乙私有数据被拒绝且无字段回显 | M5、M10 |
| 管理员无事项授权读取聊天或附件 | 拒绝，不能凭角色获取私有对象链接 | M5/M6、M10 |
| 管理员获单个举报授权后扩大查询范围 | 只允许必要消息/证据，越界拒绝；成功读取有审计 | M5/M9、M10 |
| 用户提交资料修改，夹带管理员角色/交易次数 | 拒绝整次非法写入，原角色及派生值不变 | M5、M10 |
| 审查响应、错误和日志 | 不含密码、摘要、完整令牌、内部证据 key；登录/刷新签发通道单独验证 | M5/M9、M10 |

这里只完成文档规则走查；上述 API/浏览器/日志测试待 Phase 2 契约及 Phase 3 实现后执行。交接与未确认项见 [M5 handoff](m5/handoff.md)。
