# BP-P1 后端与平台组交接

## 阶段结论

M5、M6、M9 的个人设计输入已经齐备，可作为 BP-P2 的认证契约、业务 OpenAPI、数据库迁移和统一运行环境输入。Phase 1 只接受候选规则，不冻结实现细节。

## Phase 2 接收动作

- M5 将账号、权限、字段可见性和安全风险转为 `auth-contract.md`、认证 OpenAPI 输入和安全设计。
- M6 将实体、状态、不变量和并发规则转为 canonical OpenAPI、写操作合同和状态枚举。
- M9 将组件、ER 和运行需求转为模型、迁移、种子、Compose、CI 与恢复基线。
- M2/M3/M4 按 OpenAPI 生成 SDK 消费，不手工维护冲突字段。
- M10 将高风险场景转为权限、状态、并发和恢复测试。

## 保留到 Phase 2 的决策

URL、字段类型、索引、状态枚举名称、令牌参数、附件限制和具体端口在 Phase 2 冻结。保留这些参数决策不阻塞 Phase 1 关闭，因为本阶段目标是形成可追踪、可评审且有失败边界的设计候选。
