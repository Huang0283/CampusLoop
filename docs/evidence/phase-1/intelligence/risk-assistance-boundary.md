# AI1-10 风险辅助边界与人工处理方案

## 文档信息

- Owner：M8
- 状态：Phase 1 候选设计，需 M1/M5/M6/M10 评审
- 核心原则：风险线索不等于违规或欺诈判定；自动规则不得处罚用户

## 允许与禁止

风险辅助允许：

- 根据可解释规则生成内部审核线索。
- 聚合与具体业务事实相连的证据引用。
- 为授权管理员提供排序和处理建议。
- 记录人工决定、理由、规则版本和申诉结果。

风险辅助禁止：

- 自动封禁账号、下架商品、取消订单、修改信誉或认定欺诈。
- 使用私聊原文、敏感身份、设备指纹或精确位置进行未授权建模。
- 将未审核举报数量作为公开信誉分。
- 把规则分数或异常分数解释为欺诈概率。
- 因新用户没有历史而自动标记高风险。

## 风险线索目录

| 线索代码 | 可用事实 | 触发候选 | 解释要求 | 自动动作 |
|---|---|---|---|---|
| `PRICE_EXTREME` | 商品分类、价格、已批准参考区间 | 价格明显偏离宽参考区间 | 显示价格、区间、数据版本和限制 | 仅建审核线索 |
| `REPEATED_CANCELLATION` | 用户参与订单及取消事件 | 滚动窗口内重复取消；阈值待冻结 | 列出事件 ID 和时间窗，不推断动机 | 仅建审核线索 |
| `REPEATED_NO_SHOW` | 经双方/管理员确认的爽约事件 | 多次有效爽约记录 | 未确认的单方指控不得计入 | 仅建审核线索 |
| `REPORT_CLUSTER` | 已提交举报及关联对象 | 不同有效账户在时间窗内集中举报 | 去重关联举报，明确尚未定性 | 仅提升人工队列优先级 |
| `DUPLICATE_LISTING` | 商品结构化字段和允许处理的文本特征 | 同账号短期重复发布高度相似商品 | 展示相似字段和版本 | 仅建审核线索 |
| `ACTIVITY_BURST` | 账号操作计数和时间桶 | 发布/报价频率异常 | 不保存设备或精确行为轨迹到解释 | 仅建审核线索 |

所有阈值必须在 Phase 2 配置化、版本化，并在看到最终测试结果前冻结。Phase 1 不提供虚假命中率。

```json
{
  "case_id": "generated-server-side",
  "subject_type": "PRODUCT",
  "subject_id": "opaque-id",
  "signals": [
    {
      "code": "PRICE_EXTREME",
      "rule_version": "risk-rule-v0.1-draft",
      "evidence_refs": ["price-advice-result-id"],
      "explanation": "挂牌价超出宽参考区间，仅建议人工核对"
    }
  ],
  "recommended_action": "MANUAL_REVIEW",
  "decision": null
}
```

不得返回“骗子”“欺诈概率”或自动处罚指令。公开 API 不返回内部线索、阈值或举报证据。

## 人工处理流程

```text
规则生成线索
  -> 去重并进入审核队列
  -> 授权管理员查看最少必要证据
  -> 管理员选择：无操作/请求补充/内容处理/账号处理建议
  -> 高影响动作按后端权限和治理流程执行
  -> 记录决定、理由和证据版本
  -> 通知受影响用户并提供申诉入口
  -> 不同人员复核申诉并记录最终结果
```

风险服务只创建或更新审核案件。真正改变账号、商品或订单状态的动作必须经过 M5/M6 管理的授权接口，校验角色、状态前置、理由和审计要求。

## 申诉与重算

- 用户可查看影响自身的处理结果、理由类别和申诉期限，但不能查看举报人身份或受保护证据。
- 申诉不得由原决定人单独终审；课程规模无法双人复核时，应至少由另一位管理员确认。
- 证据修正、规则版本变化或原决定撤销时重新计算线索状态，但不得删除原审计事件。
- 被证明为误报的线索不得继续影响队列优先级或公开信誉。

## 权限与数据最小化

| 角色 | 权限 |
|---|---|
| 普通用户 | 举报、查看自己的处理通知和提交申诉 |
| 交易参与者 | 提交与自身交易相关的证据 |
| 审核管理员 | 在案件范围内查看最少必要证据并记录决定 |
| 系统管理员 | 管理规则版本和访问权限，不默认读取全部私聊 |
| 智能服务 | 读取批准的结构化事实，生成线索；不能执行处罚 |

日志不得包含令牌、邮箱、完整私聊、精确地点和未经脱敏的举报证据。访问聊天证据必须与具体举报或争议案件绑定并留下审计记录。

## 安全失败与降级

- 风险服务不可用：基础发布、浏览、聊天和交易继续；举报仍进入待处理队列。
- 数据缺失：不猜测风险，不自动扩大处罚范围。
- 规则冲突：案件标记为需要人工核对，不自动选择更严厉结论。
- 重复事件：使用幂等键避免重复案件；不得累计制造虚假高风险。
- 低置信或阈值边界：仅记录解释，不提升为定性标签。

## 测试场景

1. 新用户正常发布低价教材，不因无历史被标高风险。
2. 极端价格只生成审核线索，商品状态保持不变。
3. 同一举报事件重复投递，不产生多个有效案件。
4. 单一账户重复举报，不伪装成多人集中举报。
5. 未确认爽约指控不进入 `REPEATED_NO_SHOW`。
6. 管理员无案件关联时不能读取聊天证据。
7. 申诉撤销决定后，公开信誉不受旧线索影响且审计历史仍在。
8. 风险服务关闭时交易闭环仍可运行。

## Phase 1 决策

- 可解释规则线索 + 人工审核：`go`。
- Isolation Forest 或其他异常检测：MVP `no-go`；仅在有合法数据、固定评估集和人工边界后考虑实验。
- 自动封禁、自动下架、自动取消订单：永久超出智能服务权限，`no-go`。
