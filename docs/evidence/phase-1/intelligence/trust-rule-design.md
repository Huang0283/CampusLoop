# AI1-09 信誉规则设计

## 文档信息

- Owner：M8
- 状态：Phase 1 候选设计，需 M5/M6/M10 确认
- 原则：新用户中性、事实可追溯、公开信息最小化、风险与信誉分离

## 目标与非目标

信誉模块帮助交易双方理解可验证的历史行为，不对用户作身份真实性、商品质量或“绝对可信”的保证。风险线索、举报和管理员判断不得直接混入公开评分。

## 事实来源

| 事实 | 是否进入公开信誉 | 规则 |
|---|---|---|
| `COMPLETED` 订单 | 是 | 双方针对同一版本完成确认，且订单事实有效 |
| 完成订单后的有效评价 | 是 | 仅参与者可评，每单每方最多一条 |
| `CANCELLED` 订单 | 否 | 不计正常完成；取消原因可作为内部运营统计 |
| `DISPUTED` 未决订单 | 否 | 争议解决前不进入正常完成或评分 |
| 管理员裁决后完成 | 条件性 | 只有订单最终事实为完成且评价仍有效时计入 |
| 报价、聊天数量 | 否 | 不能证明可靠交易行为 |
| 举报数量 | 否 | 未审核举报不能作为公开负面信誉 |
| 风险规则命中 | 否 | 只生成内部人工审核线索 |

## 新用户与公开表现

新用户没有足够历史时显示“新用户/暂无足够交易记录”，不显示低分，也不把缺少历史解释为风险。

公开字段候选：

- 昵称和头像。
- 校园认证指示，仅表示教学系统中的模拟认证状态。
- 已完成交易数。
- 有效评价数和经平滑的平均评分。
- 简短、事实型解释，如“完成 6 笔交易，收到 4 条有效评价”。

禁止公开：邮箱、取消明细、举报证据、私聊、风险线索、审核备注、精确活动时间和内部权重。

## 评分平滑

若评价采用 1-5 星，候选平滑公式为：

```text
smoothed_rating = (prior_mean * prior_weight + sum(valid_ratings))
                  / (prior_weight + valid_rating_count)
```

Phase 1 候选参数：`prior_mean = 4.0`，`prior_weight = 5`。参数只是防止少量评价导致极端分数的基线，必须在 Phase 2 版本化并由 M10 复核。

展示规则：

- `valid_rating_count = 0`：显示“暂无评价”，不展示 4.0 作为真实用户评分。
- `1-4` 条：可显示平滑评分，但同时显示样本少提示。
- `5+` 条：显示一位小数、有效评价数和更新时间。
- 不将完成数、取消数或风险线索秘密换算进星级评分。

## 有效评价规则

评价进入聚合前必须满足：

1. 评价者是订单买方或卖方，且评价对象是另一方。
2. 订单最终状态为 `COMPLETED`。
3. 每个订单、评价者、评价对象组合最多一条有效评价。
4. 评价未被管理员按明确规则判为垃圾、重复或违规内容。
5. 删除或无效化必须保留审计事件，不物理改写历史事实。

编辑策略候选：允许在短时间窗内修改一次，修改后聚合只使用最新有效版本；时间窗和权限由 M5/M6 冻结。

## 状态与重算

```text
订单进入 COMPLETED
  -> 创建“可评价”资格
  -> 双方独立评价
  -> 验证评价资格与唯一性
  -> 写入不可变评价事件
  -> 按规则版本重算公开聚合
```

以下事件触发重算：有效评价新增/修改/无效化、订单裁决改变评价资格、规则版本发布。重算必须幂等，同一事实集和规则版本产生相同结果。

## 解释字段候选

```json
{
  "status": "ESTABLISHED",
  "completed_transactions": 6,
  "valid_review_count": 4,
  "smoothed_rating": 4.3,
  "summary": "基于 4 条已完成交易评价",
  "rule_version": "trust-rule-v0.1-draft",
  "updated_at": "2026-09-21T00:00:00Z"
}
```

示例仅说明契约，不代表真实用户。对新用户，`status = NEW`、计数为 0、`smoothed_rating = null`。

## 防滥用与公平性

- 完成交易计数来自订单事实，前端和智能服务不能直接修改。
- 重复评价、同一订单互刷和无效订单评价由唯一约束与资格检查拒绝。
- 不因账号年龄、聊天频率、设备或个人身份特征降低公开信誉。
- 买卖双方使用同一评价资格和聚合规则。
- 用户可以查看与自己相关的计数来源并对错误事实发起申诉。
- 规则变更必须保存版本、迁移说明和前后差异，不能静默重写历史展示。

## 降级

- 聚合服务不可用时显示完成交易数或“信誉暂不可用”，不展示过期缓存为实时结果。
- 数据不足时显示新用户状态，不估算低分。
- 订单/评价事实存在争议时暂停该条进入聚合，不暂停用户正常浏览与发布。

## 验收样例

1. 新用户无订单：显示 `NEW`，评分为空。
2. 单方确认完成：不增加完成数，不开放评价。
3. 取消订单：不计完成，不允许正常评价。
4. 未决争议：不进入正常完成聚合。
5. 同一方重复评价：第二条被唯一约束拒绝。
6. 一条五星评价：平滑后不直接显示满分，并标记样本少。
7. 评价无效化后：幂等重算，保留审计记录。
