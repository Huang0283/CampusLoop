## 2. 标注单元与流程

搜索以 queryId/productId 为一对；匹配以 wantedId/productId 为一对。每条包含语料版本、查询/求购版本、asOf、权限测试身份、逐项硬约束判定、label、reason、annotator、reviewer、adjudicator、labelVersion。

标签：2=高度相关且满足明确需求；1=部分相关；0=不相关或违反任一硬约束；U=信息不足/待裁决。以 2 为主报告正例，≥1 的敏感性分析独立报告。文字相似但超预算、已售、不可见必须为 0。U 不得自动变成负例。

M7 首标，M8 独立复核，分歧由指定裁决者依据输入事实判定并留痕；M10 抽检。标注时不展示算法排序/分数以减少锚定偏差。身份名必须是实际执行人，不能用模板名字冒充签字。

## 3. 小规模试运行的构造方法

先固定一个全部候选都可逐条判断的小语料，分成商品实体组；为以下每类编写至少一个查询/求购，枚举语料内所有候选并双人标注后再运行算法。数量由团队投入确定，本文件不把计划数量写成已有样本。

| 类型 | 正例设计 | 难负例/失败点 |
| --- | --- | --- |
| 精确型号 | 正确品牌型号 | 相似型号、连接符差异、错别字 |
| 中文/英文混合 | 小米 13、TI-84 Plus | 部分数字相同但不同产品 |
| 口语/同义词 | 与需求一致且描述表达不同 | 只共享“宿舍”却用途不同 |
| 预算/成色/地点 | 上下限等值、刚好达到最低要求 | 超上限 1 分、低一个等级、地点不交集 |
| 业务/权限 | 在售、未过期且可见 | 已售、过期、自匹配、隐藏、他校不可见 |
| 缺信息/冷启动 | 字段完整的新商品 | 缺关键规格或未知成色；无历史不自动低分 |
| 无答案 | 语料完全无合格结果 | 不得加入超预算或失效商品填满列表 |

与 [MC 案例](matching-baseline-design.md)、[SR 案例](search-requirements.md)对应，保留违反条件的难负例，不能为了提分删除。

## 4. 划分与防泄漏

只调规则/融合时用开发集和封存测试集；需要训练时才增加训练集。按商品实体、近重复文本及查询模板关系分组，关联样本必须同组，再用固定 seed 划分；保存分组清单、集合 ID 和哈希。seed 可候选取 20260923，比例及最终规模留到 AI2-03 冻结。

同一商品不同版本或标题改写不能跨标签集合。区分“新商品泛化”和“同库存新查询泛化”；公开检索语料可包含待召回商品，但测试标签不得用于调参。封存后若更改规则，须记录新实验并重新安排未见评估，不反复对同一测试集挑最优结果。

U 优先裁决。仍无法裁决时所有方案主对比一致排除该整条查询，报告排除数及理由；不只剔除某个返回商品再补位。

## 5. 指标定义

固定 snapshot、身份、asOf、硬约束、标签与 K；候选 K=5，补充 K=10，AI2 冻结。最终返回商品 ID 去重后取 TopK，R 为整个可评估语料中的标签 2 正例集合。

```text
P@K = |TopK ∩ R| / K                 # 不足 K 的缺位计未命中
R@K = |TopK ∩ R| / |R|              # 仅 |R|>0 的查询
RR@K = 1 / 首个正例排名             # K 内无正例则 0
MRR@K = 有正例查询的 RR@K 宏平均
```

主 P/R/MRR 在同一有正例查询集合上按查询宏平均，搜索和匹配分开报告。没有可评估正例查询时指标记 N/A，不用 0 或 1 冒充结果。没有完整正例集合时不能报全库 Recall；若仅标注候选池，应标“池内 Recall”并附池构造方法。

无答案查询另报空结果正确率=返回空的无答案查询数/无答案查询数，以及误推荐条数。另报有正例但返回空的查询占比。分母为 0 时记 N/A。

硬约束违规率=返回项中违反任一硬约束的去重项数/实际返回项数，同时保存逐约束违规计数；没有返回项时比例 N/A、计数 0。该计数是必须为 0 的正确性要求，不是通过减少候选掩盖召回失败的理由。

## 6. 可独立手算的公式校验

取 K=5；ID 仅用于合成算例：

| 查询 | 完整正例集合 R | 返回顺序 | P@5 | R@5 | RR@5 |
| --- | --- | --- | --- | --- | --- |
| Q1 | a,b,c,d | a,x,b,y,z | 2/5=0.4 | 2/4=0.5 | 1 |
| Q2 | e,f | x,e | 1/5=0.2 | 1/2=0.5 | 1/2 |
| Q3 | 空 | 空 | 不入主平均 | N/A | 不入主平均 |

Q1/Q2 宏平均 P@5=0.3、R@5=0.5、MRR@5=0.75。Q3 单独空结果正确率为 1/1。这些数字只证明公式算例一致，不证明 CampusLoop 搜索效果。Q2 不足五项仍除以 5。

## 7. 实验、运行与报告要求

固定 B0=关键词/规则，B1=纯向量候选，B2=混合候选；相同数据、身份、筛选、标签与指标脚本。超参只用开发集；原始候选模式与实际含降级模式都报告，不能用大量回退掩盖候选失败。

Phase 2 需实现：schema/重复 ID 校验→数据来源与哈希校验→划分检查→统一指标计算器。Phase 3 增加真实基线运行器，Phase 4 增加候选对比。这里是开发要求，不是现有仓库命令。

每次 run 保留 codeCommit、dataHash、splitHash、labelVersion、算法/索引/配置版本、seed、运行环境与命令、起止时间，以及逐查询排序、metrics、失败样例和日志。报告至少覆盖分词/型号错误、语义或文本相关性偏差、硬筛选/数据缺失三类失败。

性能另报 p50/p95、超时率、降级率、资源占用和重复通知数，注明预热、并发、硬件及数据规模。当前无实测数字，不设伪造已达标门槛；AI2-10 由 M7/M8/M9/M10/M1 在开发前冻结数值标准。
