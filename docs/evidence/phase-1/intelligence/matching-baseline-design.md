# AI1-03 供需匹配规则基线

版本：m7-p1-v1.1，2026-09-23。状态：可手算候选；非线上服务。匹配对象为一条求购与业务商品快照。

## 1. 资格先于评分

每对输入先输出 eligible、ineligible 或 needs_info。任一已知硬条件失败即 ineligible；没有已知失败但硬条件信息不足则 needs_info；只有全部通过的 eligible 项能进入排序。未知不能记作通过，也不向用户泄露无权访问商品。

| 硬条件 | 候选规则 | 缺失/边界 |
| --- | --- | --- |
| 求购有效 | status=OPEN，未删除，expiresAt>asOf | 到期等值即失效；MATCHED 是否仍开放待 M6 确认 |
| 商品有效 | status=ON_SALE，未删除 | RESERVED/SOLD/HIDDEN/下架均排除 |
| 权限/校区 | 后端确认接收人可见 | 学校字符串不能替代权限判断 |
| 非本人 | product.ownerId != wanted.ownerId | ID 缺失不能通过 |
| 分类 | 有显式类别要求时 ID 精确匹配 | 默认不自动包含子类；字典未知为 needs_info |
| 预算 | min≤priceFen≤max，已设置的边界生效 | null 不限制；0 是有效值；金额必须为非负整数分 |
| 最低成色 | 商品等级≥求购最低等级 | 有序字典待冻结；禁止按字符串大小或模糊分档比较 |
| 必须地点 | 商品可交易 placeIds 与求购 requiredPlaceIds 有交集 | 学校不能当作具体地点；若是偏好须使用独立字段 |
| 必需规格 | 所有用户已确认的结构化属性满足比较规则 | 没有屏幕尺寸不能凭标题相似断言满足 24 英寸 |

这里 product.ownerId 是商品卖家（源字段 products.seller_id），wanted.ownerId 是求购发布者（源字段 wanted_posts.owner_id）。二者比较的是同一用户标识域中的不同业务角色；本次不改字段名。

没有明确类别、地点、成色或预算边界就不施加该项约束。文本中的愿望不是用户确认的结构化属性。非法求购输入整体拒绝；坏商品隔离并记录诊断，不默默修复金额或猜枚举。

## 2. 合格商品排序

文本因素 s_text 复用 [关键词评分](keyword-baseline-design.md)，权重 0.75。仅当求购 queryText 有有效词项时启用。品牌/型号偏好权重 0.25，仅在求购显式填写已支持偏好时启用；商品缺该软字段得 0，不能因此移除权重抬高分数。

品牌/型号偏好评分：将用户填写的品牌、型号视为最多两项偏好，各项用批准字典归一后精确相等记 1，否则 0；s_pref=命中偏好数/已填写偏好数。业务尚无该结构化字段，因此第一版默认不开放此输入；显式传入未支持偏好应报错，不能静默忽略。必需型号属于硬约束，不能当软偏好绕过。

```text
rankScore = 100 × Σ(w_i × s_i) / Σ(启用的 w_i)
contribution_i = 100 × w_i × s_i / Σ(启用的 w_i)
```

两种因素都没启用时 rankScore=null、scoreType=constraints_only，按发布时间降序、ID 数值升序；否则 scoreType=rule_match_v0，先按未舍入分数降序，再按时间和 ID。文本为 0 不否决已满足全部硬约束的候选，但只能显示低相关规则结果，不能因此自动发“高匹配”通知。通知阈值需单独校准。

## 3. 可核对的解释

每项 reason 含 code、kind（constraint/factor）、field、observed、required、contribution 和 ruleVersion。预算/成色通过的 contribution=null；排序因素有贡献数值。仅传接收人有权查看的观测值。

示例：BUDGET_MATCH：180 元在 100—200 元范围；CONDITION_MATCH：成色达到要求；TEXT_TITLE_HIT：标题包含“计算/算器”。不使用“成交概率”“信誉好”“热门机型”“距离很近”等无输入依据的理由。价格建议来自 M8 独立能力，不进入 M7 分数。

## 4. 合成资格验收表

假设 W 为本人以外、同一授权校区、OPEN、未到期的“计算器”求购：预算 10000—20000 分，最低八成新，分类 calc，地点 library。算例暂用全新>九成新>八成新>七成新的有序表；这不是已批准的成色字典。除差异列外均满足前置。

| ID | 商品差异 | 资格 | 理由 |
| --- | --- | --- | --- |
| MC-01 | 18000 分，八成新 | eligible | 所有硬约束通过 |
| MC-02 | 20000 分，八成新 | eligible | 上限等值通过 |
| MC-03 | 20001 分，九成新 | ineligible | 超预算，与文本分无关 |
| MC-04 | 15000 分，七成新 | ineligible | 成色低于要求 |
| MC-05 | 成色为空 | needs_info | 无法证明达到最低成色 |
| MC-06 | SOLD | ineligible | 状态不允许推荐 |
| MC-07 | 商品属于求购本人 | ineligible | 排除自匹配 |
| MC-08 | 分类 phone 或地点仅 dormitory | ineligible | 显式约束失败 |
| MC-09 | 无权访问 | ineligible | 不返回商品信息 |
| MC-10 | expiresAt=asOf | ineligible | 求购已到期 |

## 5. 分数手算

MC-01 标题仅“计算器”，其余字段无命中。s_text=8/18=4/9。未填写品牌偏好时权重归一，rankScore=100×4/9≈44.4444。若未来已支持偏好且用户指定品牌，品牌命中 s_pref=1，则分数=100×(0.75×4/9+0.25)=58.3333；贡献分别约 33.3333 和 25，合计与总分一致。

文本因素和偏好全部未启用不显示 100 分。超预算候选即使文本和偏好均为 1，也不会进入这个计算。展示四舍五入误差不用于排序。

## 6. 可行性结论

规则方案可继续详细设计；生产接入为 conditional，依赖 M6/M5 的业务和权限契约、成色/地点字典、M10 验收及 M4 通知政策。以上案例是预期结果而非项目已运行测试，正式状态见 [verification.md](verification.md)。
