本清单只补 T2 验收发现的问题和证据缺口，不重跑全部 84 条。复测前先拉取已合入 main 的修复版本，记录完整软件 SHA、API/UI 地址、数据版本和执行日期。不得把本地自动化或开发者联调记成 T2 独立签收。

沿用原用例 ID，在 `execution-log.csv` 保留旧行并新增复测行；`retest-log.csv` 记录旧结果、修复版本和新证据链接：

| 用例 | 需要确认的结果 | 证据要求 |

| C44 | 同一交易重复评价时，提示已经评价且不产生第二条有效评价 | 第一次与第二次请求/界面结果、评价数量 |

## 补上原记录缺口

- C30：对同一待接受报价实际重复发送/重试，确认仍只有一个有效订单；记录请求次数、相同幂等键及订单数量。
- C54、C65：对同一举报重复处理或重发同一请求，确认结果是确定的幂等响应或冲突，且不会多出处理记录或通知；区分按钮重复点击和请求重放。
- C51：分别验证合法附件及超限/不支持附件，记录文件类型、大小、API 结果和是否残留上传对象。不得把只测正常附件写成边界通过。
- C75：补商品治理状态子检查，覆盖预订/已售/删除等可合法形成的状态；无法形成的前置写阻塞/缺口，不改数据库伪造。
- C76：分别核订单搜索、状态筛选、详情弹窗及 CSV 内容/字段；当前截图不能证明的子项补对应证据。
- C79/C80：按 Issue #145 的逐词预期核验搜索。区分 `/search` 和 `/products`，记录实际商品 ID、分页、价格筛选及包含/排除理由；C79 不能把双肩包当电脑整机通过。
- C83：按合法可达前置执行取消回归；无法创建的隐藏/删除前置如实留缺口，不能直接改测试库状态。

## 交付与完成标准

1. 在原 CSV 中追加复测记录，不删除或改写旧失败和旧版本结果；缺陷继续引用实际 Issue。
2. 每条记录包含执行者、完整软件 SHA、数据/角色/对象 ID、步骤、预期、实际、分类结果和证据路径。
3. 更新 `retest-log.csv`、`defects.md`、`daily-report.md`、`delivery-checklist.md` 与 `user-handoff.md`，其余文件只链接原始证据，避免复制日志。
4. PR 描述列出本次复测的用例编号和未解决缺口；不能因为修复已合 main 就把测试写成通过。
