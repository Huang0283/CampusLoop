# 校园全分类搜索与求购匹配复测

功能代码必须一致：日常、T1、T2 都运行同一修复版本。测试账号、数据库和图片各自隔离，不能互换密码；旧版本的测试结论仍对应原 SHA，不算新版本通过。

## 商品覆盖

保留原 60 件基础商品和 10 件搜索对照，另加 `tests/catalog/campus-products.json` 的 400 件商品。十类各 40 件不同名称或型号：图书教材、文具文创、数码电子、生活用品、家具家电、寝具床品、交通代步、运动户外、服饰鞋包、其他。

数码包含 5 部手机、4 台平板、9 台笔记本、4 台台式电脑、3 个鼠标、3 个键盘，以及耳机、相机、显示器、打印机、路由器和存储/充电配件。生活用品含雨伞、钳子；商品地点均为校内。价格和商品均为虚构测试样例，不能据此证明真实行情、成交估价或模型准确率。

图片是各商品独立生成的文字示意图，明确标注“功能测试示意图 · 非商品实拍”，用途是验证上传、卡片、详情和图片加载，不能用于验收真实照片识别。无需额外寻找 400 张实拍图。图片与账号、凭据和 ID 映射保存于忽略的 `.codex-tmp`。

## 导入方法

先按 `scripts/audit_env.py` 建立独立 audit 环境。新批次使用 T1 的 `setup_data.py --admin-search --campus-catalog` 一次导入 470 件，校园商品先于求购发布，避免导入时产生大量重复匹配任务。已有 run2 可通过 `audit_env.py upgrade` 保留原账号和数据并真实升级代码，随后单独增加校园商品。在项目根目录运行以下模板，按实际 namespace/run-id/container/state-dir 替换参数：

```powershell
python scripts/seed_campus_catalog.py --api http://127.0.0.1:18024 --container <T2的API容器名> --namespace business --run-id <批次> --state-dir .codex-tmp/audit/business/<批次>/data-state --font C:/Windows/Fonts/msyh.ttc
```

T1 替换为 `permission`、API `18025`。同一批次可重跑而不重复发布；商品已被交易或下架时脚本会报冲突，保留证据后换测试批次，不能强行复位。脚本会检查实际 Docker 配置，拒绝日常 8001、非 audit 数据库/媒体和非 Redis14/15。Linux 传入已安装的中文字体路径。

## T2 怎么测试

先用干净基线测搜索，再测会改变商品状态的交易和治理流程。每次记录页面/API、完整软件 SHA、数据批次、输入条件、商品 ID、总数和全部分页；不要只截第一页。

| 输入 | 应该看到什么 | 应该排除什么 |
|---|---|---|
| 电脑 | 笔记本、游戏本、MacBook、台式机，跨页全部取出 | 电脑包、相机、充电器、纸质笔记本 |
| 笔记本 | 笔记本电脑和纸质笔记本 | 台式机、电脑包 |
| 笔记本电脑 | 轻薄本、游戏本、MacBook 等笔记本 | 台式机、纸质笔记本、电脑包 |
| 联想笔记本电脑 | 联想品牌的笔记本，支持不加空格 | 其他品牌、联想台式机 |
| 手机 | 5 部新增手机及原数据中的相关手机 | 手机壳、充电器、平板 |
| 手机 128GB | 同时符合手机和容量条件 | 256GB 手机、不相关商品 |
| 手机或平板 | 手机和平板的并集 | 充电器、平板拖把 |
| 键盘 | 新增 3 个键盘及原有相关商品 | 键盘吸尘器 |
| 自行车 | 山地车、公路车、折叠车等整车；按标题也包含电动自行车 | 车锁、头盔、打气筒、车灯、手机支架 |
| 雨伞 | 日用雨伞 | 摄影柔光伞 |
| 可以装电脑 | 简介中说明能装电脑的包 | 不要求必须是电脑整机 |
| 不存在的量子传送商品xyz | 空结果 | 不能为凑结果返回任意商品 |

空格连接的词要求同时符合；“或”“或者”“、”、英文 `or` 表示并集。新商品名称和简介实时参与搜索，不依赖把每个型号手工写进代码。常见别名仍采用有限规则字典，不声称覆盖任意口语、错别字或所有自然语言意图。语义模式不可用时必须明确显示降级，不能把规则结果说成模型结果。

对上面输入继续组合分类、成色、价格上下界、排序；跨第 1/2 页搜索后清空应回到第 1 页并恢复总量。重点记录筛选前后的总数和无重复/遗漏。

## 求购匹配怎么判

用 B 查看自己的求购。必须同时符合名称/简介相关性、预算、最低成色、地点、在售状态、卖家可用和非本人商品。匹配入口与后台匹配通知复用同一个后端函数。

- 高数教材应匹配高等数学/高数书，不能匹配雨伞、衣服或保温杯。
- 收纳箱应匹配收纳箱/整理箱/储物箱，不能匹配保温杯。
- 用同一物品建立价格恰好等于预算下/上界、低一分、高一分、成色不足、地点不符、本人发布、已预订/售出/下架、卖家禁用的对照。
- 没有符合商品时显示空结果；新增、修改、预订、取消、下架和恢复后重新核对匹配及后台通知，不以“接口返回200”代替正确性验收。

T1 负责数据包、预期结果和权限证据，T2 负责页面业务的独立实际执行与缺陷复测。维护者自动检查不代替 T1/T2 签收。旧 Q40/Q42 的“全部70件”只指原基础数据，现在全商城是470件；原编号预期只与基础 manifest 对照，新商品另与校园扩展 manifest 对照。
