## 1. 必修产品漏洞：封禁后，旧报价仍可创建新订单

已通过正常业务 API 分别复现买家、卖家被封禁两种路径：先建立会话与报价，管理员禁用报价参与者，另一正常用户接受旧报价；接口仍返回 200，创建 `PENDING_CONFIRM` 订单并将商品设为 `RESERVED`。

`backend/app/api/routes/transactions.py` 的 `pending_offer` / `available_product` 未复核交易对方的 ACTIVE 状态，`accept_offer` 因而继续创建订单。`backend/app/services/order_governance.py` 只在禁用时保护已存在订单，覆盖不到禁用之后才创建的订单。

最小修复方向：在共享报价交易入口复核双方交易资格，遵守现有用户授权锁与商品/报价/订单锁顺序，覆盖封禁并发边界；拒绝时不能写入订单、商品状态、通知或成功事件。保留已有订单取消/争议保护。加入买家和卖家两方向回归，而不是只修前端按钮。

证据：`test_deep_probes.py`、`deep-probes.log`、`deep-probes.xml`。新增探针 5 条：3 通过、2 失败，两个失败属于同一漏洞；本轮尚未修复。
