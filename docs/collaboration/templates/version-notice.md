# 每轮版本通知模板（由 M10 填写后发到关联 Issue）

以下是模板，不是已发布版本或测试结果。填写完成后删掉本提示；密码、token、真实个人资料不要公开。

## 本轮版本

- 变更 ID：例如 C20261027-01。
- 日期与反馈日期：
- 本轮目的及关联 Issue/PR：
- 代码分支、完整软件 SHA；API/Worker/智能服务如版本不同，分别列出：
- 预览 URL、对应 API；是 main 还是尚未合并的候选：
- 运行/安装说明、必要依赖和环境；本机地址不能给其他电脑直接当共享部署地址：
- 汇总 PR 目标：当前 phase<n>/integration 或已收口后的 main。

## 我今天具体改了什么

每项变更分别列出：

- 修改前行为 → 修改后行为：
- 受影响页面/路由、接口/字段/权限/状态、需求 ID：
- 改动 PR/文件及本次未改内容：
- 现有自测命令/结果、已知风险与限制：
- 对应 T01–T15 测试范围及相邻回归：
- 用户组需要执行的 U01–U08 任务：
- 报告章节、手册、截图和演示草稿的影响：

## 测试怎么开始

- 测试环境/专用数据库、测试媒体卷、Redis DB14/15；确认不使用日常数据库：
- 数据集版本/哈希、生成/复位说明、测试资源 ID：
- 卖家/买家/管理员等账号别名与私下获取方式（不公开凭据）：
- 具体操作步骤、预期成功结果及失败/权限边界：
- 测试负责人、复核人及接收回报日期（自行认领后填写）：

## 各组接收与回报

- 测试组：执行用例、发现故障的 Issue、每日汇报链接、能否交给用户组及阻塞范围。
- 用户组：在核心流程通过后登录并完成角色任务，提交卡点/完成情况、体验 Issue、手册与截图 PR。
- 文书组：列出需更新的章节、证据来源和已核对未变内容。
- 演示组：冻结前只更新草稿及来源；冻结后核对最终脚本、彩排和录像。
- M10：反馈处置结果、修复 SHA、下一轮通知及仍未解决项。

## 本轮结束时填写

- 测试与体验完成/失败/阻塞/未执行情况：
- 修复及原执行人复测证据：
- 材料 PR、Review、软件基线 SHA 和最终材料/集成 SHA：
- 暂缓事项、理由、Owner 和下一次检查日期：
- 是否允许发布/冻结/最终演示及依据：
