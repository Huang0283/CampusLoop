# 用户组真人任务与体验反馈模板

本模板用于真实组员使用虚构测试数据完成任务，不是虚构访谈，也不要求用真实交易数据。先接收测试组已通过的流程，再开始正式体验。

## 任务记录

- 变更 ID、任务 U01–U08、任务目标：
- 实际执行人、日期；是否参与过该页面实现：
- 分支、软件完整 SHA、浏览器、桌面/手机视口：
- 角色（游客/买家/卖家/管理员）、专用账号别名与数据 ID：
- 前置条件、测试组流程通过记录链接：
- 自己实际尝试的操作路径：
- 完成 / 失败 / 阻塞 / 未执行及具体原因：
- 哪里找不到、哪里看不懂、哪个状态误解、哪一步需要别人指导：
- 提示、等待、失败恢复、返回/刷新、移动布局的观察：
- 实测耗时/原话摘要（没记录就写未记录，不补造）：
- 路由、截图索引、证据路径及脱敏情况：
- 关联功能缺陷或体验 Issue：
- 用户/管理员/部署手册需改的具体步骤和文件：

## 体验问题 Issue

标题：`[体验][变更ID][角色任务] 具体卡点`

- 软件 SHA、任务/角色/路由、浏览器/视口：
- 尝试步骤与想完成的目标：
- 实际看到什么、为什么造成困惑、影响/出现频率：
- 截图或操作证据：
- 建议及其希望改善的结果（可以没有设计方案）：
- M10 决定：接受并修复 / 后续处理 / 不采纳；理由、Owner、检查日期：
- 修复 PR/SHA；原执行人重走任务的日期、结果和证据：

## 本轮用户组汇总

- 已完成/失败/阻塞/未执行的任务及计数：
- 发现的功能缺陷、体验问题与优先级：
- 提交给 M10 的问题链接及其处理结论：
- 更新的手册、截图索引和个人/组 PR：
- 未改材料的影响检查；已过期截图/步骤如何标记：
- 修复后原体验人员复测的任务与仍遗留的问题：
- 组内复核人、下一步与预计回报日期：
