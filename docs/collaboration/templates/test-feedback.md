# 测试执行、每日反馈与缺陷模板

这是未执行模板。执行记录存入本人测试目录，再在协作 Issue 给链接；不要把模板里的待填项当作结果。

## 单条用例

- 用例 ID、T01–T15 功能域、需求/Issue、变更 ID：
- 软件完整 SHA、服务/镜像版本、环境、浏览器/视口：
- 数据集版本/哈希、账号角色别名、商品/会话/订单等 ID：
- 前置条件及清理/复位方法：
- 按顺序列明输入/点击/请求动作：
- 每个关键动作的预期结果及依据（契约/需求/状态机）：
- 实际结果、请求/响应/持久化证据（脱敏）：
- 结论：通过 / 失败 / 阻塞 / 未执行 / 不适用（附理由）。
- 执行人、时间与证据路径：
- 缺陷 Issue、严重度、受影响回归范围：

## 每日汇报给 M10

- 日期、执行人、变更 ID、软件 SHA：
- 环境、数据集版本、实际执行用例 ID：
- 计划总数；通过、失败、阻塞、未执行、不适用各多少（互斥且总和一致）：
- 新发现缺陷、最高严重度、Issue 链接与证据：
- 已修复项复测结果、修复 SHA 与记录链接：
- 能交给用户组的流程与仍阻塞的任务：
- 需要 M10 修复/运维/说明的事项：
- 下一步与预计回报日期；当天没测说明原因：

## 新建缺陷 Issue

标题：`[缺陷][变更ID][模块] 一句话描述具体故障`

- 影响和严重度；依据已有项目缺陷等级，说明是否阻断核心交易/启动或涉及越权/数据丢失：
- 分支/软件 SHA、环境、账号角色别名、数据版本与资源 ID：
- 最少复现步骤：
- 预期结果及依据：
- 实际结果、出现次数/尝试次数：
- 截图、时间、脱敏日志/请求及证据路径：
- 是否有安全的临时操作方式：
- 修复人及修复 PR（由 M10 填）：
- 待复测 SHA（由 M10 填）：
- 原执行人复测：日期、SHA、原用例与相邻回归、结果和证据。

故障初报不必等全部字段齐全；先报告严重问题，再补证据。修复 PR 关联 `Refs #缺陷号`；复测通过后再关闭，未运行不能关闭。
