# FE-P2 可点击原型与接口契约

## 阶段信息

- 周次：第 3-4 周；截止：第二次汇报前。
- 成员：M2、M3、M4；组内负责人：M2。
- 集成分支：`phase2/frontend-prototype`。
- 任务分支：`task/m2-p2-shell-prototype`、`task/m3-p2-market-prototype`、`task/m4-p2-transaction-prototype`；PR 目标：`phase2/frontend-prototype`。
- 证据目录：`docs/evidence/phase-2/frontend/`。
- 输入门禁：FE-P1 已关闭；M1 给出需求候选；M5/M6 给出角色、字段和状态；M7/M8 给出智能结果候选。
- 输出去向：FE-P3、BP-P3、AI-P3、MQ-P2 测试基线。

## 阶段完成结果

在低保真结果上形成可点击原型、组件规范和接口映射。原型可以使用明确标识的 Mock，但每个页面字段、动作、状态和错误必须对应已评审契约；本阶段不把 Mock 宣称为真实联调。

## M2 任务：框架、认证与公共体验

- [ ] 冻结学生/管理员/未登录导航、路由、面包屑和移动端布局。
- [ ] 完成登录、注册、退出、资料、模拟校园认证和 403 可点击原型。
- [ ] 定义认证恢复、令牌失效、禁用账号和隐私字段展示交互。
- [ ] 冻结颜色、字号、间距、表单、表格、弹窗和反馈规范。
- [ ] 提供加载、空数据、成功、失败、无权限五类公共状态组件设计。
- [ ] 建立页面 -> 角色 -> 路由 -> Owner -> API -> 状态总表。
- [ ] 与 M5 对签认证/用户契约，与 M10 对签验收入口。

## M3 任务：市场、商品、求购与智能结果

- [ ] 完成市场、搜索、筛选、排序、分页、商品详情和收藏可点击流程。
- [ ] 完成商品发布/编辑/上下架/删除及图片状态原型。
- [ ] 完成求购列表/详情/发布/编辑/关闭流程。
- [ ] 完成匹配结果和价格建议原型，展示原因、区间、声明与降级。
- [ ] 定义表单校验、草稿、离开提醒、重复提交和服务端错误映射。
- [ ] 为每页填写五类状态设计矩阵。
- [ ] 与 M6/M7/M8 对签字段、枚举、错误和降级契约。

## M4 任务：聊天、交易与治理

- [ ] 完成会话列表进入详情、历史消息、商品/求购上下文可点击流程。

- [ ] 完成订单列表/详情/时间线、见面约定与双方确认原型。
- [ ] 完成仅已完成订单可评价以及用户/商品/交易/聊天四类举报入口。

## 契约交付

| 文档 | 必填列 | 接收人 |
|---|---|---|
| 页面/API 映射 | 页面、动作、方法、路径、请求、响应、错误、Owner、状态 | M5/M6/M7/M8 |
| 五类状态矩阵 | 页面、加载、空、成功、失败、无权限、不适用原因 | M10 |
| 角色动作矩阵 | 角色、资源状态、动作、前置、UI 表现、服务端结果 | M5/M6/M10 |
| Mock 清单 | Mock 数据源、对应接口、启用条件、移除阶段 | FE-P3 |

## 协作顺序

1. M5/M6/M7/M8 先提供已评审字段、状态、成功/失败样例和降级含义。
2. M2/M3/M4 按契约制作可点击 Mock；Mock 不要求上游服务运行。
3. 上游负责人检查字段和规则，M10 只验原型旅程、权限表达和异常设计。
4. 真实 API/WebSocket/模型交互统一在 Phase 3 或 Phase 4 验收，本阶段不得因此误判原型未完成。

- [ ] M2/M3/M4 任务 PR 均经另一名前端成员 Review。

- [ ] M10 按核心旅程检查原型无断点；M1 复核没有扩展范围。

- [ ] Issue 收尾记录原型地址、路由、任务 PR、汇总 PR、构建结果和遗留阻塞。

## 本阶段不做

- 不要求所有页面接入真实接口，不把内存状态或静态提示算联调。
- 不自行决定后端字段、状态、权限或智能分数含义。
