# FE-P2 可点击原型与接口契约

## 阶段信息

- 周次：第 2 周；截止：第二次汇报前。
- 成员：M2、M3、M4；组内负责人：M2。
- 证据目录：`docs/evidence/phase-2/frontend/`。

## 小组目标

在低保真结果上形成可点击原型、组件规范和接口映射。原型可以使用明确标识的 Mock，但每个页面字段、动作、状态和错误必须对应已评审契约；本阶段不把 Mock 宣称为真实联调。

## 小组验收标准

### 游客浏览与动作鉴权（FE2-01、FE2-05、FE2-07）

- 未登录用户可以直接打开 `/`、`/market`、`/product/:id`、`/wanted` 和 `/wanted/:id`，完成列表浏览、搜索、筛选、排序、分页、详情查看和返回列表；这些页面不得因为缺少 token 跳转登录。
- 收藏、联系卖家/发布者、举报、发布商品、发布求购和查看个性化匹配属于登录后动作。游客点击这些动作时保存当前路径并进入 `/login`，登录成功后回到来源页面；浏览动作不能触发登录提示。
- `/profile`、`/favorites`、`/my-products`、`/publish`、`/wanted/publish`、`/wanted/matches`、聊天、交易、通知和管理后台仍属于受保护页面；管理员入口还必须通过角色校验。
- 路由映射交付物必须同时记录“页面访问级别”和“页面动作级别”，不能只用一个“学生/公开”字段代替两种权限。

- [ ] 未登录访问受限页进入登录或 403；管理员入口不向普通用户开放。
- [ ] 买家可从市场依次进入详情、收藏/聊天、报价和订单原型。
- [ ] 卖家可完成商品发布/管理并响应报价。
- [ ] 求购发布可进入匹配结果；智能不可用时展示明确降级。
- [ ] 聊天列表能进入详情；未完成/取消订单不能进入正常评价。
- [ ] 四类举报入口位置明确，证据和私密消息不向无权限角色展示。
- [ ] 每个 MVP 页面有五类状态设计或书面“不适用”理由。
- [ ] `npm run lint`、`npm run build` 通过并记录提交号。

## 本阶段小闭环

本周由前端体验组完成“页面、交互、页面到契约的映射和用户可见证据”的最小可验收闭环。只有本节的输入、结果、证据和交接均已记录，才允许把本 Issue 标记为本组完成。

### 输入确认

- 本阶段输入：对应 Phase 1 已关闭 Issue 的交付物、提交号和遗留清单；所有输入必须可从阶段集成提交检出。
- 本组本周工作边界：只处理本文件“个人任务”和“小组共同任务”列出的范围；未列出的新需求不得借本 Issue 关闭。
- 输入不完整时：在证据目录的 `handoff.md` 写明阻塞事项、上游 Owner、下游 Owner、当前可做内容和不能验收内容；不得用猜测字段、临时数据或口头确认代替输入。

### 本周可验收结果

- 最小结果：冻结可消费的设计基线：页面原型/组件、API/数据库/环境契约、数据评估或测试契约；Mock、样例或骨架必须明确标注，不能算真实业务完成。
- 验收动作：由非作者从阶段集成提交检出，按本 Issue 的任务 ID 找到交付文件，执行文档中的命令或场景，并分别记录成功、失败、权限/状态边界。
- 证据要求：保存成功/失败样例、版本号、差异决策、启动命令和契约测试结果，确保下一阶段不需要猜测字段或状态。 证据至少包含提交号、运行环境、命令或操作步骤、实际结果和失败时的日志/截图路径。

### 输出与下一阶段交接

- 输出位置：源码、测试和迁移保留在所属目录；阶段证据统一写入 `docs/evidence/phase-2/frontend/`，至少包含 `deliverables.md`、`verification.md` 和 `handoff.md`。
- 接收人和动作：下一阶段实现负责人同步 phase2/integration 的收口提交，按接收清单逐项验证契约、样例和环境。
- 接收清单必须列出：输出文件/提交号、接收人、接收动作、验收命令或场景、接收结论；任何未完成项都要写明 Owner、依赖人、影响、下一动作和明确截止时间。
