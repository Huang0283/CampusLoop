# FE-P2 可点击原型与接口契约

## 阶段信息

- 周次：第 3-4 周；截止：第二次汇报前。
- 成员：M2、M3、M4；组内负责人：M2。
- 证据目录：`docs/evidence/phase-2/frontend/`。
- 输入门禁：FE-P1 已关闭；M1 给出需求候选；M5/M6 给出角色、字段和状态；M7/M8 给出智能结果候选。
- 输出去向：FE-P3、BP-P3、AI-P3、MQ-P2 测试基线。

## 小组目标

在低保真结果上形成可点击原型、组件规范和接口映射。原型可以使用明确标识的 Mock，但每个页面字段、动作、状态和错误必须对应已评审契约；本阶段不把 Mock 宣称为真实联调。

## 契约交付

### 文档：页面/API 映射

- 必填列：页面、动作、方法、路径、请求、响应、错误、Owner、状态
- 接收人：M5/M6/M7/M8

### 文档：五类状态矩阵

- 必填列：页面、加载、空、成功、失败、无权限、不适用原因
- 接收人：M10

### 文档：角色动作矩阵

- 必填列：角色、资源状态、动作、前置、UI 表现、服务端结果
- 接收人：M5/M6/M10

### 文档：Mock 清单

- 必填列：Mock 数据源、对应接口、启用条件、移除阶段
- 接收人：FE-P3

## 协作顺序

1. M5/M6/M7/M8 先提供已评审字段、状态、成功/失败样例和降级含义。
2. M2/M3/M4 按契约制作可点击 Mock；Mock 不要求上游服务运行。
3. 上游负责人检查字段和规则，M10 只验原型旅程、权限表达和异常设计。
4. 真实 API/WebSocket/模型交互统一在 Phase 3 或 Phase 4 验收，本阶段不得因此误判原型未完成。

## 小组验收标准

- [ ] 未登录访问受限页进入登录或 403；管理员入口不向普通用户开放。
- [ ] 买家可从市场依次进入详情、收藏/聊天、报价和订单原型。
- [ ] 卖家可完成商品发布/管理并响应报价。
- [ ] 求购发布可进入匹配结果；智能不可用时展示明确降级。
- [ ] 聊天列表能进入详情；未完成/取消订单不能进入正常评价。
- [ ] 四类举报入口位置明确，证据和私密消息不向无权限角色展示。
- [ ] 每个 MVP 页面有五类状态设计或书面“不适用”理由。
- [ ] `npm run lint`、`npm run build` 通过并记录提交号。

## 本阶段不做

- 不要求所有页面接入真实接口，不把内存状态或静态提示算联调。
- 不自行决定后端字段、状态、权限或智能分数含义。
