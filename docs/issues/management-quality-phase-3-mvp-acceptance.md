# MQ-P3 MVP 里程碑验收

## 阶段信息

- 周次：第 5-6 周；截止：第三次汇报前。
- 成员：M1、M10；主责：M1；独立验收：M10。
- 集成分支：`phase3/management-quality`。
- 输入门禁：Phase 2 需求/设计基线已合并；统一环境可启动；Phase 3 各组任务有 Owner。
- 输出去向：Phase 4 智能集成、MVP 版本标签、第三次汇报。

## 阶段完成结果

用两个普通账号在统一环境完成真实持久化的基础交易闭环，并形成可复现测试、缺陷和版本证据。页面打开、固定 Mock、手工改数据库或仅截图均不算通过。

## M1 任务

- [ ] 每日检查 MVP 需求追踪，阻塞超过半天立即分派处理。
- [ ] 主持前端/后端接口联调会，记录字段、状态和错误变更。
- [ ] 控制范围：Phase 3 只做 MVP 和可接入基线，不加入 Phase 4 高级功能。
- [ ] 审核所有变更是否关联需求 ID、接口版本、迁移和测试场景。
- [ ] 组织第 5 周主流程检查和第 6 周里程碑验收。
- [ ] 形成第三次汇报脚本、贡献说明、已知限制和现场备用方案。
- [ ] 验收通过后记录版本提交并创建候选标签。

## M10 任务

- [ ] 执行认证、商品、搜索、收藏、聊天、报价、订单、约定、完成、评价、举报和通知测试。
- [ ] 执行双账号 E2E：卖家发布，买家搜索/联系/报价，双方约定并独立确认，完成后评价。
- [ ] 验证未登录、非资源所有者、普通用户/管理员越权场景。
- [ ] 验证重复报价接受、重复完成、重复评价、非法状态跳转和幂等。
- [ ] 验证 WebSocket 断线、消息补拉、重复消息和发送失败。
- [ ] 建立缺陷单，包含级别、环境、步骤、预期/实际、证据、Owner 和回归结果。
- [ ] 复核 CI、迁移、干净数据库种子和构建结果。

## MVP 验收路径

| 场景 | 前置 | 关键检查 | 通过证据 |
|---|---|---|---|
| 账号 | 空测试库 | 注册、登录、刷新/退出、资料、越权 | API/页面记录和测试结果 |
| 商品 | 卖家已登录 | 多图发布、列表、详情、编辑/上下架 | 数据库持久化和页面更新 |
| 交易 | 买卖双方 | 聊天、报价、接受、订单、约定、双方完成 | 状态事件顺序和 E2E 录像/日志 |
| 评价治理 | 订单完成/未完成各一笔 | 完成后评价；未完成禁止；举报可追踪 | 权限/状态测试和后台记录 |
| 降级 | 智能/WebSocket 等不可用 | 关键词、HTTP 补拉或明确不可用提示 | 降级测试记录 |

## 发布门禁

- [ ] P0/P1 缺陷为 0；P2 均有 Owner、影响、计划且不破坏演示主路径。
- [ ] 前端 lint/build、后端静态检查/测试、迁移检查和 E2E 均有最终结果。
- [ ] 测试账号/数据不含真实个人信息，能够重复创建或重置。
- [ ] API 文档、页面映射、状态机和当前代码一致。
- [ ] 第三次汇报从空闲状态按脚本完成，不依赖开发者手工修数据。

## 交接与关闭

- [ ] FE-P3、BP-P3、AI-P3 已关闭并合并。
- [ ] M10 独立执行核心测试并签署通过/有条件通过结论。
- [ ] M1 对照需求追踪确认 MVP 范围完成并登记遗留项。
- [ ] 阶段提交已打标签，Phase 4 从该提交创建分支。
- [ ] Phase 4 明确接收可集成事件、接口、数据版本和未解决缺陷。

## 本阶段不做

- 不为赶进度跳过权限、事务、迁移、异常或独立复测。
- 不把语义模型、价格模型或高级风险功能作为 MVP 关闭前置。
