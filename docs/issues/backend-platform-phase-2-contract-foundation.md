# BP-P2 API、数据库与统一环境基线

## 阶段信息

- 周次：第 3-4 周；截止：第二次汇报前。
- 成员：M5、M6、M9；业务主责：M6；平台主责：M9。
- 集成分支：`phase2/backend-foundation`。
- 任务分支：`task/m5-p2-auth-contracts`、`task/m6-p2-business-contracts`、`task/m9-p2-runtime-foundation`；PR 目标：`phase2/backend-foundation`。
- 证据目录：`docs/evidence/phase-2/backend-platform/`。
- 输入门禁：BP-P1 领域候选完成；需求/页面字段/智能资源需求可用。
- 输出去向：BP-P3、FE-P3、AI-P3、MQ-P2 测试基线。

## 阶段完成结果

建立可启动的 FastAPI/PostgreSQL 基础工程、首版迁移、种子数据、API 契约和 CI。所有 MVP 接口在实现前已明确权限、事务、幂等、错误码和测试场景；接口样例不得与数据库事实或前端字段冲突。

## M5 任务

- [ ] 冻结注册、登录、刷新、退出、当前用户、资料和管理员用户接口。
- [ ] 定义令牌生命周期、密码哈希、账号禁用和会话撤销。
- [ ] 定义字段级可见性与序列化规则，禁止返回密码哈希和敏感令牌。
- [ ] 建立认证/权限错误码与前端行为映射。
- [ ] 编写账号/权限接口样例和服务层测试骨架。
- [ ] 与 M2/M10 对签契约和越权测试场景。

## M6 任务

- [ ] 冻结商品、收藏、求购、会话、消息、报价、订单、约定、评价、举报、通知 API 清单。
- [ ] 为每个写接口写明角色、前置状态、事务边界、幂等方式和失败结果。
- [ ] 冻结商品/求购/报价/订单/约定状态及合法转换表。
- [ ] 定义并发接受报价、双方确认、评价唯一性和状态事件记录策略。
- [ ] 定义分页、筛选、排序和错误响应通用结构。
- [ ] 与 M3/M4/M10 对签契约、样例和测试场景。

## M9 任务

- [ ] 建立后端目录、配置、依赖锁定、健康检查和日志基础。
- [ ] 提交首版数据库模型和迁移，覆盖键、唯一、外键、检查和审计字段。
- [ ] 建立本地种子数据和测试数据，使用虚构账号且可重复执行。
- [ ] 提供 PostgreSQL/pgvector、Redis、MinIO、API 的 Compose 环境。
- [ ] 建立 `.env.example`，验证真实密钥和环境文件被排除。
- [ ] 建立 CI：格式/静态检查、迁移检查、单元/接口测试、前端构建入口。
- [ ] 编写从空环境启动、迁移、重置测试库、健康检查和常见故障步骤。
