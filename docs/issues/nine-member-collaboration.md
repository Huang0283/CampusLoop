# 九人协作、文书测试与最终演示闭环

## 目标

本 Issue 用于组织 M10 技术负责人之外的九名组员，完成课程技术报告、PoC 用户手册、独立测试、页面证据、最终 PPT、15 分钟真人演示和提交材料。每个阶段占一周；阶段内所有材料必须绑定同一个验收 SHA。

## 参与人和主责

- M1 黄麒玮：文书报告统稿、需求追踪、课程文件清单和最终材料汇总。
- M8 梁迦文：系统设计、架构图、智能方法和技术限制章节。
- M5 胡可铭：账号、权限、隐私和安全测试。
- M6 李明远：双账号交易、状态机、并发和业务回归测试。
- M9 叶子聃：干净部署、CI、数据库/对象存储、性能、故障和恢复测试。
- M2 马萱：用户手册、学生主流程和桌面/移动页面操作证据。
- M3 陈红卿：管理员/部署/故障手册、截图索引、页面问题和演示数据方案。
- M4 高峻杰：最终 PPT、课程要求核对、每页证据来源和提交文件清单。
- M7 骆康睿：15 分钟讲稿、双账号演示脚本、两轮彩排、真人出镜 MP4 和备用方案。
- M10 陈梓弘：功能/API/UI/SDK/联调/缺陷修复、可验收 SHA、阶段技术集成和最终技术合并。

## 任务清单

### MQ-COLLAB-01 文书与技术报告

M1 和 M8 必须提交英文报告章节、需求追踪、架构与智能方法说明。报告正文必须满足课程 40 至 60 页要求，不能把目录、References、Appendix A 计入正文。每个实现结论必须引用代码、契约、测试或明确限制。

### MQ-COLLAB-02 独立测试与验收

M5、M6、M9 必须在独立测试环境执行功能、权限、状态、异常、部署、性能和恢复测试。每条用例写明角色、数据、步骤、预期、实际、SHA、时间和证据。技术负责人修复后，原执行人必须复测；没有复测不能关闭缺陷。

### MQ-COLLAB-03 用户手册与页面证据

M2 和 M3 必须完成 8 至 12 页用户手册以及管理员、部署、故障文档。截图、手册和页面问题必须来自当前 SHA，覆盖桌面/移动、游客/学生/管理员、成功/失败/无权限/空状态。页面问题通过 Issue 交给 M10 修复，不能用材料 PR 改生产功能。

### MQ-COLLAB-04 最终演示与提交

M4 和 M7 只能在功能与 UI 冻结后制作最终材料。课程演示为 15 分钟，MP4 必须出现演示者本人；先完成第一轮彩排，修复并复测，再完成第二轮。PPT、讲稿、视频、截图和软件必须绑定同一 SHA。

### MQ-COLLAB-05 每次大改动的同步闭环

M10 修改路由、API、SDK、数据库、状态、权限、UI、错误提示、AI 行为、端口、部署或 CI 时，必须在 PR 中列出受影响材料。测试组更新用例并复测，文书组更新需求/设计/实现/测试章节，手册组更新步骤/截图/故障处理；演示组在冻结前只维护草稿。所有同步 PR 链接回本 Issue。

## 验收标准

- 每个成员有独立分支、独立 PR、任务日志和组内复核记录。
- 软件、测试、报告、手册、PPT 和视频绑定同一 SHA；旧截图和旧数字明确标为过期。
- 课程报告、用户手册、项目演示、至少三次项目更新和 Group Workload Profile 按教师文件完成。
- 失败、阻塞、未实现和 NO_GO 功能如实保留；不以自动化日志代替真人演示或成员签名。
- M10 在阶段集成分支复验，M1 核对范围和提交清单，全部门禁满足后再关闭本 Issue。

## 分支和 PR 规则

- 文书：`docs/p<阶段>-report`。
- 测试：`docs/p<阶段>-testing`。
- 手册：`docs/p<阶段>-manuals`。
- 演示：`docs/p<阶段>-presentation`。
- M10 技术分支：`task/m10-p<阶段>-<主题>`，先进入阶段技术集成分支。
- 所有 PR 必须写任务 ID、文件、基线 SHA、验证命令、实际结果、遗留问题和关联 PR；不得直接改 `main`。

## 周内节奏

第 1 天锁定 SHA；第 2 天补测试/报告/手册草稿；第 3 至 4 天执行测试并修复；第 5 天复测和同步文书；第 6 天交叉 Review；第 7 天阶段验收和交接。演示最终录制放在功能/UI 冻结之后。

## 关闭条件

本 Issue 不因提交一份草稿而关闭。必须有独立测试结果、报告和手册更新、同 SHA 交接、最终演示材料、贡献记录和真实 Review。课程截止日期以 Blackboard 为准；未提供日期时保持待确认。
