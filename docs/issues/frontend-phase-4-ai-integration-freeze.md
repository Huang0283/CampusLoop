# FE-P4 智能结果、后台与冻结

## 阶段信息

- 周次：第 7-8 周；截止：第四次汇报及功能冻结前。
- 成员：M2、M3、M4；组内负责人：M2。
- 集成分支：`phase4/frontend-integration`。
- 任务分支：`task/m2-p4-admin-freeze`、`task/m3-p4-ai-results`、`task/m4-p4-governance-regression`；PR 目标：`phase4/frontend-integration`。
- 证据目录：`docs/evidence/phase-4/frontend/`。
- 输入门禁：FE-P3/MQ-P3 通过；M7/M8 结果契约和 M5/M6 接口提交可测。
- 输出去向：MQ-P4 集成验收、FE-P5 稳定化。

## 阶段完成结果

在不破坏 MVP 的前提下接入智能搜索、供需匹配、价格建议及已纳入范围的信誉/风险展示，补齐最低管理后台和五类状态，并按冻结清单锁定页面范围。

## 接入顺序

1. M7/M8 提供版本化结果、解释、降级样例和真实评估证据。
2. M5/M6 提供带权限的业务 API、任务状态和结果持久化。
3. M3/M2 只调用业务 API 展示，不直接读取模型文件或绕过后端权限。
4. M10 同时验证正常与降级路径；M1 决定是否进入冻结范围。

## M2 任务

- [ ] 完成管理后台用户、商品、举报、风险线索和基础统计入口。
- [ ] 实现管理员权限、人工审核状态、审计结果和普通用户隔离。
- [ ] 统一异步任务的加载、排队、失败、超时、过期和重试反馈。
- [ ] 补齐全局错误边界、404/403、离线提示和可访问性基础。
- [ ] 更新完整路由/API/状态/Owner 表并组织功能冻结 Review。

## M3 任务

- [ ] 接入混合/语义搜索并区分关键词基线与语义结果状态。
- [ ] 接入求购匹配结果、硬约束/匹配原因、版本和通知入口。
- [ ] 接入价格建议区间、影响因素、数据不足和免责声明。
- [ ] 智能服务失败时保留关键词、规则匹配或明确不可用路径。
- [ ] 防止把相似度显示为成交概率，把价格建议显示为保证价格。
- [ ] 完成智能页面五类状态及旧结果/任务处理中状态。

## M4 任务

- [ ] 回归聊天、交易、评价、举报、通知与智能通知联动。
- [ ] 确认匹配/风险通知不泄露私聊、举报证据或内部风险依据。
- [ ] 完善争议/举报后的用户可见状态和管理员处理结果通知。
- [ ] 回归断线、重复通知、任务重试造成的重复消息/操作。
- [ ] 配合 M10 复测双账号主路径，确保新增功能未破坏状态机。

## 可执行验收

- [ ] 至少两个智能功能从真实业务入口触发并展示持久化结果。
- [ ] 每项结果展示依据、版本/时间、限制和降级状态。
- [ ] 智能服务关闭后，关键词搜索和基础交易继续可用。
- [ ] 普通用户不能进入管理后台或查看风险/举报私密证据。
- [ ] 异步任务不会无限加载；失败/超时有可理解下一步。
- [ ] MVP 双账号 E2E、`npm run lint`、`npm run build` 和关键 UI 测试通过。

## 交接与关闭

- [ ] M7/M8 确认解释含义，M5/M6 确认权限/状态，M9 确认环境。
- [ ] M10 验正常/降级/越权，M1 确认冻结范围。
- [ ] 页面冻结清单包含保留、删除、部分完成、已知缺陷和 Phase 5 Owner。
- [ ] 汇总 PR 合并到阶段分支；Phase 5 不新增页面能力。

## 本阶段不做

- 不由前端计算权威匹配、价格、信誉或风险结论。
- 不用静态 JSON 冒充真实集成，不隐藏智能失败或数据不足。
