# AI-P1 数据可行性与规则基线

## 阶段信息

- 周次：第 1 周；截止：第一次汇报前。
- 成员：M7、M8；组内负责人：M7；评估复核：M10。
- 证据目录：`docs/evidence/phase-1/intelligence/`。
- 启动输入：M1 范围候选。M3/M4 展示需求、M5/M6 业务字段和 M9 环境约束可在阶段内分批进入 `phase1/integration`，智能组基于版本化候选开展可行性评估并在联合评审前冻结。
- 输出去向：AI-P2、FE-P2、BP-P2、MQ-P2。

## 小组目标

逐项判断语义搜索、供需匹配、价格建议、信誉和风险辅助是否可做。每项能力必须有数据来源、简单基线、评估口径、解释字段、降级路径和 `go/conditional/no-go` 结论；本阶段不承诺模型效果。

## 本阶段小闭环

本周由智能功能组完成“数据、基线/模型、评估结果、解释和降级证据”的最小可验收闭环。只有本节的输入、结果、证据和交接均已记录，才允许把本 Issue 标记为本组完成。

### 输入确认

- 本阶段输入：M1 已发布的范围候选、产品总文档和本组成员职责；跨组输入可以在本周内补交，但必须记录版本和确认人。
- 本组本周工作边界：只处理本文件“个人任务”和“小组共同任务”列出的范围；未列出的新需求不得借本 Issue 关闭。
- 输入不完整时：在证据目录的 `handoff.md` 写明阻塞事项、上游 Owner、下游 Owner、当前可做内容和不能验收内容；不得用猜测字段、临时数据或口头确认代替输入。

### 本周可验收结果

- 最小结果：形成可评审的候选方案和验收场景；本阶段只证明范围、规则或可行性，不声称真实页面、接口、持久化或模型已经实现。
- 验收动作：由非作者从阶段集成提交检出，按本 Issue 的任务 ID 找到交付文件，执行文档中的命令或场景，并分别记录成功、失败、权限/状态边界。
- 证据要求：将需求/规则/页面旅程/数据可行性与对应任务 ID 关联，并保存一份可由非作者阅读的验收记录。 证据至少包含提交号、运行环境、命令或操作步骤、实际结果和失败时的日志/截图路径。

### 输出与下一阶段交接

- 输出位置：源码、测试和迁移保留在所属目录；阶段证据统一写入 `docs/evidence/phase-1/intelligence/`，至少包含 `deliverables.md`、`verification.md` 和 `handoff.md`。
- 接收人和动作：下一阶段负责人按文件路径读取候选结果，逐项确认采用、修改或删除；未采用项必须写明理由。
- 接收清单必须列出：输出文件/提交号、接收人、接收动作、验收命令或场景、接收结论；任何未完成项都要写明 Owner、依赖人、影响、下一动作和明确截止时间。

### 单周关闭门禁

- [ ] 小组任务 PR 已经由同组成员 Review，并合并到 `phase1/intelligence`；小组汇总 PR 已提交到 `phase1/integration`。
- [ ] M10 已在阶段集成提交上执行本组验收，M1 已确认范围、遗留项和下一阶段接收清单。

## 本阶段不做

- 不训练复杂模型，不把 Isolation Forest 纳入 MVP 承诺。
- 不抓取许可不明数据，不使用真实个人隐私做实验。
- 不生成、猜测或美化任何尚未运行的效果数字。

## Issue 关闭条件

- [ ] 每项能力都有明确业务输入、输出、用户和 Owner。
- [ ] 搜索、匹配、价格均有不依赖复杂模型的可执行基线。
- [ ] 指标口径和评估集构建方法可由 M10 独立复现。
- [ ] 相似度不称为成交概率；价格不称为自动定价；风险不称为欺诈判定。
- [ ] 智能不可用不阻塞发布、浏览、聊天和交易。
- [ ] 所有数据来源有许可状态；未知数据不得填写虚假规模或效果。
- [ ] M7/M8 互审，M9 确认环境可行，M1 确认范围，M10 确认评估可执行。
- [ ] 汇总 PR 合并，AI-P2 对每项结论给出接收或删除决定。
- [ ] Phase 1 阶段收口 PR 合并到 `main` 后，由该 PR 统一关闭本阶段四个 Issue。
