# BP-P3 MVP 业务闭环实现

## 阶段信息

- 周次：第 5-6 周；截止：第三次汇报前。
- 成员：M5、M6、M9；业务主责：M6；平台主责：M9。
- 集成分支：`phase3/backend-mvp`。
- 任务分支：`task/m5-p3-auth-api`、`task/m6-p3-transaction-api`、`task/m9-p3-mvp-runtime`；PR 目标：`phase3/backend-mvp`。
- 证据目录：`docs/evidence/phase-3/backend-platform/`。
- 输入门禁：BP-P2 契约/迁移/环境基线冻结；前端映射和 M10 场景可用。
- 输出去向：FE-P3 联调、MQ-P3 验收、BP-P4 智能与治理扩展。

## 阶段完成结果

实现真实持久化、权限正确、事务完整且可测试的 MVP API/WebSocket。基础交易在智能服务不可用时仍能运行；所有状态改变由服务端验证和记录。

## 提供方优先顺序

1. M5/M6 先提交契约测试可通过的 API/WebSocket 和虚构测试数据。
2. M9 确认迁移、依赖和统一环境可复现，发布可供前端使用的提交号。
3. M2/M3/M4 再开始真实联调；发现契约差异退回对应后端 Owner，不由前端猜测修补。
4. M10 在后端服务证据和前端接入证据都存在后执行 E2E。后端单测不能代替页面验收，页面 Mock 也不能代替接口验收。

## M5 任务

- [ ] 实现注册、登录、刷新、退出、当前用户、资料读取/编辑。
- [ ] 实现密码哈希、令牌轮换/撤销、账号状态和角色权限。
- [ ] 实现字段级序列化，防止邮箱、令牌、私密时间和审核证据泄露。
- [ ] 实现评价汇总、用户公开资料和最低管理员用户能力。
- [ ] 编写认证、权限、字段可见性和管理员审计测试。
- [ ] 配合 M2 完成 401/403/禁用账号联调。

## M6 任务

- [ ] 实现商品、图片元数据、收藏、搜索/筛选和求购基础接口。
- [ ] 实现会话、消息持久化、历史补拉和 WebSocket 鉴权。
- [ ] 实现报价状态机、接受报价创建订单的事务与幂等。
- [ ] 实现订单、状态事件、见面约定版本和双方确认。
- [ ] 实现仅完成订单参与者一次评价、举报、通知/已读。
- [ ] 对所有资源执行对象级权限和合法状态转换校验。
- [ ] 编写并发接受、重复请求、双方确认、重复评价和越权测试。
- [ ] 为 M7 提供关键词/规则服务调用点和匹配触发事件。

## M9 任务

- [ ] 为全部实现提交迁移、索引和约束，审查 N+1 与关键查询。
- [ ] 接入对象存储开发环境，验证上传类型/大小/权限和失败清理。
- [ ] 配置 Redis/WebSocket 所需环境，但保证数据库为消息/订单事实源。
- [ ] 完善 CI、测试数据库隔离、种子和一键启动。
- [ ] 建立结构化日志、请求关联 ID、健康/就绪检查。
- [ ] 验证迁移从空库升级和最近版本回滚。
- [ ] 固定第 6 周演示环境和版本化配置说明。

## 核心不变量

- [ ] 只有商品/订单参与者或授权管理员能访问受限资源。
- [ ] 一个报价最多成功接受一次；接受与订单创建在同一事务。
- [ ] 单方完成不改变订单为完成；双方必须确认同一约定版本。
- [ ] 每个参与方每订单最多评价一次；非完成订单拒绝评价。
- [ ] 订单状态事件不可由客户端伪造或覆盖。
- [ ] 举报证据私有；管理员访问有审核上下文和审计记录。

## 可执行验收

- [ ] API/服务/数据库测试覆盖主路径、权限、非法状态、重复和回滚。
- [ ] 两账号从发布到评价的数据可通过 API 和数据库事件一致验证。
- [ ] 并发请求不创建重复订单、完成或评价。
- [ ] 服务重启后数据仍在；缓存清空不改变订单事实。
- [ ] WebSocket 断开可通过 HTTP 获取缺失消息。
- [ ] OpenAPI、迁移和运行说明与当前提交一致。

## 交接与关闭

- [ ] M5/M6 互审服务逻辑；M9 审查迁移、索引、配置和运行证据。
- [ ] M2/M3/M4 完成真实联调确认；M10 独立执行接口和 E2E。
- [ ] 汇总 PR 合并并进入 MQ-P3 标签；BP-P4 明确接收智能任务和治理遗留。

## 本阶段不做

- 不以管理员权限代替正常权限测试，不手改数据库制造演示状态。
- 不让智能、Redis 或 WebSocket 故障破坏基础交易写入和读取。
