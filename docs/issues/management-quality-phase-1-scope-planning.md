# MQ-P1 范围、计划与质量框架

## 阶段信息

- 周次：第 1 周；截止：第一次汇报前。
- 成员：M1、M10；主责：M1；质量复核：M10。
- 证据目录：`docs/evidence/phase-1/management-quality/`。
- 启动输入：项目总说明和教师要求。M1 先发布范围候选；M2-M9 的职责、依赖和风险候选在阶段内按截止时间补齐，不作为启动前硬门禁。
- 输出去向：四组 Phase 2 Issue、第一次汇报、需求追踪表。

## 小组目标

把项目设想转换成五阶段周期内可执行的候选范围和质量机制。完成时，每个纳入功能必须有需求 ID、优先级、负责人、依赖、验收条件和计划阶段；计划功能不得写成已实现。

## 分支与合并要求

- 项目阶段集成分支：`phase1/integration`，由 M1 从上一阶段已验收的 `main` 创建。
- 小组集成分支：`phase1/management-quality`。
- 分支负责人：M1；组内交叉评审：M10；范围复核：M1；可测试性复核：M10。
- M1 从最新 `phase1/integration` 创建并推送 `phase1/management-quality`，在本 Issue 中记录远程分支链接。
- 远程分支链接：https://github.com/Huang0283/CampusLoop/tree/phase1/management-quality
- M1 个人任务分支：`task/m1-p1-scope`。
- M10 个人任务分支：`task/m10-p1-quality`。
- 所有个人任务分支均从 `phase1/management-quality` 创建，通过 Pull Request 合并回 `phase1/management-quality`。
- 禁止直接向 `main` 或小组集成分支提交；共享分支禁止 force-push 和变基改写历史。
- 任务 PR 必须写明任务编号、交付物路径、验证命令、验证结果、遗留问题和评审人。
- 个人任务完成并交叉评审后，由 M1 从 `phase1/management-quality` 向 `phase1/integration` 提交小组汇总 Pull Request。

## 本阶段小闭环

本周由管理质量组完成“范围、追踪、阶段验收、缺陷和交接证据”的最小可验收闭环。只有本节的输入、结果、证据和交接均已记录，才允许把本 Issue 标记为本组完成。

### 输入确认

- 本阶段输入：M1 已发布的范围候选、产品总文档和本组成员职责；跨组输入可以在本周内补交，但必须记录版本和确认人。
- 本组本周工作边界：只处理本文件“个人任务”和“小组共同任务”列出的范围；未列出的新需求不得借本 Issue 关闭。
- 输入不完整时：在证据目录的 `handoff.md` 写明阻塞事项、上游 Owner、下游 Owner、当前可做内容和不能验收内容；不得用猜测字段、临时数据或口头确认代替输入。

### 本周可验收结果

- 最小结果：形成可评审的候选方案和验收场景；本阶段只证明范围、规则或可行性，不声称真实页面、接口、持久化或模型已经实现。
- 验收动作：由非作者从阶段集成提交检出，按本 Issue 的任务 ID 找到交付文件，执行文档中的命令或场景，并分别记录成功、失败、权限/状态边界。
- 证据要求：将需求/规则/页面旅程/数据可行性与对应任务 ID 关联，并保存一份可由非作者阅读的验收记录。 证据至少包含提交号、运行环境、命令或操作步骤、实际结果和失败时的日志/截图路径。

### 输出与下一阶段交接

- 输出位置：源码、测试和迁移保留在所属目录；阶段证据统一写入 `docs/evidence/phase-1/management-quality/`，至少包含 `deliverables.md`、`verification.md` 和 `handoff.md`。
- 接收人和动作：下一阶段负责人按文件路径读取候选结果，逐项确认采用、修改或删除；未采用项必须写明理由。
- 接收清单必须列出：输出文件/提交号、接收人、接收动作、验收命令或场景、接收结论；任何未完成项都要写明 Owner、依赖人、影响、下一动作和明确截止时间。

### 单周关闭门禁

- [ ] 本周截止前，所有个人任务均有对应交付物和成员验收结果；未完成项已登记为阻塞或经 M1 正式移出范围。
- [ ] 小组任务 PR 已经由同组成员 Review，并合并到 `phase1/management-quality`；小组汇总 PR 已提交到 `phase1/integration`。
- [ ] M10 已在阶段集成提交上执行本组验收，M1 已确认范围、遗留项和下一阶段接收清单。
- [ ] 本阶段收口前，证据、提交号和交接记录不依赖未合并分支；未达到门禁不得关闭 Issue。
