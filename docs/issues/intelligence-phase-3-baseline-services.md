# AI-P3 可接入基线服务

## 阶段信息

- 周次：第 3 周；截止：第三次汇报前。
- 成员：M7、M8；组内负责人：M7。
- 证据目录：`docs/evidence/phase-3/intelligence/`。
- 输入门禁：AI-P2 数据/评估/服务契约冻结；后端事件与运行环境可调用。
- 输出去向：FE/BP-P3 基线联调、AI-P4 模型公平对比。

## 小组目标

交付可真实调用的关键词搜索、规则供需匹配、规则价格区间及信誉/风险规则库。每项服务有版本、测试、解释和降级结果，为 Phase 4 模型改进提供固定比较基线。

## M7：搜索与供需匹配负责人

- 个人任务分支：`task/m7-p3-search-matching-baseline`。

### 个人任务

- [ ] **AI3-01**：实现关键词索引/查询，支持字段权重、结构化筛选、排序和分页。
- [ ] **AI3-02**：实现求购硬约束过滤和软因素规则排序，输出逐项原因。
- [ ] **AI3-03**：实现任务幂等、结果版本和通知去重，与 M6 的事件接口联调。
- [ ] **AI3-04**：在固定评估集运行关键词/规则基线并保存逐查询结果。

### 个人交付物

- [ ] **AI3-01**：worker/service 代码/测试、docs/evidence/phase-3/intelligence/keyword-baseline.md。
- [ ] **AI3-02**：匹配代码/测试、matching-baseline.md。
- [ ] **AI3-03**：任务代码/测试、matching-task-integration.md。
- [ ] **AI3-04**：原始结果、search-baseline-report.md。

### M7 验收标准

- [ ] **AI3-01**：固定查询得到确定结果，空/坏查询按契约返回。
- [ ] **AI3-02**：违反硬约束候选为零，原因与得分组成一致。
- [ ] **AI3-03**：重复事件不生成重复有效结果或通知。
- [ ] **AI3-04**：指标可由统一脚本重算，至少记录三个失败类别。

## 工程要求

- [ ] 服务入口使用版本化 schema；输入校验失败返回结构化错误。
- [ ] 数据/规则/参数版本与代码提交一起进入结果元数据。

- [ ] 运行日志不包含敏感文本或个人身份信息。

- [ ] README 给出安装、运行、评估、接口样例和已知限制。

## 小组验收标准

- [ ] 关键词搜索能被前端/后端实际调用，并返回契约字段。
- [ ] 匹配先排除违反硬约束候选，再输出可解释排序。
- [ ] 价格输出区间而非保证价格，缺数据时明确不可用/宽区间。
- [ ] 风险线索不会自动修改账号、订单或商品状态。

- [ ] M10 可用同一命令复现基线指标和至少三个失败样例。

## 本阶段小闭环

本周由智能功能组完成“数据、基线/模型、评估结果、解释和降级证据”的最小可验收闭环。只有本节的输入、结果、证据和交接均已记录，才允许把本 Issue 标记为本组完成。

### 输入确认

- 本阶段输入：对应 Phase 2 收口提交中的冻结契约、迁移/环境、原型映射、测试数据和验收场景。
- 本组本周工作边界：只处理本文件“个人任务”和“小组共同任务”列出的范围；未列出的新需求不得借本 Issue 关闭。
- 输入不完整时：在证据目录的 `handoff.md` 写明阻塞事项、上游 Owner、下游 Owner、当前可做内容和不能验收内容；不得用猜测字段、临时数据或口头确认代替输入。

### 本周可验收结果

- 最小结果：完成本组负责的真实 MVP 片段，并能在统一环境中按场景验证；Mock、内存状态、固定响应或手工改库不计入完成。
- 验收动作：由非作者从阶段集成提交检出，按本 Issue 的任务 ID 找到交付文件，执行文档中的命令或场景，并分别记录成功、失败、权限/状态边界。
- 证据要求：记录实际提交号、启动命令、请求/页面/数据库或模型结果证据，以及成功、失败、权限和恢复路径。 证据至少包含提交号、运行环境、命令或操作步骤、实际结果和失败时的日志/截图路径。

### 输出与下一阶段交接

- 输出位置：源码、测试和迁移保留在所属目录；阶段证据统一写入 `docs/evidence/phase-3/intelligence/`，至少包含 `deliverables.md`、`verification.md` 和 `handoff.md`。
- 接收人和动作：下一阶段只接收已通过本周门禁的真实结果；未联调项必须保留阻塞记录并由 M1 决定顺延或移出范围。
- 接收清单必须列出：输出文件/提交号、接收人、接收动作、验收命令或场景、接收结论；任何未完成项都要写明 Owner、依赖人、影响、下一动作和明确截止时间。
