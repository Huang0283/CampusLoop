# AI-P4 模型集成与真实评估

## 阶段信息

- 周次：第 7-8 周；截止：第四次汇报及功能冻结前。
- 成员：M7、M8；组内负责人：M7；独立指标复核：M10。
- 证据目录：`docs/evidence/phase-4/intelligence/`。
- 输入门禁：AI-P3 基线固定；BP-P3 业务事件可用；评估集冻结。
- 输出去向：FE/BP-P4 集成、MQ-P4 冻结、AI-P5 最终复现。

## 小组目标

在数据条件允许时交付语义搜索/匹配和价格建议候选模型，并与 Phase 3 基线公平比较。只有真实优于基线且可解释、可降级的能力进入冻结版本；不达标时保留基线并如实报告。

## 分支与合并要求

- 项目阶段集成分支：`phase4/integration`，由 M1 从上一阶段已验收的 `main` 创建。
- 小组集成分支：`phase4/intelligence-models`。
- 分支负责人：M7；组内交叉评审：M8；范围复核：M1；可测试性复核：M10。
- M7 从最新 `phase4/integration` 创建并推送 `phase4/intelligence-models`，在本 Issue 中记录远程分支链接。
- 远程分支链接：https://github.com/Huang0283/CampusLoop/tree/phase4/intelligence-models
- M7 个人任务分支：`task/m7-p4-semantic-matching`。
- M8 个人任务分支：`task/m8-p4-price-evaluation`。
- 所有个人任务分支均从 `phase4/intelligence-models` 创建，通过 Pull Request 合并回 `phase4/intelligence-models`。
- 禁止直接向 `main` 或小组集成分支提交；共享分支禁止 force-push 和变基改写历史。
- 任务 PR 必须写明任务编号、交付物路径、验证命令、验证结果、遗留问题和评审人。
- 个人任务完成并交叉评审后，由 M7 从 `phase4/intelligence-models` 向 `phase4/integration` 提交小组汇总 Pull Request。
- 四组汇总完成并通过 M10/M1 阶段验收后，仅由 M1 从 `phase4/integration` 向 `main` 提交阶段收口 Pull Request。

## 提供方顺序

1. M7/M8 先在冻结评估集运行候选，提交逐样本结果、指标、失败类别和版本。
2. M10 独立复现关键指标，确认无测试泄漏和口径变化。
3. 通过评估的服务版本交给 M6/M9 部署、触发和落库。
4. M3/M2 展示后再做端到端/降级验收。未通过步骤 1-2 的模型不得进入页面正式路径。

## 证据要求

- [ ] 数据清单、划分哈希、代码提交、依赖、参数、种子和运行环境。
- [ ] 基线与候选逐样本输出及统一计算脚本。
- [ ] 指标表、失败类别、限制、适用范围和 go/no-go 结论。
- [ ] 服务契约、解释样例、延迟记录、降级/回滚步骤。
- [ ] 禁止只提交截图或手工整理的指标数字。

## 小组验收标准

- [ ] M10 从仓库命令复现主要指标，允许误差范围事先写明。
- [ ] 候选没有使用测试标签调参，没有重复样本跨集合泄漏。
- [ ] 进入正式集成的能力满足 AI-P2 已签字的数值门槛；未达门槛只能标记为实验演示，不能替换 Phase 3 基线。
- [ ] 每个结果包含版本、解释和限制；服务失败可回到基线。
- [ ] 智能结果不直接修改商品价格、订单状态或账号状态。

## 本阶段不做

- 不为追求“AI”标签上线劣于基线、不可解释或不可降级的模型。
- 不将实验性风险模型包装成已验证的欺诈检测能力。
