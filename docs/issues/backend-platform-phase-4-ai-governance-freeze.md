# BP-P4 智能任务、治理与冻结

## 阶段信息

- 周次：第 4 周；截止：第四次汇报及功能冻结前。
- 成员：M5、M6、M9；业务主责：M6；平台主责：M9。
- 证据目录：`docs/evidence/phase-4/backend-platform/`。
- 输入门禁：BP-P3 MVP 通过；M7/M8 服务契约、版本和降级可用。
- 输出去向：FE/AI-P4 集成、MQ-P4 冻结、BP-P5 加固。

## 小组目标

实现智能任务触发、版本化结果落库、权限、降级和最低治理后台接口；补齐日志、审计和业务异常，不让智能服务成为交易硬依赖。

---

## 分支与合并要求

- 项目阶段集成分支：`phase4/integration`，由 M1 从上一阶段已验收的 `main` 创建。
- 小组集成分支：`phase4/backend-integration`。
- 分支负责人：M5；组内交叉评审：M6、M9；范围复核：M1；可测试性复核：M10。
- M5 从最新 `phase4/integration` 创建并推送 `phase4/backend-integration`，在本 Issue 中记录远程分支链接。
- 远程分支链接：https://github.com/Huang0283/CampusLoop/tree/phase4/backend-integration
- M5 个人任务分支：`task/m5-p4-governance-api`。
- M6 个人任务分支：`task/m6-p4-ai-orchestration`。
- M9 个人任务分支：`task/m9-p4-worker-runtime`。
- 所有个人任务分支均从 `phase4/backend-integration` 创建，通过 Pull Request 合并回 `phase4/backend-integration`。
- 禁止直接向 `main` 或小组集成分支提交；共享分支禁止 force-push 和变基改写历史。
- 任务 PR 必须写明任务编号、交付物路径、验证命令、验证结果、遗留问题和评审人。
- 个人任务完成并交叉评审后，由 M5 从 `phase4/backend-integration` 向 `phase4/integration` 提交小组汇总 Pull Request。
- 四组汇总完成并通过 M10/M1 阶段验收后，仅由 M1 从 `phase4/integration` 向 `main` 提交阶段收口 Pull Request。

## 提供与消费顺序

1. M7/M8 发布服务版本、请求/响应样例和失败语义。
2. M6 建立业务触发、幂等任务、结果落库和通知；M5 建立可见性/人工权限。
3. M9 部署 Worker/队列/向量依赖并提供健康证据。
4. M3/M2 接入后，M10 执行正常、超时、重复、旧版本和越权测试。

## 小组验收标准

- [ ] 同一事件重复投递不会生成重复有效结果或通知。
- [ ] 过期/旧版本结果不会覆盖更新业务数据对应的新结果。
- [ ] 智能超时不会回滚商品发布、求购发布或交易操作。
- [ ] 风险结果只创建人工线索，管理员操作可审计。
- [ ] 普通用户无法读取内部风险依据、举报证据或后台任务详情。
- [ ] 关闭 Worker/模型服务后基础 API 和 MVP E2E 仍通过。

## 本阶段小闭环

本周由后端与平台组完成“领域规则、接口/持久化、运行环境和服务端证据”的最小可验收闭环。只有本节的输入、结果、证据和交接均已记录，才允许把本 Issue 标记为本组完成。

### 输入确认

- 本阶段输入：Phase 3 MVP 收口提交、真实业务事件/数据、智能结果契约和未关闭缺陷清单。
- 本组本周工作边界：只处理本文件“个人任务”和“小组共同任务”列出的范围；未列出的新需求不得借本 Issue 关闭。
- 输入不完整时：在证据目录的 `handoff.md` 写明阻塞事项、上游 Owner、下游 Owner、当前可做内容和不能验收内容；不得用猜测字段、临时数据或口头确认代替输入。

### 本周可验收结果

- 最小结果：完成已批准的智能集成、治理补齐或前端展示，并同时保留基线、解释、权限和不可用降级；本周末功能冻结。
- 验收动作：由非作者从阶段集成提交检出，按本 Issue 的任务 ID 找到交付文件，执行文档中的命令或场景，并分别记录成功、失败、权限/状态边界。
- 证据要求：固定数据/代码/参数版本，保存逐样本和汇总指标、集成路径、降级路径、人工边界和冻结提交号。 证据至少包含提交号、运行环境、命令或操作步骤、实际结果和失败时的日志/截图路径。

### 输出与下一阶段交接

- 输出位置：源码、测试和迁移保留在所属目录；阶段证据统一写入 `docs/evidence/phase-4/backend-platform/`，至少包含 `deliverables.md`、`verification.md` 和 `handoff.md`。
- 接收人和动作：Phase 5 只接收冻结清单中的修复、优化、复验和打包任务；任何新功能必须先走范围变更。
- 接收清单必须列出：输出文件/提交号、接收人、接收动作、验收命令或场景、接收结论；任何未完成项都要写明 Owner、依赖人、影响、下一动作和明确截止时间。

### 单周关闭门禁

- [ ] 本周截止前，所有个人任务均有对应交付物和成员验收结果；未完成项已登记为阻塞或经 M1 正式移出范围。
- [ ] 小组任务 PR 已经由同组成员 Review，并合并到 `phase4/backend-integration`；小组汇总 PR 已提交到 `phase4/integration`。
- [ ] M10 已在阶段集成提交上执行本组验收，M1 已确认范围、遗留项和下一阶段接收清单。
- [ ] 本阶段收口前，证据、提交号和交接记录不依赖未合并分支；未达到门禁不得关闭 Issue。
