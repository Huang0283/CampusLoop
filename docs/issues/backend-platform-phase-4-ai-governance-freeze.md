# BP-P4 智能任务、治理与冻结

## 阶段信息

- 周次：第 7-8 周；截止：第四次汇报及功能冻结前。
- 成员：M5、M6、M9；业务主责：M6；平台主责：M9。
- 集成分支：`phase4/backend-integration`。
- 输入门禁：BP-P3 MVP 通过；M7/M8 服务契约、版本和降级可用。
- 输出去向：FE/AI-P4 集成、MQ-P4 冻结、BP-P5 加固。

## 阶段完成结果

实现智能任务触发、版本化结果落库、权限、降级和最低治理后台接口；补齐日志、审计和业务异常，不让智能服务成为交易硬依赖。

## 提供与消费顺序

1. M7/M8 发布服务版本、请求/响应样例和失败语义。
2. M6 建立业务触发、幂等任务、结果落库和通知；M5 建立可见性/人工权限。
3. M9 部署 Worker/队列/向量依赖并提供健康证据。
4. M3/M2 接入后，M10 执行正常、超时、重复、旧版本和越权测试。

## M5 任务

- [ ] 实现信誉结果读取、公开/本人/管理员字段边界。
- [ ] 实现管理员用户/举报/风险线索查看与人工处理接口。
- [ ] 记录管理员访问证据、修改状态和人工覆盖的审计事件。
- [ ] 确保模型/规则结果不直接禁用账号或删除内容。
- [ ] 编写隐私、越权、审计和人工处理测试。

## M6 任务

- [ ] 实现新商品/求购/变更触发搜索索引和匹配任务。
- [ ] 实现任务幂等键、状态、重试上限、结果版本和去重通知。
- [ ] 实现搜索、匹配、价格建议的业务 API 和持久化结果。
- [ ] 验证结果所依赖商品/求购仍有效，拒绝展示过期事实。
- [ ] 实现智能超时/失败时关键词、规则或不可用降级。
- [ ] 补齐举报、争议、通知和最低管理员业务接口。
- [ ] 编写重复触发、乱序结果、旧版本、超时和降级测试。

## M9 任务

- [ ] 部署 Worker、队列、pgvector/索引及模型服务所需资源。
- [ ] 建立任务/服务健康检查、超时、重试、死信或失败记录。
- [ ] 增加结果表/索引迁移并验证回滚和数据兼容。
- [ ] 建立监控指标：队列长度、失败率、耗时、版本和资源使用。
- [ ] 验证模型服务关闭/恢复及任务重放不会破坏业务事实。
- [ ] 固定功能冻结环境、依赖、配置和迁移版本。

## 可执行验收

- [ ] 同一事件重复投递不会生成重复有效结果或通知。
- [ ] 过期/旧版本结果不会覆盖更新业务数据对应的新结果。
- [ ] 智能超时不会回滚商品发布、求购发布或交易操作。
- [ ] 风险结果只创建人工线索，管理员操作可审计。
- [ ] 普通用户无法读取内部风险依据、举报证据或后台任务详情。
- [ ] 关闭 Worker/模型服务后基础 API 和 MVP E2E 仍通过。

## 交接与关闭

- [ ] M7/M8 确认版本/结果语义；M2/M3 确认业务 API 可消费。
- [ ] M10 执行任务、权限、降级和 MVP 回归；M1 确认冻结范围。
- [ ] M9 记录冻结环境和迁移；汇总 PR 合并。
- [ ] BP-P5 接收性能、安全、恢复和未关闭缺陷，不接收新功能。

## 本阶段不做

- 不让队列或缓存成为订单事实源，不允许模型直接处罚用户。
- 不因智能集成修改已冻结交易状态机而不走变更评审。
