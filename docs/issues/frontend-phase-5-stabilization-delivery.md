# FE-P5 前端稳定化与交付

## 阶段信息

- 周次：第 9-10 周；截止：第五次汇报和最终提交前。
- 成员：M2、M3、M4；组内负责人：M2。
- 集成分支：`phase5/frontend-release`。
- 任务分支：`task/m2-p5-frontend-release`、`task/m3-p5-market-fixes`、`task/m4-p5-transaction-fixes`；PR 目标：`phase5/frontend-release`。
- 证据目录：`docs/evidence/phase-5/frontend/`。
- 输入门禁：FE-P4 页面冻结；发布候选 API/智能版本和缺陷清单固定。
- 输出去向：MQ-P5 最终回归、用户手册和演示。

## 阶段完成结果

冻结页面不再新增功能，集中修复缺陷、完善可访问性/兼容性/性能、同步文档并提供可重复构建。每个页面的实际状态和限制与最终后端一致。

## 修复顺序

1. M10 提交可复现缺陷，M1 按 P0/P1/P2 和演示影响排序。
2. 页面 Owner 修复并附自测；涉及接口的缺陷由对应 M5/M6/M7/M8 先确认根因。
3. 另一名前端成员 Review，随后 M10 回归；作者不能自行关闭最终缺陷。
4. M2 只在最终 API 提交固定后更新构建与文档。

## M2 任务

- [ ] 修复认证、权限、布局、导航、公共状态和管理后台缺陷。
- [ ] 检查路由刷新、深链接、404/403、令牌失效和退出清理。
- [ ] 检查键盘操作、焦点、标签、对比度和关键可访问性。
- [ ] 审查打包体积、明显重复请求、错误边界和控制台错误。
- [ ] 固定生产环境变量说明、构建命令和部署路径。
- [ ] 汇总最终页面/路由/API/状态矩阵和前端用户手册章节。

## M3 任务

- [ ] 修复市场、商品、上传、搜索、求购和智能结果缺陷。
- [ ] 回归筛选/分页保留、表单输入保留、重复提交和上传失败恢复。
- [ ] 核对智能解释、区间、声明、版本和降级与最终契约一致。
- [ ] 检查空列表、大文本、长文件名、慢请求和移动宽度。
- [ ] 编写市场/求购/智能功能用户操作与已知限制。

## M4 任务

- [ ] 修复聊天、报价、订单、约定、评价、举报、通知缺陷。
- [ ] 回归断线重连、补拉、去重、重复点击和多标签页基本行为。
- [ ] 核对所有角色/状态按钮和禁止评价规则。
- [ ] 检查私聊、举报证据、通知和管理员信息不泄露。
- [ ] 编写双账号交易演示步骤、失败恢复和已知限制。

## 可执行验收

- [ ] 干净安装后 `npm run lint`、测试和 `npm run build` 通过。
- [ ] 浏览器控制台无主流程未处理错误，失败状态不出现永久白屏。
- [ ] 两账号交易、智能正常/降级、管理员治理三个流程通过。
- [ ] Chrome/Edge 当前版本及约定移动宽度完成冒烟。
- [ ] 所有前端 P0/P1 和纳入发布的 P2 经 M10 回归关闭。
- [ ] 用户手册中的路径、按钮名称、截图和实际版本一致。

## 交接与关闭

- [ ] M2/M3/M4 交叉 Review，受影响接口 Owner 确认契约未被前端规避。
- [ ] M10 在最终构建执行回归；M1 检查冻结范围未被扩大。
- [ ] 记录最终构建提交、构建产物生成方法、页面矩阵、缺陷和限制。
- [ ] 汇总 PR 合并，MQ-P5 使用同一提交验收。

## 本阶段不做

- 不新增路由、智能能力或视觉重做；不升级无关依赖。
- 不用隐藏按钮或吞掉错误来掩盖后端缺陷。
