# FE-P5 前端稳定化与交付

## 阶段信息

- 周次：第 9-10 周；截止：第五次汇报和最终提交前。
- 成员：M2、M3、M4；组内负责人：M2。
- 证据目录：`docs/evidence/phase-5/frontend/`。
- 输入门禁：FE-P4 页面冻结；发布候选 API/智能版本和缺陷清单固定。
- 输出去向：MQ-P5 最终回归、用户手册和演示。

## 小组目标

冻结页面不再新增功能，集中修复缺陷、完善可访问性/兼容性/性能、同步文档并提供可重复构建。每个页面的实际状态和限制与最终后端一致。

---

## 分支与合并要求

- 项目阶段集成分支：`phase5/integration`，由 M1 从上一阶段已验收的 `main` 创建。
- 小组集成分支：`phase5/frontend-release`。
- 分支负责人：M2；组内交叉评审：M3、M4；范围复核：M1；可测试性复核：M10。
- M2 从最新 `phase5/integration` 创建并推送 `phase5/frontend-release`，在本 Issue 中记录远程分支链接。
- 远程分支链接：https://github.com/Huang0283/CampusLoop/tree/phase5/frontend-release
- M2 个人任务分支：`task/m2-p5-frontend-release`。
- M3 个人任务分支：`task/m3-p5-market-fixes`。
- M4 个人任务分支：`task/m4-p5-transaction-fixes`。
- 所有个人任务分支均从 `phase5/frontend-release` 创建，通过 Pull Request 合并回 `phase5/frontend-release`。
- 禁止直接向 `main` 或小组集成分支提交；共享分支禁止 force-push 和变基改写历史。
- 任务 PR 必须写明任务编号、交付物路径、验证命令、验证结果、遗留问题和评审人。
- 个人任务完成并交叉评审后，由 M2 从 `phase5/frontend-release` 向 `phase5/integration` 提交小组汇总 Pull Request。
- 四组汇总完成并通过 M10/M1 阶段验收后，仅由 M1 从 `phase5/integration` 向 `main` 提交阶段收口 Pull Request。

## 修复顺序

1. M10 提交可复现缺陷，M1 按 P0/P1/P2 和演示影响排序。
2. 页面 Owner 修复并附自测；涉及接口的缺陷由对应 M5/M6/M7/M8 先确认根因。
3. 另一名前端成员 Review，随后 M10 回归；作者不能自行关闭最终缺陷。
4. M2 只在最终 API 提交固定后更新构建与文档。

## 小组验收标准

- [ ] 干净安装后 `npm run lint`、测试和 `npm run build` 通过。
- [ ] 浏览器控制台无主流程未处理错误，失败状态不出现永久白屏。
- [ ] 两账号交易、智能正常/降级、管理员治理三个流程通过。
- [ ] Chrome/Edge 当前版本及约定移动宽度完成冒烟。
- [ ] 所有前端 P0/P1 和纳入发布的 P2 经 M10 回归关闭。
- [ ] 用户手册中的路径、按钮名称、截图和实际版本一致。

## 本阶段不做

- 不新增路由、智能能力或视觉重做；不升级无关依赖。
- 不用隐藏按钮或吞掉错误来掩盖后端缺陷。
