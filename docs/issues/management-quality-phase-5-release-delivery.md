# MQ-P5 发布、答辩与最终提交

## 阶段信息

- 周次：第 9-10 周；截止：第五次汇报和课程提交截止时间。
- 成员：M1、M10；主责：M1；发布质量负责人：M10。
- 集成分支：`phase5/release-candidate`。
- 任务分支：`task/m1-p5-release`、`task/m10-p5-final-verification`；PR 目标：`phase5/release-candidate`。
- 证据目录：`docs/evidence/phase-5/management-quality/`。
- 输入门禁：Phase 4 冻结标签、冻结清单、未关闭缺陷和四组最终交付清单齐全。
- 输出：最终标签、课程提交包、第五次汇报、演示视频和贡献记录。

## 阶段完成结果

从冻结版本形成可在新电脑复现的最终系统。需求、代码、测试、部署、用户文档和演示结论一致；所有未完成能力明确标记，不用口头说明、截图或计划文字冒充完成。

## M1 任务

- [ ] 锁定发布范围，仅批准 P0/P1 修复、必要 P2 修复、文档和交付变更。
- [ ] 每日维护发布看板：缺陷、Owner、验证人、目标版本和状态。
- [ ] 审核需求追踪最终状态：完成/部分完成/未完成及证据。
- [ ] 整合架构、接口、数据库、智能、测试、部署、安全和用户文档。
- [ ] 整理成员贡献：Issue、提交、PR、Review、测试和文档证据。
- [ ] 组织最终演示脚本、无网络/服务故障备用方案和答辩分工。
- [ ] 审核提交包结构、许可证/数据许可、隐私和密钥排除。
- [ ] 在全部门禁通过后创建最终版本标签和发布记录。

## M10 任务

- [ ] 在干净环境执行安装、迁移、启动、健康检查和测试数据导入。
- [ ] 执行最终功能、接口、权限、状态机、WebSocket、AI 降级和 E2E 回归。
- [ ] 执行约定的并发、性能、恢复和安全检查，记录真实环境与结果。
- [ ] 验证 P0/P1 为 0，逐项复验已关闭 P2；检查遗留缺陷披露。
- [ ] 检查用户手册、管理员手册、部署文档和故障恢复步骤可执行。
- [ ] 进行至少两次十分钟演示彩排，记录时长、失败点和修复结果。
- [ ] 检查最终文档中的数字、状态、路径和版本与实际一致。
- [ ] 签署发布检查表；不通过时明确阻止最终标签。

## 最终验收场景

1. 非作者获取仓库，按文档配置虚构环境变量并启动全部必要服务。
2. 从空库执行迁移和种子，使用两个账号完成基础交易闭环。
3. 演示至少两个已通过评估的智能能力及其解释。
4. 关闭智能服务，验证关键词/规则降级和基础交易仍可运行。
5. 执行管理员举报/风险人工处理并验证审计记录。
6. 执行备份/恢复或约定恢复演练，验证关键业务记录一致。

## 发布门禁

- [ ] 所有必需 CI 检查通过，最终提交与测试提交一致。
- [ ] P0/P1 为 0；遗留缺陷和未完成功能均已披露。
- [ ] 仓库和提交包不含密钥、真实个人数据、缓存或构建垃圾。
- [ ] 十分钟演示可完成，备用演示不依赖伪造业务结果。
- [ ] M10 签署质量结论；M1 签署范围和提交完整性。

## 关闭要求

- [ ] FE/BP/AI-P5 均关闭且证据已进入仓库。
- [ ] 最终 PR 合并到 `main`，创建不可变最终标签。
- [ ] GitHub Issue 收尾列出最终提交、标签、文档、测试、视频、遗留和贡献。
- [ ] 提交包在另一目录/电脑完成一次最终复现。

## 本阶段不做

- 不新增功能、替换核心技术或重新设计界面。
- 不为了通过演示删除安全校验、异常处理或失败测试。
