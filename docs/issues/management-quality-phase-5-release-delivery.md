# MQ-P5 发布、答辩与最终提交

## 阶段信息

- 周次：第 9-10 周；截止：第五次汇报和课程提交截止时间。
- 成员：M1、M10；主责：M1；发布质量负责人：M10。
- 证据目录：`docs/evidence/phase-5/management-quality/`。
- 输入门禁：Phase 4 冻结标签、冻结清单、未关闭缺陷和四组最终交付清单齐全。
- 输出去向：最终标签、课程提交包、第五次汇报、演示视频和贡献记录。

## 小组目标

从冻结版本形成可在新电脑复现的最终系统。需求、代码、测试、部署、用户文档和演示结论一致；所有未完成能力明确标记，不用口头说明、截图或计划文字冒充完成。

---

## 分支与合并要求

- 项目阶段集成分支：`phase5/integration`，由 M1 从上一阶段已验收的 `main` 创建。
- 小组集成分支：`phase5/release-candidate`。
- 分支负责人：M1；组内交叉评审：M10；范围复核：M1；可测试性复核：M10。
- M1 从最新 `phase5/integration` 创建并推送 `phase5/release-candidate`，在本 Issue 中记录远程分支链接。
- 远程分支链接：https://github.com/Huang0283/CampusLoop/tree/phase5/release-candidate
- M1 个人任务分支：`task/m1-p5-release`。
- M10 个人任务分支：`task/m10-p5-final-verification`。
- 所有个人任务分支均从 `phase5/release-candidate` 创建，通过 Pull Request 合并回 `phase5/release-candidate`。
- 禁止直接向 `main` 或小组集成分支提交；共享分支禁止 force-push 和变基改写历史。
- 任务 PR 必须写明任务编号、交付物路径、验证命令、验证结果、遗留问题和评审人。
- 个人任务完成并交叉评审后，由 M1 从 `phase5/release-candidate` 向 `phase5/integration` 提交小组汇总 Pull Request。
- 四组汇总完成并通过 M10/M1 阶段验收后，由 M1 从 `phase5/integration` 向 `main` 提交唯一的阶段收口 Pull Request。

## 最终交付包

- [ ] 源代码、锁文件、迁移、配置模板和许可证说明。

- [ ] 五次汇报材料、最终演示脚本/视频和成员贡献说明。
- [ ] 完成/部分/未完成矩阵及所有已知限制。

## 最终验收场景

1. 非作者获取仓库，按文档配置虚构环境变量并启动全部必要服务。
2. 从空库执行迁移和种子，使用两个账号完成基础交易闭环。
3. 演示至少两个已通过评估的智能能力及其解释。
4. 关闭智能服务，验证关键词/规则降级和基础交易仍可运行。
5. 执行管理员举报/风险人工处理并验证审计记录。
6. 执行备份/恢复或约定恢复演练，验证关键业务记录一致。

## 发布门禁

- [ ] 所有必需 CI 检查通过，最终提交与测试提交一致。
- [ ] P0/P1 为 0；遗留缺陷和未完成功能均已披露。
- [ ] 仓库和提交包不含密钥、真实个人数据、缓存或构建垃圾。
- [ ] 十分钟演示可完成，备用演示不依赖伪造业务结果。
- [ ] M10 签署质量结论；M1 签署范围和提交完整性。

## 本阶段不做

- 不新增功能、替换核心技术或重新设计界面。
- 不为了通过演示删除安全校验、异常处理或失败测试。
