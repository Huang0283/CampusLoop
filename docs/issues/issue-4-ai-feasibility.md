## 阶段信息

- 阶段：第 1-2 周
- 小组：智能功能组
- 成员：M7、M8
- 组内负责人：M7
- 截止时间：第一次汇报前
- 依赖：M1 提供功能范围；M3/M4 提供展示需求；M5/M6 提供业务字段；M9 提供数据与运行环境约束

## 小组目标

确认语义搜索、供需匹配、价格建议、信誉与风险辅助功能是否具备可用数据和可执行方案。

每项智能功能都必须有简单基线、评估方法、结果解释和服务不可用时的降级方案。本阶段不训练复杂模型，也不预设任何效果指标。

## 分支与合并要求

- 小组集成分支：`phase1/ai-feasibility`。
- 分支负责人：M7；交叉评审：M8；评估复核：M10；范围复核：M1。
- M7 从最新 `main` 创建并推送小组集成分支，并把远程分支链接填写到本 Issue。
- 个人任务分支命名为 `task/<成员编号>-<简短任务>`，例如 `task/m7-search-matching-baseline`、`task/m8-price-risk-baseline`。
- 任务分支从 `phase1/ai-feasibility` 创建，完成后通过 Pull Request 合并回小组集成分支。
- 禁止直接向 `main` 或小组集成分支提交；共享小组分支禁止 force-push 和变基改写历史。
- 数据来源、许可、样本、指标、权重和效果描述必须在 PR 中给出证据或标为未知；涉及展示、事件或环境时邀请对应负责人评审。
- 小组交付通过交叉评审后，由 M7 从 `phase1/ai-feasibility` 向 `main` 提交汇总 Pull Request。

## M7：语义搜索与供需匹配负责人

### 个人任务

- [ ] 明确语义搜索解决的具体问题和目标用户。
- [ ] 定义搜索输入，包括关键词、自然语言描述和结构化筛选条件。
- [ ] 定义搜索输出，包括商品字段、排序分数、匹配原因和降级状态。
- [ ] 设计关键词搜索基线，至少支持标题、描述、类别和品牌字段。
- [ ] 设计关键词检索与结构化筛选的最低可用方案。
- [ ] 调研文本向量模型作为候选改进方案，不在本阶段承诺具体模型。
- [ ] 定义混合检索候选流程，包括关键词、语义相似度和结构化过滤。
- [ ] 明确相似度只表示内容相关程度，不能解释为成交概率。
- [ ] 定义求购与商品匹配的业务输入和输出。
- [ ] 定义类别、预算、成色、地点、有效期和商品状态等硬约束。
- [ ] 定义标题、描述、品牌型号和使用目的等软匹配因素。
- [ ] 设计供需匹配的规则基线。
- [ ] 起草综合评分候选公式，但不在数据不足时宣称权重已经合理。
- [ ] 定义同一商品与求购重复匹配、重复通知和结果版本处理方式。
- [ ] 定义新商品、新求购和信息修改时的匹配触发条件。
- [ ] 设计搜索与匹配标注样本结构。
- [ ] 定义正例、普通负例、难负例、重复项和争议样本。
- [ ] 制定标注人员、复核方式和冲突处理规则。
- [ ] 提出 Precision@K、Recall@K 和 MRR 等候选评估指标。
- [ ] 说明每个指标的含义、计算输入和适用范围。
- [ ] 设计关键词基线与语义方案的公平对比方法。
- [ ] 定义服务超时、模型不可用和向量索引未就绪时的降级行为。
- [ ] 与 M3 确认搜索、匹配和解释字段。
- [ ] 与 M6 确认事件触发、权限和结果落库边界。
- [ ] 与 M9 确认 pgvector、索引和后台任务环境需求。
- [ ] 从最新 `main` 创建并推送 `phase1/ai-feasibility`，在本 Issue 中记录远程分支链接。
- [ ] 建立搜索与匹配任务分支，并在 PR 中记录数据来源、基线方法、评估计划、解释字段和降级路径。

### 个人交付物

- [ ] 供需匹配需求说明
- [ ] 搜索输入与输出字段表

- [ ] 规则匹配基线方案

### M7 验收标准

- [ ] 搜索和匹配都明确业务输入、输出、使用者和评估方式。
- [ ] 语义模型之外存在可以实现的关键词或规则基线。
- [ ] 供需匹配先执行硬约束，再计算软匹配。
- [ ] 评估集构建方法、指标口径和复核人员已经明确。
- [ ] 匹配分数不会被描述为成交概率。
- [ ] 智能服务失败时能够回退到关键词或规则方案。
- [ ] 搜索、发布和交易不会因为智能服务不可用而被阻塞。

## M8：价格建议、信誉与风险辅助负责人

### 个人任务

- [ ] 明确价格建议的业务场景、使用者和输出形式。
- [ ] 定义价格建议所需字段，包括类别、品牌、型号、成色、使用时间和原价。
- [ ] 区分挂牌价、实际成交价和人工录入参考价。
- [ ] 盘点价格数据来源，并记录来源、许可、样本量、时间范围和可用状态。
- [ ] 检查数据缺失、异常价格、类别不平衡和时间失效问题。
- [ ] 设计基于类别、成色、使用时间和原价的规则基线。
- [ ] 设计建议价格区间，不只输出单一价格。
- [ ] 定义影响因素解释，例如使用年限、成色和品牌保值情况。
- [ ] 明确价格建议仅供参考，最终定价由卖家决定。
- [ ] 仅在数据量和质量满足要求时，将回归模型列为候选改进。
- [ ] 提出 MAE、MAPE 和预测区间覆盖率等候选指标。
- [ ] 说明 MAPE 在低价格样本上的风险和适用限制。
- [ ] 明确信誉指标使用的完成交易、评价、取消、爽约和举报信息。
- [ ] 设计新用户的中性起点，避免将缺少历史记录解释为低信誉。
- [ ] 设计信誉平滑规则，避免少量评价造成极端分数。
- [ ] 定义公开信誉信息和仅管理员可见信息。
- [ ] 明确未完成、取消或争议交易不能按正常完成交易计入信誉。
- [ ] 明确风险功能只提供人工审核线索。
- [ ] 列出异常价格、频繁取消、重复举报和异常账号活动等候选线索。
- [ ] 定义风险线索的依据、状态、解释和人工处理入口。
- [ ] 明确风险分数不能自动封禁用户或认定欺诈。
- [ ] 设计申诉、人工修改和重新计算的候选流程。
- [ ] 与 M5 确认信誉口径和字段可见性。
- [ ] 与 M6 确认交易、取消、评价和举报数据。
- [ ] 与 M9 确认数据处理和结果保存环境。
- [ ] 与 M10 确认价格、信誉和风险的评估方法。
- [ ] 建立价格、信誉与风险任务分支，并在 PR 中记录数据许可、规则基线、评估限制、人工兜底和未知项。

### 个人交付物

- [ ] 价格建议需求说明
- [ ] 价格字段与数据来源清单
- [ ] 数据许可和可用状态记录
- [ ] 数据质量初查报告
- [ ] 价格规则基线方案
- [ ] 建议区间与影响因素说明
- [ ] 价格评估指标方案
- [ ] 信誉规则与新用户处理方案
- [ ] 风险线索与人工审核边界
- [ ] 申诉和重新计算流程初稿
- [ ] 与 M5/M6/M9/M10 的待确认问题表

### M8 验收标准

- [ ] 每个数据来源都标明许可、字段、样本量和可用状态。
- [ ] 数据不足时能够使用规则区间，不强行训练回归模型。
- [ ] 挂牌价与真实成交价没有混为一谈。
- [ ] 价格结果包含建议区间、主要依据和限制说明。
- [ ] 新用户不会因为缺少交易记录而直接得到低信誉。
- [ ] 风险结果只作为人工审核线索。
- [ ] 系统不会依据模型结果自动定价、封禁用户或认定欺诈。

## 本阶段不做

- 不训练或承诺复杂模型，不把 Isolation Forest 纳入 MVP。
- 不抓取许可不明的数据，不使用个人敏感信息进行实验。
- 不把相似度解释为成交概率，不把挂牌价直接视为真实成交价。
- 不允许智能服务成为商品发布、浏览、聊天或交易的硬依赖。
- 不为汇报美观而生成虚假的模型指标、样本规模或对比结果。
