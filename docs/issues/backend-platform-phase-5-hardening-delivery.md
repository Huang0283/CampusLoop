# BP-P5 安全、恢复与部署交付

## 阶段信息

- 周次：第 9-10 周；截止：第五次汇报和最终提交前。
- 成员：M5、M6、M9；业务主责：M6；发布平台主责：M9。
- 集成分支：`phase5/backend-release`。
- 输入门禁：BP-P4 功能冻结；数据库/智能/前端最终契约和缺陷列表固定。
- 输出去向：MQ-P5 干净部署、最终测试和提交包。

## 阶段完成结果

发布候选后端在干净环境可部署、迁移、监控、备份和恢复；核心权限、事务、并发和降级通过最终测试。只处理冻结范围和发布质量，不新增业务能力。

## 修复与发布顺序

1. M10/M1 确认缺陷优先级；模块 Owner 复现并定位前端、业务、数据或智能层。
2. M5/M6 修复业务并提交测试；M9 审查迁移、配置和部署影响。
3. 前端/智能消费者回归受影响契约；M10 最终关闭缺陷。
4. M9 从固定提交构建发布环境，任何临时手工操作必须进入文档或自动化。

## M5 任务

- [ ] 完成认证、权限、隐私、限流/滥用保护和管理员审计复查。
- [ ] 回归令牌撤销、禁用账号、对象级权限和敏感字段序列化。
- [ ] 检查日志/错误不泄露密码、令牌、邮箱和隐私证据。
- [ ] 修复用户/管理员模块发布缺陷并补回归测试。
- [ ] 编写账号安全、权限和管理员操作最终说明。

## M6 任务

- [ ] 完成交易状态机、事务、幂等、并发和失败回滚复查。
- [ ] 回归 WebSocket 鉴权、消息补拉、报价接受、双方确认和评价唯一性。
- [ ] 检查智能任务失败/重复/乱序不改变业务事实。
- [ ] 修复市场/交易/治理发布缺陷并补回归测试。
- [ ] 同步 OpenAPI、错误码、状态机和运维故障处理说明。

## M9 任务

- [ ] 固定依赖、镜像/Compose、配置模板、端口、卷和健康检查。
- [ ] 从空库运行全部迁移，验证升级路径和约定回滚策略。
- [ ] 执行备份/恢复演练，核对用户、商品、订单、消息和结果完整性。
- [ ] 执行约定的性能/并发检查，记录环境、数据量、命令和结果。
- [ ] 检查日志轮转、磁盘/对象存储、服务重启和启动顺序。
- [ ] 编写部署、升级、备份、恢复、监控和故障排查文档。
- [ ] 扫描提交包的密钥、环境文件、数据库转储和隐私数据。

## 可执行验收

- [ ] 非作者在干净环境按文档启动所有服务并通过健康检查。
- [ ] 从空库迁移并完成 MVP/智能降级 E2E，无手工改库步骤。
- [ ] 备份恢复后关键数量、外键、订单状态事件和消息一致。
- [ ] 认证/对象权限/管理员审计/举报证据访问测试通过。
- [ ] 并发关键操作保持不变量，无重复有效订单、完成或评价。
- [ ] 所有后端 P0/P1 和纳入发布的 P2 经 M10 回归关闭。
- [ ] OpenAPI、迁移头、配置和最终代码提交一致。

## 本阶段不做

- 不新增表和接口来实现冻结外功能；必要修复必须有迁移与回归。
- 不把开发数据库、真实密钥或手工环境状态带入提交包。
