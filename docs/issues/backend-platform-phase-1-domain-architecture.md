# BP-P1 领域边界与平台方案

## 阶段信息

- 周次：第 1-2 周；截止：第一次汇报前。
- 成员：M5、M6、M9；业务主责：M6；平台主责：M9。
- 证据目录：`docs/evidence/phase-1/backend-platform/`。
- 输入门禁：M1 范围候选、前端用户旅程、智能组数据/任务需求均已提供。
- 输出去向：BP-P2、FE-P2、AI-P2、MQ-P2。

## 小组目标

明确账号、市场、交易和运行平台边界，形成可供详细设计消费的实体、权限、状态机、事务、架构和环境候选。所有内容是设计结论，不得声称接口、数据库或容器已经实现。

## 本阶段不做

- 不冻结 URL、表字段和索引，不实现正式接口或容器。
- 不允许智能模型直接修改订单事实、定价、封禁或审核结论。
- 不提交真实密钥、个人隐私或来源不明数据。

## Issue 关闭条件

- [ ] 每个前端 MVP 行为可映射到后端模块、实体和权限 Owner。
- [ ] 每个关键状态转换有角色、前置条件、成功结果和失败结果。
- [ ] 并发接受、重复确认、重复评价、越权修改和证据泄露有控制方案。
- [ ] AI、Redis、对象存储或 WebSocket 不可用时，基础交易的降级边界明确。
- [ ] 数据库、缓存、对象存储、Worker 的责任没有混淆。
- [ ] M5/M6 互审业务；M9 复核数据/环境；M1 复核范围；M10 确认可测试。
- [ ] 汇总 PR 合并，BP-P2 明确接收所有设计项或记录删除理由。
